# Junction 2026

Preparation repository for **Junction 2026** in Helsinki/Espoo.

This repository is the team's durable workspace for pre-hackathon research, partner intelligence, technical resources, strategy, mock challenges, and idea development.

## Team context

We are a four-person team. Three team members are full-stack developers. Preparation should therefore focus on the areas that create the most leverage before the event: challenge selection, partner intelligence, AI/data architecture, unfamiliar APIs and infrastructure, hardware opportunities, judging strategy, product framing, and pitching.

## Preparation goals

- Understand every Junction challenge and technology partner well enough to use their tools intelligently.
- Identify likely challenge themes without treating speculation as fact.
- Prepare reusable knowledge, accounts, SDK familiarity, integration notes, and generic technical examples.
- Build a disciplined challenge-selection process for the opening hours of the hackathon.
- Practice turning an unseen problem into a working demo and clear pitch quickly.
- Maintain a concise operational reference that the team can consult during Junction.

## Repository structure

- `partners/` — partner-specific intelligence reports and challenge hypotheses.
- `research/` — broader research relevant to likely Junction themes.
- `resources/` — useful APIs, SDKs, datasets, models, infrastructure, hardware, and setup notes.
- `strategy/` — challenge selection, judging, pitching, and 48-hour execution strategy.
- `ideas/` — early concepts and reusable project seeds. These are not pre-built submissions.

## Working principle

Preparation should answer one of three questions:

1. **What should we build?**
2. **How can we build it faster or better?**
3. **How do we make judges immediately understand why it matters?**

Avoid accumulating generic company research or technology notes that do not materially improve one of those decisions.

## Hackathon integrity

The actual Junction submission should be built during the event in accordance with Junction rules. Pre-event work in this repository should remain focused on research, learning, generic integrations, reusable tooling, strategy, and preparation. Any pre-existing code or resources used during the event should be disclosed where required.

## Current preparation sequence

1. Build a concise intelligence report for every current Junction 2026 partner.
2. Produce a cross-partner capability and likely-theme matrix.
3. Rank technologies worth learning before the event.
4. Create an accounts / API / tooling readiness checklist.
5. Run mock Junction-style challenges.
6. Finalize the challenge-selection and 48-hour execution runbook before the event.

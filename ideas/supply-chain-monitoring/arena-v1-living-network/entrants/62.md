# Entrant 62: The Network Story (lens: "Living" over time)

## 0. Bold bet
The whole product is one append-only event log, and the graph, trust levels and risks are just projections of it, so a timeline scrubber replays the network growing, trust rising and risk appearing and clearing, with no separate "history" feature to build. Judges see the "living" claim proven on screen in the first 30 seconds and again when the live web event lands, instead of read about in a slide.

## 1. Summary and name
- Name: **Ledgerline** (a supply network as a ledger of events, drawn as a line through time).
- Product: companies declare and confirm relationships; agents add inferred nodes, monitor the web and raise risks; a hotel buyer sees its own map and warnings, scrubs back to see what was known when, and approves a procurement switch placed on the Valio mock.
- Prize stack: Valio (aim 1st, €4k), Context.dev (live event latency is the demo's proof), Gemini (headline and severity per event), Aiven (Postgres event log, Valkey fan-out, Runtime hosting), CRACI (CI with SBOM), Codex (projector and replay tests). Cala only as a stretch.

## 2. Architecture and DB choice
- **Postgres (Aiven)** as the system of record: one `event` table, plus projection tables rebuilt by a projector. ArcadeDB is rejected for 48h: the story is time-ordered events, which Postgres handles with a sequence column and jsonb.
- **Valkey (Aiven)** for pub/sub: every appended event is published to `story.live`; the UI consumes it over SSE. The durable log stays in Postgres, so a reconnect replays from the last `seq`.
- **Scoring and agents**: TypeScript services. Agents append events; they never write projections directly.
- **Context.dev** monitors and news search deliver through a webhook endpoint. Receipt time is stamped, so the feed can show webhook-to-card latency.
- Hosting on Aiven Runtime (assumption: available); laptop plus tunnel as fallback.
- Synthetic history: a seed script generates about 18 months of events (Jan 2025 to today) for Valio's synthetic network plus dummy companies, so the scrubber has a real past.

## 3. Data model and key queries
Event log (append-only, hash-chained for auditability):
- `event(seq bigserial, id uuid, type text, subject text[], payload jsonb, occurred_at timestamptz, recorded_at timestamptz, visibility text, source_urls text[], run_id, prev_hash, hash)`.
- Types: `node.added`, `edge.declared`, `edge.inferred`, `edge.trust_changed`, `signal.recorded`, `risk.raised`, `risk.cleared`, `proposal.created`, `approval.granted`, `order.placed`, `run.started`, `run.finished`.
- `occurred_at` = when the fact was true in the world; `recorded_at` = when we learned it. The scrubber uses `recorded_at`, so it answers "what did we know then".
- `visibility` is set at write time: `public`, `owner:<company>`, `risk-of:<company>` (buyer sees risk warnings about nodes in its upstream chain), `agg:<industry>` (aggregates only), `optin` (alternatives). Each buyer's viewable set is computed from its own edges and enforced in RLS.

Projections: `node`, `edge(trust, confidence, first_seen_seq)`, `risk(status raised|cleared, score, raised_seq, cleared_seq)`, `proposal`, `order`. Each row carries `as_of_seq`.

Key queries:
```sql
-- Graph as of a point in the story (edges only; nodes analogous)
SELECT DISTINCT ON (payload->>'edge_id')
       payload->>'edge_id' AS edge_id, type, payload
FROM event
WHERE seq <= $cursor AND type IN ('edge.declared','edge.inferred','edge.trust_changed')
ORDER BY payload->>'edge_id', seq DESC;

-- Trust history of one edge (the rising-trust story)
SELECT recorded_at, payload->>'from' AS from_t, payload->>'to' AS to_t, payload->>'actor' AS actor
FROM event WHERE type = 'edge.trust_changed' AND payload->>'edge_id' = $e ORDER BY seq;

-- Buyer's story feed: only what the buyer may see
SELECT seq, type, payload, recorded_at FROM event
WHERE seq > $since AND visibility IN ('public', 'owner:' || $me)
   OR (visibility LIKE 'risk-of:%' AND split_part(visibility, ':', 2) = ANY($upstream_ids))
ORDER BY seq LIMIT 200;

-- Hash-chain check (tamper evidence)
SELECT seq FROM (SELECT seq, prev_hash, lag(hash) OVER (ORDER BY seq) AS p FROM event) x
WHERE prev_hash IS DISTINCT FROM p AND p IS NOT NULL;
```
Blast radius and hidden concentration use the same recursive CTEs as usual, filtered by `first_seen_seq <= $cursor`, so they also replay in time.

## 4. Agents (discovery, monitoring, procurement)
Each agent run emits `run.started`/`run.finished` so the timeline shows agent activity as bands. All use **Gemini** with function calling and structured output.
- **Discovery**: tools `contextdev.companyEnrich`, `contextdev.newsSearch`, `contextdev.extract(url, schema)`. Output: candidate edges with source URL and quote. Validation: the quote must appear verbatim in fetched text, and confidence is capped at 0.9. Emits `node.added` (unregistered), `edge.inferred`, and an invite event.
- **Monitoring**: Context.dev monitors and webhooks on supplier domains and news queries. On change, `extract` pulls certifications and recall notices. Gemini returns severity from a rubric and a one-sentence headline citing the URL. Emits `signal.recorded`; if the score crosses 0.5, `risk.raised`. Batch re-check every 6 hours.
- **Procurement**: triggered by `risk.raised` or a price premium over opted-in published alternatives. Tools `valio.productLookup`, `valio.availability`, `valio.quote`, `valio.substitutions` (assumption: quote and order endpoints exist in the mock). Emits `proposal.created` with quote ID and `quote_hash`, then waits for `approval.granted`. The order call refuses unless the hash matches and the quote is under 10 minutes old. Spend cap €2,000.
- Exceptions are events too: partial availability emits a substitution proposal with the same certification; no substitute escalates to the manager.

## 5. Risk engine
Rules compute scores; Gemini only classifies text. Risks have a lifecycle: `risk.raised` when a score crosses 0.5, `risk.cleared` when the evidence ages out or a fresh signal disconfirms it. The timeline shows risks appearing and disappearing.
- **Geopolitical**: seeded country index plus conflict or trade-restriction news.
- **Regulatory**: sanctions name match (fuzzy ≥ 0.92; assumption: EU consolidated list loaded at build); certificate expiry; EUDR commodity without geolocation certificate; CSDDD flag.
- **Concentration**: several direct suppliers sharing an upstream root (≥ 2), weighted by the root's risk; single-source flag per product.
- **Financial**: insolvency and layoffs news via `companyEnrich` and `newsSearch`.
- **Live events**: recalls, strikes, outages, negative news, each with a decay half-life (recall 60 days, news 14 days).
- **Price premium**: (ours − cheapest opted-in published alternative) / alternative, capped at 25%.
- Every risk cites at least one signal with URL. No evidence, no event.

## 6. Screens and graph view
- **Story (hero)**: timeline scrubber at the bottom with event markers; playback at 1x, 8x, 30x; live feed on the right. Each card shows headline, type, `recorded_at`, source URL and webhook-to-card latency.
- **Map**: Cytoscape, upstream left to downstream right. Edges: dashed `inferred` (confidence label), solid `claimed`, thick `agreed`, double `audited`. Nodes fade in at `first_seen_seq`; trust upgrades pulse; risk colours the node and cleared risks fade.
- **Risk card**: factors, severity, source, status history.
- **Alternatives**: opted-in suppliers, published price range, anonymised peer usage (k ≥ 5).
- **Proposal and approval**: guardrail ticks, approve or reject; approval binds to `quote_hash`.
- **Audit view**: the raw event rows with hash verification badge.
- **Supplier and auditor**: confirm edges (claimed → agreed), stamp `audited`.

## 7. Demo script (timed beats)
- 0:00–0:25: scrubber at Jan 2025: Valio alone with a dozen suppliers. "This is a network with a past."
- 0:25–0:50: play at 30x: 60 nodes appear, dashed edges harden to solid as parties confirm.
- 0:50–1:30: **live**: "Watch the web" starts a Context.dev news search and a monitor on the dairy producer. A new card lands with URL, Gemini headline and latency in seconds. The risk fades in on the map.
- 1:30–2:05: log in as "Hotel Kalevala Group" (dummy). Its feed shows only its own edges and warnings; another company's private edges are absent. Open the concentration risk: three processors share the dairy producer.
- 2:05–2:30: alternatives with a published price range and peer usage 17% (k ≥ 5).
- 2:30–3:10: procurement feed cards: `proposal.created`, substitution for partial availability, approval, `order.placed` with Valio mock order ID.
- 3:10–3:40: supplier confirms edge (claimed → agreed); auditor stamps `audited`; trust bars update live.
- 3:40–4:00: scrub back to "before the recall": the risk was not yet known. Verify the hash chain badge.

## 9. Judging-criteria mapping
- **Valio (30% demo, 20% need, 20% controls, 15% exceptions, 15% standards)**: order event chain with approval bound to quote hash; substitution events; hash-chained audit log; OpenAPI client and JSON-schema events.
- **Context.dev**: live news and monitors in the core flow; real-timeness shown as webhook-to-card latency; source URLs on every card.
- **Gemini (€4k)**: headlines, severity rubric with quote checks, procurement function calling.
- **Aiven (€1k)**: Postgres event log, Valkey fan-out, Runtime hosting.
- **CRACI**: GitHub Actions on CRACI runners, SBOM and vulnerability scan.
- **Codex**: projector, replay and visibility tests, logged in PR descriptions.
- **Trust and privacy**: `visibility` tags on every event; buyer feed enforced by query and RLS.

## 10. Risks and cuts
- Cut first: Cala (not in this design), then the scrubber's 30x playback, then auto-invites (seed manually), then the hash-chain badge (keep the chain, drop the UI).
- Never cut: the scrubber replay of the network, the live Context.dev card with URL, the approval gate, and buyer visibility filtering.
- Risks: synthetic history must look plausible (generate with a script, not by hand); webhook reachability (poll fallback); Gemini headline drift (quote check drops it); SSE reconnect gaps (replay from `seq`).

## 11. Biggest weakness of this proposal (be honest)
Most of the build goes into the timeline and event pipeline, so the procurement and risk features may look thinner than in a rules-first build. The synthetic 18-month history is a fiction we seed, which a sharp judge may see through, and the scrubber's value depends on the audience caring about history rather than on today's risk.

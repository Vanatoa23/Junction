# Entrant 60: Hold Week (lens: Scenario designer)

## 0. Bold bet
One causal chain drives the whole demo: a production hold at a shared upstream dairy co-op triggers a hidden-concentration alert, a price premium, a switch to opt-in alternatives, and a partial-availability exception mid-order. Every judging criterion gets a specific on-screen beat from this single story, and the seeded facts are chosen so each beat is guaranteed to fire.

## 1. Summary and name
- **Hold Week**: a hotel buyer's dairy basket is threatened by an upstream hold it could not see. The network shows the exposure, offers visible alternatives, and the buyer approves a switch that goes through Valio's mock API.
- Persona: **Hotel Lumi Group** (fictional, six hotels), buying through Valio Aimo. Weekly basket: 120 × butter 500 g, 80 × whipping cream 1 L, 200 × milk 1 L.
- All non-Valio companies are fictional except where a live scan names a real public domain. Team checks names for collisions before the demo.

## 2. Architecture and DB choice
- **Postgres on Aiven** as the only store. Graph as edge table with recursive CTEs; events, decisions and auth in the same DB. Reason: four engineers, one dialect, Aiven bounty. ArcadeDB is not used on the critical path.
- Components: React app; Node/TypeScript API on Aiven Runtime (assumption: container deploy); agent worker (cron plus Context.dev webhook at `/hooks/ctx`); Valio mock client; Gemini client for classification and proposal drafting.
- Flow: agent tool call → `evidence` row → claim JSON → validator (unknown evidence IDs rejected) → graph, risk or decision write plus `event_log` row in one transaction → UI.
- Valio mock: `GET /products`, `GET /availability`, `POST /orders` (idempotency key = decision ID; assumption: mock supports partial fills and substitution flags).

## 3. Data model and key queries
Tables: `company(id, name, tier, status[unregistered|registered], opted_in)`, `edge(src, dst, category, trust, confidence)`, `evidence(edge_id, url, excerpt, retrieved_at, sha256)`, `risk(company_id, type, severity, score)`, `score_factor(risk_id, factor, weight, value, conf, contribution)`, `price(company_id, sku, min, max, published)`, `decision(id, option, rejected, status, approver)`, `event_log(seq, actor, verb, why, evidence_ids, prev_hash, hash)`.

Trust rules: `agreed` needs two confirm events; `audited` needs a stamp event; `inferred` confidence 0.4 / 0.7 / 0.85 for 1 / 2 / 3+ independent URLs.

Seed graph (Tier 0 = Valio; Tier 1 direct suppliers; Tier 2 upstream):
- Pohjola Maito Oy (Tier 1, butter and cream) → Valio, edge `claimed`.
- Kallio Juusto Oy (Tier 1, cheese) → Valio, `agreed`.
- Nordic Dairy Co-op (Tier 2, raw milk) → Pohjola Maito and → Kallio Juusto. Edges `claimed`, then `agreed` after NDC confirms.
- 47 member farms (Tier 3), aggregated only.
- Lakeside Dairy Group (alternative, opted in, `inferred` at 0.7 from two supplier-list URLs, then `claimed` after it declares itself).
- Kettu Dairy Ltd (alternative, opted in, certificate expired).
- Baltic Butter Ltd (alternative, not opted in, hidden from buyer).

Key queries (SQL):
- **Upstream:** `WITH RECURSIVE up AS (SELECT src, dst, 1 d, ARRAY[dst] p FROM edge WHERE dst='valio' UNION ALL SELECT e.src, e.dst, up.d+1, up.p||e.src FROM edge e JOIN up ON e.dst=up.src WHERE up.d<4 AND NOT e.src=ANY(up.p)) SELECT * FROM up;` Result for Lumi: Pohjola, Kallio (depth 1), NDC (depth 2), 47 farms (depth 3).
- **Hidden concentration:** `SELECT e2.src AS upstream, COUNT(DISTINCT e1.src) n FROM edge e1 JOIN edge e2 ON e2.dst=e1.src WHERE e1.dst='valio' GROUP BY e2.src HAVING COUNT(DISTINCT e1.src)>=2;` Returns NDC, n=2.
- **Blast radius (NDC):** downward recursion from `src='ndc'`, returning distinct buyers reached. Result: Pohjola, Kallio, Valio, Lumi plus three other hotels.
- **Alternatives:** `company JOIN price ON published JOIN opted_in WHERE category='butter' AND id NOT IN current suppliers ORDER BY max`.

## 4. Agents (discovery, monitoring, procurement)
- **Discovery (pre-demo, plus one live run).** Context.dev company enrichment on Lakeside's domain and a news search for "dairy supplier" produce two URLs for the Lakeside→Valio edge. Gemini classifies relevance and must cite supplied evidence IDs. Output: `inferred` edge at 0.7, labelled.
- **Monitoring (the live beat).** Context.dev monitor on NDC's domain and two Finnish food-safety news pages, with webhook. Gemini prompt: "Given this page diff, return {event_type, product, date, source_url} or null. Cite only supplied IDs." The seeded hold notice is published on a demo news page we control, labelled "demo-seeded source" on screen. A live scan of three real Finnish dairy producer domains runs on stage with timestamps, so one real pull is guaranteed.
- **Procurement.** Trigger: NDC event severity >= 3 and Pohjola emergency price +9% over Lakeside's published range. Output: decision draft with rejected options and reasons, status `pending`. Order call only after manager approval.

## 5. Risk engine
Score = min(100, Σ weight × value × confidence × decay). Seed values produce these scores:
- **Live event (NDC hold):** weight 60, value 1.0, conf 0.8 (two URLs), decay 1.0 → 48. Plus concentration.
- **Concentration:** NDC shared by two Tier-1 suppliers → 62 (weight 40 × value 2/2 × conf 1.0 × 1.55 rounding for Lumi's 100% dependence on that chain in butter and cream).
- **Regulatory:** Kettu certificate expired (partner dataset) → 40 on the rejected alternative card.
- **Price premium:** Pohjola emergency price €3.49 vs Lakeside published €3.20–3.36 → 35.
- Sanctions and geopolitical checks run and return clean for all seeded companies, shown as green ticks (required beat).
Decay half-life 30 days. Each factor stored, so judges can click the score.

## 6. Screens and graph view
- **Map:** Valio centre, Tier 0 to Tier 2 left to right, arrows for direction. Dotted = inferred (Lakeside), solid = claimed, thick = agreed, double = audited. NDC has a red ring, Pohjola and Kallio amber.
- **Risk alert:** headline "Nordic Dairy Co-op: production hold (2 sources)", score bars, links, "Why you see this: upstream risk, visibility rule 2a."
- **Alternatives:** table with price band, certificate status, lead time, opt-in badge, and "used by 9 of 14 hotels in category (n>=5)". Baltic Butter absent, with note "not visible: not opted in".
- **Proposal:** options and rejected options; Approve button records the manager's name.
- **Exception card:** partial availability (Lakeside 90 of 120 butter) → substitute 30 units with Valio own-brand unsalted butter (mock catalogue) → re-approval.
- **Trail:** chronological log with evidence chips and a Verify chain button.

## 7. Demo script (timed beats, 4 min)
- 0:00–0:25: login as Lumi. Map shows red NDC ring. "Every edge says how we know it."
- 0:25–0:55: click NDC: hold notice, two URLs, timestamp. Score breakdown. Visibility line.
- 0:55–1:25: live scan of three real domains, results stream in with URLs. Lakeside inferred edge appears.
- 1:25–1:50: concentration card: "Pohjola and Kallio both rely on NDC." Blast radius shows Lumi and three other hotels.
- 1:50–2:20: alternatives: Lakeside and Kettu visible; Baltic hidden. Kettu's certificate shows expired (rejected). Aggregate shows n=9 of 14.
- 2:20–2:45: procurement proposal with reasons. Manager clicks Approve. Mock order returns ID.
- 2:45–3:10: exception: Lakeside 90 of 120. Substitution card with Valio own-brand. Re-approval, order completes.
- 3:10–3:30: supplier NDC confirms the Pohjola edge (claimed to agreed). Auditor stamps Lakeside→Valio (audited).
- 3:30–4:00: Trail: Verify chain, then Tamper one row, Verify fails with the row named.

## 9. Judging-criteria mapping
- **Valio end-to-end (30%):** approval-gated mock order at 2:20 and re-approved order at 2:45.
- **Buyer need (20%):** a concrete basket, a concrete price gap (€3.49 vs €3.20–3.36), a concrete switch.
- **Autonomy and controls (20%):** rejected options with reasons, approver name, Verify chain with tamper test.
- **Exceptions (15%):** partial availability and substitution is an entire beat.
- **Open standards (15%):** decision and event exports as JSON; SHA-256 chain (assumption: judges value exportable records).
- **Context.dev (15%):** live scan, monitor webhook, enrichment, timestamps on screen.
- **Trust and privacy (10%):** opt-in filter, n >= 5 aggregate, hidden Baltic Butter.
- **Side bounties:** Gemini (classifier and drafts), Aiven (Postgres and Runtime), CRACI (CI on the repo). Codex only if genuinely used.

## 10. Risks and cuts
- Cut order: Tamper test becomes a screenshot; Kettu rejection becomes text; monitor webhook becomes 15-minute poll; Lakeside discovery becomes a seeded inferred edge with two URLs.
- Biggest risks: the live scan returns nothing (mitigation: cached result with timestamp shown as cached); Valio mock partial-fill behaviour not as assumed (mitigation: fixed mock contract agreed Friday with the sponsor's mock); judges question the seeded news source (mitigation: label it on screen and in the script).

## 11. Biggest weakness of this proposal (be honest)
The story is engineered, so a judge may read it as rigged. Anything outside the scripted basket, such as a different buyer or an unseeded question, gets a weak answer. The demo leans on one seeded hold notice, which is honest only if the label stays visible.

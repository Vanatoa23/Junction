# Entrant 54: Ledgerline on Aiven (lens: Aiven-hosted stack)
## 0. Bold bet
We run the whole product on one Aiven footprint (Postgres, Valkey, Runtime), used only where each service removes a real demo risk: Postgres as the single source of truth, Valkey for live agent progress, Runtime so judges hit a stable URL. The result is a credible production path that a judge can see on a dashboard, not a laptop-only prototype.

## 1. Summary and name
**Ledgerline**: a living supply-chain network where every edge has a trust level and every risk has a source link. A hotel buyer sees its supply map, a live Context.dev-sourced risk alert, opt-in alternatives with published prices, and a procurement proposal that a manager approves before the Valio mock API places the order.
Assumptions: Valio mock API endpoints match the brief; Aiven free or hackathon credits cover Postgres, Valkey and Runtime for the weekend; Gemini model `gemini-2.5-flash` (verify day 1).

## 2. Architecture and DB choice
- **Aiven for PostgreSQL**: system of record. Companies, edges, trust, visibility, proposals, approvals, audit log.
- **ArcadeDB: not used.** Graph depth is at most 4 hops over a few hundred companies. Recursive CTEs cover upstream, hidden concentration and blast radius. Adding ArcadeDB means a second engine and query language in 48h. Named as the post-hackathon option for traversal at scale.
- **Aiven for Valkey**: pub/sub channel for live agent progress (`run:{id}`) pushed to the UI over SSE, plus a rate-limit counter for Context.dev calls. Valkey is not the source of truth; losing it loses only progress ticks.
- **Kafka: deliberately not used in the demo.** A transactional outbox table in Postgres plus a worker poll gives the same at-least-once delivery with no broker. Aiven Kafka is the stated path to production once event volume justifies it.
- **Aiven Runtime**: hosts the FastAPI backend and the React build. One URL for judges.
- Services: FastAPI, React and Cytoscape.js, Gemini via `google-genai`, Context.dev SDK (Python), Valio mock REST client.
- Event flow: Context.dev monitor webhook → `/hooks/ctx` → `outbox` row in the same transaction as `source_item` → worker picks it up → agent run → outbox row for proposal → UI via Valkey pub/sub.

## 3. Data model and key queries
- `company(id, name, country, industry, status enum[seeded,scraped,registered], vat_id, visible_opt_in bool)`
- `edge(id, supplier_id, buyer_id, category, trust enum[inferred,claimed,agreed,audited], confidence numeric null, sources jsonb, price_published jsonb null)`
- `edge_event(id, edge_id, from_trust, to_trust, actor, actor_type enum[human,agent,system], reason, ts)`. The only path that changes `trust`. A DB trigger rejects `agreed` or `audited` when the actor is an agent.
- `risk_signal(id, company_id, type enum[geo,reg,conc,fin,event,price], severity, confidence, evidence jsonb, status, valid_until)`
- `source_item(id, url unique, domain, retrieved_at, provider, text)`
- `proposal(id, kind enum[edge_inferred,risk_alert,switch_order], payload jsonb, status enum[pending,approved,rejected,executed], decided_by, decided_at)`
- `agent_run(id, agent, model, input jsonb, tool_calls jsonb, output jsonb, status, ts)`
- `outbox(id, topic, payload jsonb, created_at, processed_at)`
- `audit_log(id, actor, actor_type, action, args jsonb, result jsonb, ts)`, append-only (UPDATE and DELETE revoked).

Visibility in SQL views:
- `v_buyer_risk`: active `risk_signal` rows for companies in the buyer's upstream closure.
- `v_industry_usage`: supplier usage per industry, suppressed when count < 5.
- `v_alternatives`: `visible_opt_in` suppliers with `price_published` set.
- The API connects as a role that can only read these views for buyer endpoints. Own-map tables are not granted.

Queries:
- Upstream (depth 4, cycle-safe):
```sql
WITH RECURSIVE up(id, via, depth, path) AS (
  SELECT supplier_id, supplier_id, 1, ARRAY[supplier_id] FROM edge WHERE buyer_id=$1
  UNION ALL
  SELECT e.supplier_id, up.via, up.depth+1, up.path||e.supplier_id
  FROM edge e JOIN up ON e.buyer_id=up.id
  WHERE up.depth<4 AND NOT e.supplier_id=ANY(up.path))
SELECT id, MIN(depth) FROM up GROUP BY id;
```
- Hidden concentration: `SELECT id FROM up GROUP BY id HAVING COUNT(DISTINCT via) >= 2`.
- Blast radius: the same recursion walking `buyer_id` downstream from the failed supplier, joined to `order_history` for weekly volume.
- Alternatives: `SELECT * FROM v_alternatives WHERE category=$1 ORDER BY price_published->>'min'`.

## 4. Agents (discovery, monitoring, procurement)
All agents use Gemini, run in the Runtime worker, and write `agent_run` plus Valkey progress events.

**Discovery (function calling).**
- Allowlist: `news_search(query, since_iso, limit<=10)`, `company_enrich(domain)`, `propose_edge(...)`. Mode `ANY`, `allowedFunctionNames` set to these three.
```json
{"name":"propose_edge","description":"Propose a supplier link as INFERRED. No edge is written until corroborated.",
 "parameters":{"type":"OBJECT","properties":{
   "supplier_name":{"type":"STRING"},"buyer_name":{"type":"STRING"},
   "category":{"type":"STRING","enum":["dairy","meat","produce","dry_goods","beverages","packaging"]},
   "confidence":{"type":"NUMBER"},
   "source_urls":{"type":"ARRAY","items":{"type":"STRING"},"minItems":1}},
 "required":["supplier_name","buyer_name","category","confidence","source_urls"]}}
```
- Final output: a second Gemini call with `responseSchema` over the tool transcript (assumption: tool calling and JSON schema are not combined in one request; verify day 1).
- Validation (code): URLs must appear in tool results. Confidence above 0.7 needs 2 distinct domains; otherwise capped at 0.6. Below 0.4 is dropped.

**Monitoring (extraction, then code).**
- Trigger: Context.dev monitor webhook, or scheduled `news_search` per company.
- Gemini, no tools, `responseSchema`: `{claims:[{company_name, type enum[geo,reg,conc,fin,event,price], claim_text, quote, event_date, severity_hint 0-1}]}`.
- Code checks each `quote` is a verbatim substring of `source_item.text`. Failures are rejected.
- Signal confidence = distinct domains; two or more is a corroborated signal.

**Procurement (thin, one step).**
- Calls `valio_check_availability(sku, qty, date)` and `v_alternatives`.
- One Gemini call with `responseSchema`: `{alt_sku, price_delta_pct, delivery_days, rationale<=40 words, evidence_refs[]}`.
- No order tool is in any model's allowlist. Approval calls `valio_place_order` with the stored payload, writes `audit_log`, and changes `proposal.status`.

## 5. Risk engine
- **Geopolitical:** seeded country-risk table (labelled as seeded). Score = table value x 0.5 plus corroborated conflict or trade-restriction claims.
- **Regulatory:** sanctions name match on a static EU consolidated-list snapshot (assumption), normalised similarity >= 0.9 = 1.0. Certificate expiry from Valio sustainability data. EUDR flag for cocoa, soy, palm and beef without a deforestation-free certificate. CSDDD flag when due-diligence records are missing.
- **Concentration:** single source in a category = 0.4. Hidden shared upstream through >= 2 direct suppliers = 0.7, scaled by volume share.
- **Financial:** insolvency 0.9, layoffs 0.4, funding stress 0.3 (Context.dev news plus classifier).
- **Live events:** recalls, strikes and outages from monitors, weighted by severity_hint and corroboration.
- **Price premium:** published prices only. Premium above 10% = 0.3, above 25% = 0.6.
- Aggregate: 1 - product(1 - s_i). Red >= 0.7, amber >= 0.4. Decay halves event weights every 7 days.
- Each alert stores its driver signal IDs and evidence URLs. No evidence, no alert.

## 6. Screens and graph view
1. Buyer home: radar of red and amber companies, Valio at centre.
2. Supply map: arrows supplier to buyer; node ring = risk; edge style = trust (dashed inferred with confidence badge, grey claimed, solid agreed, gold double audited).
3. Risk detail: claim, verified quote, source URLs with retrieval timestamps, decay.
4. Alternatives: opt-in suppliers, price ranges, industry usage bars (k >= 5 only).
5. Proposal: diff, rationale, evidence, Approve or Reject.
6. Live run panel: SSE stream from Valkey showing each tool call and URL as it lands.
7. Supplier view (confirm claimed to agreed); auditor view (stamp audited); audit timeline.

## 7. Demo script (4 min)
- 0:00-0:25 Open the Runtime URL. Radar: red ring on an upstream dairy co-op. Show its quote and sources.
- 0:25-1:05 Live: "Scan now". Live panel streams Context.dev news calls and URLs. New dashed edge at confidence 0.74 with 2 domains.
- 1:05-1:35 A monitor webhook lands a second source; the signal moves from unconfirmed to corroborated, and the ring turns amber.
- 1:35-2:05 Hidden concentration: three Valio dairy suppliers share one co-op.
- 2:05-2:40 Alternatives with price ranges and usage bars.
- 2:40-3:10 Procurement proposal. Manager approves. Valio mock order ID.
- 3:10-3:40 Supplier confirms claimed to agreed. Auditor stamps audited.
- 3:40-4:05 Audit timeline; point at the Postgres dashboard as the single record.
Fallback: the pre-recorded run, labelled as replay.

## 9. Judging-criteria mapping
- **Valio (30%):** approval gate, mock order only after approval, audit log, partial availability.
- **Buyer need (20%):** radar, alternatives, procurement in one flow.
- **Feasibility (25%):** Postgres plus Valkey plus Runtime only; no Kafka; ArcadeDB out.
- **Context.dev (15%):** news search, extraction, monitor webhooks in the core path; live panel shows sources.
- **Trust and privacy (10%):** DB triggers on trust, views with restricted role.
- **Concreteness (10%):** schemas, SQL, prompts.
- **Bounties:** Aiven (Postgres, Valkey, Runtime, and the path to Kafka), Gemini (agents), CRACI (CI with SBOM, about an hour). Cala and Codex skipped.

## 10. Risks and cuts
- **Cut first:** Valkey live panel (fall back to polling), Kafka (never started), ArcadeDB, Cala, Oxylabs, Modal.
- **Risk:** Runtime deploy problems on Saturday. Mitigation: deploy hello-world Friday night; keep a local fallback.
- **Risk:** Context.dev latency or rate limits. Mitigation: Valkey counter, cached recorded run.
- **Risk:** Valio mock API differences. Mitigation: Friday-morning contract check.

## 11. Biggest weakness of this proposal (be honest)
Aiven is in the stack for credibility and the bounty, so the hosting work competes with the core flow for scarce hours on Friday and Saturday. Judges may also see Kafka as absent and Valkey as decorative if the live panel is cut. Procurement is a single step, which is thin on exceptions.

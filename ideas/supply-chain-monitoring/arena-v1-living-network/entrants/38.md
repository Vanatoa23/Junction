# Entrant 38: Fathom (lens: Chat-first copilot UI)

## 0. Bold bet
The buyer's main interface is a chat with a copilot, and every answer is assembled from tool results as graph snippets, risk cards and one-click actions, not prose alone. Judges type unscripted questions live and get verifiable answers in seconds, and the approval step becomes a button inside the conversation.

## 1. Summary and name
- **Fathom**: ask your supply chain a question and see the answer as a graph. "What happens if Nordic Dairy Co-op fails?" returns a blast-radius snippet, the affected Valio products, and an action to find a switch.
- Persona: Hotel Lumi Group (fictional) buying through Valio Aimo. Dummy companies are fictional; real companies appear only from live scans.

## 2. Architecture and DB choice
- **Postgres on Aiven** is the single store: graph as an edge table with recursive CTEs, plus events, chat, decisions and auth. Reason: four engineers, one query dialect, Aiven bounty. ArcadeDB is off the critical path; an optional Cypher mirror is considered only if Saturday is green.
- Components: React app (chat on the left, graph canvas on the right); Node/TypeScript API on Aiven Runtime (assumption: Runtime runs a container); Copilot service calling Gemini with function calling over a fixed tool registry; agent worker for discovery and monitoring; Context.dev webhook endpoint; Valio mock client.
- Request flow: message → Copilot gets viewer ID and tool schemas → Gemini selects tools → tools execute as the viewer (visibility enforced inside each tool) → results rendered as answer cards → message and tool calls stored.
- **Guardrail:** the LLM's tool list contains no order-placing tool. The order exists only as an endpoint called by an Approve button on a decision card. The endpoint checks `decision.status = approved` and the approver's role.
- **Deterministic fallback:** if Gemini errors or exceeds 4 s, a keyword router maps about eight scripted question patterns to the same tools. The demo never depends on the LLM being up.

## 3. Data model and key queries
Tables:
- `company(id, name, country, industry, status[unregistered|registered], source_url)`
- `edge(id, src_id, dst_id, category, trust[inferred|claimed|agreed|audited], confidence, created_by)`
- `edge_evidence(id, edge_id, kind, url, excerpt, retrieved_at)`
- `risk(id, company_id, type, severity, score, status, created_at)`
- `visibility(company_id, opted_in)`; `price_publication(company_id, sku, min, max, currency)`
- `chat_message(id, thread_id, role[user|copilot], text, created_at)`
- `answer_card(id, message_id, kind[graph|risk|alternatives|decision|trail], payload jsonb)`
- `tool_call(id, message_id, viewer_id, tool, args jsonb, result_hash, ms, started_at)`
- `decision(id, risk_id, option jsonb, rejected jsonb, status[pending|approved|rejected|ordered], approver_id)`
- `event_log(seq, actor, verb, subject, why, evidence_ids[], prev_hash, hash)`, hash-chained with SHA-256.

Trust is derived: `agreed` needs two confirm events; `audited` needs an auditor stamp event; `inferred` confidence is 0.4 / 0.7 / 0.85 for 1 / 2 / 3+ independent sources (our rule).

Visibility enforcement: every read tool calls `visible_graph(viewer_id)` internally. The LLM sees only tool output, never raw tables. Industry aggregates require n >= 5. A test suite of ten private-edge probes must return nothing.

Key tool queries (SQL):
- `upstream(company, depth<=4)`: recursive CTE, `dst_id = up.src_id`, cycle-safe with an array path.
- `hidden_concentration(buyer)`: join buyer's direct suppliers `e1` to their suppliers `e2`, group by `e2.src_id`, keep groups with `COUNT(DISTINCT e1.src_id) >= 2`.
- `blast_radius(failed)`: downward recursion (`src_id = cur.dst_id`), returning distinct buyers reached and the path to each.
- `alternatives(category, viewer)`: `company JOIN visibility(opted_in) JOIN price_publication`, filtered on category, excluding current suppliers, `trust IN ('agreed','audited')`, ordered by max price, limit 5.
- `subgraph(answer_ids, hops=2)`: returns nodes and edges as JSON for the mini-canvas, with trust and risk attributes.

## 4. Agents (discovery, monitoring, procurement)
Tools exposed to the Copilot: `find_upstream`, `hidden_concentration`, `blast_radius`, `alternatives`, `price_lookup` (Valio mock), `risk_list`, `explain_edge`, `scan_web(company)` (live Context.dev), `propose_switch(risk_id)` (creates a pending decision only). Each tool is a JSON Schema function spec (assumption: this maps cleanly to MCP later).
- **Discovery.** Trigger: chat request ("look for more dairy suppliers") or nightly run. Inputs: Valio supplier list and category seeds. Tools: Context.dev company enrichment and news search. Gemini only classifies relevance and must cite evidence IDs we supplied; unknown IDs are rejected. Output: `inferred` edges and unregistered companies with invitations. No gate for inferred edges, which are labelled.
- **Monitoring.** Context.dev monitors on supplier domains and risk keywords, webhook to `/hooks/ctx`, plus a 15-minute poll fallback. Output: `risk` rows, and a notice card posted into the chat: "New recall notice for Nordic Dairy Co-op [url], 2 min ago."
- **Procurement.** Trigger: severity >= 3 or price premium above 8% against a published alternative. Tools: `alternatives`, `price_lookup`, mock availability. Output: decision card with the chosen option, rejected options and reasons ("B: 5-day lead time; C: certification expired"), and Approve/Reject buttons. Partial availability creates a substitution card that needs its own approval. The order call uses the decision ID as its idempotency key.

## 5. Risk engine
Score = min(100, Σ weight × value × confidence × decay), half-life 30 days. Factors are stored and shown on the card.
- **Geopolitical:** seeded country-risk index (assumption) × Context.dev news hits on country keywords.
- **Regulatory:** EU consolidated sanctions CSV (hashed, fuzzy name match); certification expiry from the partner dataset; EUDR/CSDDD flag for commodity categories (cocoa, soy, palm, beef, coffee, wood) without a deforestation declaration.
- **Concentration:** `hidden_concentration`; single-source flag when one supplier exceeds 80% of category spend.
- **Financial:** Context.dev enrichment (headcount and funding change) plus negative-news terms.
- **Live events:** monitor hits for recall, strike and outage terms.
- **Price premium:** unit price against the lowest opt-in published alternative, only where published.

## 6. Screens and graph view
- **Chat (left, about 40%):** the default surface. Starter prompt chips: "Show my supply map", "Upstream risks", "Who else relies on Nordic Dairy?", "Cheaper compliant oat drink?".
- **Canvas (right, about 60%):** shows the subgraph of the latest answer, with arrows for direction (upstream left). Edge style encodes trust: dotted = inferred, solid = claimed, thick = agreed, double = audited. Red ring = open risk, amber = concentration. Clicking an edge posts "explain this edge" into the chat.
- **Answer cards:** graph snippet; risk card (score bars with the factors listed); alternatives card (opt-in badge, price band, "used by X of Y peers, n>=5" or "suppressed, n<5"); decision card (options, rejected reasons, Approve/Reject); trail card.
- **Trail tab:** event_log and tool_call timeline, a Verify chain button, and JSON export.
- **Confirm and stamp:** supplier and auditor accounts receive cards in their chat ("Hotel Lumi declared you as a supplier. Confirm?" / "Stamp this edge").

## 7. Demo script (about 4 min)
- 0:00–0:20: login, starter chips, map.
- 0:20–0:50: "Show my dairy supply chain." Snippet with trust styling. Click an inferred edge: explain card with two URLs and confidence 0.7.
- 0:50–1:25: "Scan Nordic Dairy Co-op for news." Live Context.dev calls stream into the chat with timestamps and URLs. A new inferred company appears on the canvas.
- 1:25–1:55: monitor notice card, then "What happens if Nordic Dairy Co-op fails?" Blast-radius snippet with three affected Valio products.
- 1:55–2:25: "Who else relies on this upstream co-op?" Hidden-concentration answer with the aggregate or the n<5 suppression note.
- 2:25–2:55: "Cheaper compliant alternatives?" Three opt-in options with price bands. A non-opted-in supplier is listed as "not visible: not opted in".
- 2:55–3:25: decision card. The manager clicks Approve. Mock Valio order ID returns.
- 3:25–3:45: partial availability, substitution card, re-approval.
- 3:45–4:05: Trail. Verify chain passes. Ask "Why did you switch?" and get an answer built from the event log, with links.
- 4:05–4:20: supplier confirms (claimed to agreed), auditor stamps (audited), both visible in the chat history.

## 9. Judging-criteria mapping
- **Valio end-to-end (30%):** chat-driven flow ending in a mock order after a button approval.
- **Buyer need (20%):** the buyer asks in plain language and gets answers from its own map; no UI to learn.
- **Autonomy and controls (20%):** no order tool in the LLM; approval is a button; tool_call log records every query and its viewer.
- **Exceptions (15%):** substitution card in the chat.
- **Open standards (15%):** JSON Schema tool specs (assumption), decision and event JSON export.
- **Context.dev (15%):** `scan_web` in the chat, monitors and webhooks, latency shown per call.
- **Feasibility (25%):** one database, deterministic fallback.
- **Privacy (10%):** visibility inside tools, probe tests.
- **Side bounties:** Gemini (copilot function calling and classifier), Aiven (Postgres and Runtime), CRACI (CI on the repo). Codex only if genuinely used.

## 10. Risks and cuts
- Cut order: ArcadeDB mirror (never started); free-form Gemini answers become templates; webhooks become polling; canvas library becomes static SVG; Trail verify becomes a plain log.
- Risks: intent misrouting (mitigated by forced tool choice and the fallback router); Context.dev latency during the live scan (cached last-good result with timestamp); chat latency (stream tokens and show tool progress).

## 11. Biggest weakness of this proposal (be honest)
Chat-first makes answer quality depend on intent routing. A judge who asks an unscripted question may get a weak or misrouted answer, and the copilot is a second major UI surface competing with the map and approval screens for a 48-hour budget.

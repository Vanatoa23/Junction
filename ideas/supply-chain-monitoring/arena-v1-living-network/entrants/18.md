# Entrant 18: ChainProof (lens: EU compliance desk)

## 0. Bold bet
ChainProof treats the buyer's job as due diligence evidence, not network visualisation: every edge, certificate and compliance claim carries a source URL, snapshot hash and timestamp, and an order for a regulated line is blocked until its evidence pack is complete. It wins because Valio scores buyer need and guardrails/auditability at 20% each, and a compliance-gated, human-approved order is the most defensible version of both.

## 1. Summary and name
- Name: **ChainProof**.
- Hotel chain logs in, sees its Valio-centred supply map, and a compliance desk shows CSDDD and EUDR status per supplier. A monitor flags an upstream dairy producer: lapsed certificate and no deforestation statement for soy in its feed. Procurement proposes an opted-in alternative with a complete evidence pack and a published price range. A manager approves, the order goes to the Valio mock API, and every step is logged.
- Assumptions (verify, not counsel-checked): EUDR applies to large operators from the currently amended date (demo assumes 30 Dec 2026). CSDDD scope is as narrowed by the 2025 Omnibus simplification, as we understand it. Dairy is not an EUDR commodity; the EUDR link is soy in feed and palm in ingredients. The app is decision support, not legal advice.

## 2. Architecture and DB choice
- **Postgres only** (Aiven managed, for the Aiven bounty). Recursive CTEs cover upstream traversal, concentration and blast radius at demo scale (hundreds of nodes). JSONB holds certificate and statement payloads. An append-only table gives the audit chain. The team already knows SQL.
- **ArcadeDB rejected as primary**: Docker/Helm setup and a new query language are a 48h risk. Optional stretch only if someone already knows Cypher.
- Alternatives: category and certificate match in SQL. pgvector only if Aiven enables it (assumption, not needed for the demo).
- Components: React + Cytoscape.js frontend; FastAPI backend; Python agents using Gemini function calling; Context.dev SDK (structured extraction, news, monitors with webhook); Valio mock client; one worker process for schedules.
- Flow: Context.dev monitor/webhook → `source_event` → monitoring agent (Gemini classifies, validates) → `evidence` + `risk_signal` → risk engine → desk and alert. Procurement reads opted-in alternatives → `proposal` → human approval → Valio order with idempotency key → `audit_event`.

## 3. Data model and key queries
- `company(id, name, country, lei, registered, sanctions_hit)`; `site(company_id, country, geo jsonb)` for EUDR plots.
- `supply_edge(src, dst, category, trust enum{inferred,claimed,agreed,audited}, confidence, visibility enum{private,aggregate,opted_in}, price_min, price_max null unless published)`.
- `evidence(id, subject_type, subject_id, kind{cert,sanction,news,dds,csddd_policy}, source_url, snapshot_sha256, retrieved_at, extractor, confidence)`.
- `certification(company_id, scheme{FSC,PEFC,RSPO,ISCC,organic}, cert_no, commodity, valid_to, evidence_id)`.
- `dd_statement(company_id, regime{CSDDD,EUDR}, commodity, geo jsonb, dds_ref, evidence_ids[], status{complete,missing,expired})`.
- `audit_event(id, ts, actor, action, payload jsonb, prev_hash, hash)`. A verify endpoint recomputes the chain.
- **Trust enforcement**: `claimed→agreed` needs a supplier-confirm event by the counterparty; `agreed→audited` needs an event by the simulated auditor role. A DB trigger rejects any other transition.
- **Visibility enforcement**: buyers query only views. `v_buyer_risk` (open signals on suppliers), `v_alternatives` (opted_in and complete packs), `v_industry_agg` (usage count, suppressed when under 5). Private maps never join into buyer views. Suppliers write only their own edges.

Queries:
```sql
-- Upstream closure of the buyer (depth-bounded, cycle-safe)
WITH RECURSIVE up(root, node, depth) AS (
  SELECT src, src, 0 FROM supply_edge WHERE dst = $buyer
  UNION ALL
  SELECT up.root, e.src, up.depth+1 FROM up JOIN supply_edge e ON e.dst = up.node WHERE up.depth < 4)
SELECT node, COUNT(DISTINCT root) AS direct_paths FROM up WHERE depth > 0
GROUP BY node HAVING COUNT(DISTINCT root) >= 2;   -- hidden shared upstream = concentration

-- Blast radius of a failed supplier
WITH RECURSIVE down(node, depth) AS (
  SELECT dst, 1 FROM supply_edge WHERE src = $failed
  UNION SELECT e.dst, down.depth+1 FROM down JOIN supply_edge e ON e.src = down.node WHERE down.depth < 5)
SELECT DISTINCT node FROM down;

-- Alternatives: opted-in, complete compliance pack, certificate valid
SELECT c.* FROM v_alternatives a JOIN company c ON c.id = a.company_id
WHERE a.category = $cat AND a.required_scheme = ANY(a.schemes) ORDER BY a.price_min NULLS LAST;
```

## 4. Agents (discovery, monitoring, procurement)
Shared rule: every agent output is `{claim, source_url, snapshot_sha256, confidence}`. No write without an evidence row. Gemini runs with schema-constrained JSON and one retry.
- **Discovery**: inputs are Valio's supplier list plus Context.dev structured extraction on news and company pages (schema: name, country, supplier mentions, certificate mentions). Output: `inferred` edges. Validation: two distinct domains, or one registry source; LEI or normalised name match; confidence under 0.6 goes to a review queue. No human gate, because inferred is a suggestion and is badged as such.
- **Monitoring**: Context.dev monitors on each supplier's news and certificate-registry pages, with a webhook to `/hooks/change`. Gemini classifies changes into risk types with severity. Sanctions: match against a downloaded EU consolidated list file (assumption: loaded before the demo). A scheduled scan also runs, so the demo never depends on webhook timing.
- **Procurement**: triggered by a high-severity `risk_signal` or a published price premium. Steps: SQL query for alternatives, keep only complete packs, Gemini writes a rationale citing evidence IDs. Human approval: a manager approves, and the approval row stores the proposal hash. Then POST the order to Valio mock (endpoint shape is an assumption) with `Idempotency-Key = proposal_id`. Partial availability: fall back to the second alternative and log the substitution.

## 5. Risk engine
- Signal score = severity weight × confidence × recency decay (half-life 90 days). Company risk = max signal + 0.2 × sum of the rest, capped at 1.
- **Regulatory (highest weight)**: certificate past `valid_to` (0.9); sanctions name match (score from the matching function); EUDR statement missing for a soy or palm line (0.8); CSDDD policy or grievance mechanism missing (0.5).
- **Concentration**: the upstream query above. Severity scales with the share of Valio volume through the shared node (Valio synthetic data).
- **Geopolitical**: static country table for demo countries (labelled hand-set), plus conflict and trade-restriction news from Context.dev.
- **Financial and live events**: news monitors for insolvency, layoffs, recall, strike. Confidence rises with the number of independent sources.
- **Price premium**: (seller price − cheapest opted-in alternative) / alternative above 15%. Only where prices are published.

## 6. Screens and graph view
1. **Supply map**: Cytoscape. Valio centre; hotel on the left. Edge colour = trust (inferred dotted grey, claimed amber, agreed blue, audited green). Arrow = direction. Red halo = open risk. Dashed node = unregistered.
2. **Compliance desk**: one row per supplier. CSDDD checklist (policy URL, grievance mechanism, last assessment date). EUDR lines (commodity, geolocation, DDS reference). Certificate expiry countdown.
3. **Risk alert**: evidence cards showing source URL, snapshot hash, retrieved time, and "why flagged".
4. **Alternatives and approval**: side-by-side pack comparison, price range (published only), agent rationale with evidence IDs, approve or reject, Valio order result.
5. **Audit trail**: event list with a "verify chain" button.
6. **Supplier portal**: confirm edge, upload certificate (simulated), auditor stamp.

## 9. Judging-criteria mapping
- **Valio (30% demo, 20% need, 20% guardrails, 15% exceptions, 15% standards)**: order placed only after evidence and approval; buyer need is pre-order compliance; approval row, hash chain, idempotency and views are the guardrails; partial availability triggers substitution; LEI and GeoJSON EUDR geolocation as open identifiers.
- **Context.dev (15%)**: extraction and monitors drive the alert; live URLs on screen.
- **Trust and privacy (10%)**: views and k≥5 aggregates.
- **Concreteness (10%)**: schema and queries above.
- **Side bounties**: Gemini as main LLM; Aiven Postgres; CRACI; Codex only if used meaningfully. Skip Cala and Oxylabs.

## 10. Risks and cuts
- Cut order: Oxylabs and Cala (never in); Exa (Context.dev only); real auditor flow (simulated button); price premium; webhooks (scheduled scan only, keeping one live call); graph animation.
- Context.dev latency or quota: cache last good responses and show "cached, 2h ago". Never hide it.
- Gemini JSON drift: schema-constrained output and retry.
- Aiven provisioning: local Postgres in Docker as fallback.
- Legal accuracy: labelled as decision support.

## 11. Biggest weakness of this proposal
The compliance content is only as good as the mock evidence, and our CSDDD and EUDR checklists are simplified and unverified by counsel. Judges may see the desk as a checklist rather than an agent. The EUDR link to dairy runs through soy feed, which judges may question. The graph view will get less polish than a competitor's.

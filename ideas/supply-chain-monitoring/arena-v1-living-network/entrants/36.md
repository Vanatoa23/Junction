# Entrant 36: SupplyLens, a graph the judges can read in five seconds (lens: Graph visualisation UX)

## 0. Bold bet
We treat the graph view as the product's main surface, not a decoration: direction, trust, risk and tier are each encoded in a separate visual channel, and a "replay growth" slider lets judges watch the network build itself. Privacy is enforced by sending the browser only the visible subgraph, so the picture a buyer sees is the same picture the rules allow.

## 1. Summary and name
- Name: **SupplyLens**.
- Summary: a living supply graph where the buyer sees its own supply map laid out left-to-right by tier, with risk and trust readable at a glance. Upstream companies beyond the first hop stay collapsed into private clusters unless they carry a risk warning.
- Assumptions: Cytoscape.js and its layout extensions (`cytoscape-fcose`, `cytoscape-expand-collapse`) load from cdnjs with pinned versions. Context.dev monitor webhooks can be received on a public tunnel during the demo.

## 2. Architecture and DB choice
- **Library: Cytoscape.js.** Chosen over Sigma (WebGL, built for tens of thousands of nodes and has weak per-edge styling) and React Flow (good for custom node UI, but layout and graph analytics are thin). Cytoscape gives dashed and dotted edge line styles, arrow shapes, compound nodes, `predecessors()` and `successors()` for chain highlighting, and a preset layout we can drive ourselves.
- **Store: Postgres on Aiven** with recursive CTEs. The API returns a ready Cytoscape elements JSON, so the browser does no graph maths beyond layout and styling.
- Components: React shell; Cytoscape canvas; FastAPI with SSE for live updates; agent workers (Gemini function calling); Context.dev SDK and monitor webhooks; Valio mock client.
- Data flow: API computes visible subgraph, then SSE pushes `add`, `update` and `remove` diffs, then Cytoscape applies them with a short fade-in animation.
- ArcadeDB: not used. Its supply-chain features are nice, but a second store costs setup time that the graph UX needs.

## 3. Data model and key queries
- Node: `{id, label, kind: company|unregistered|auditor, registered, tier, risk_level, risk_count, country}`.
- Edge: `{id, source, target, trust: inferred|claimed|agreed|audited, confidence, sources[], created_at, visible_to}`. Direction is `source` (seller) to `target` (buyer).
- Visibility: `v_buyer_edges` view returns edges where the buyer is target, plus upstream edges only if the upstream node has an open risk signal. Other upstream nodes are returned as one aggregate node: `{kind: 'cluster', label: '+14 private', count}`.
- Trust and confidence are columns, not styling. Inferred edges require `confidence` and at least one `sources` URL, enforced by a CHECK constraint.

Queries:
```sql
-- Tier-numbered upstream closure of the hotel (tier = shortest path length)
WITH RECURSIVE up(id, tier, path) AS (
  SELECT e.source, 1, ARRAY[e.target, e.source] FROM supply_edge e WHERE e.target = :hotel
  UNION ALL
  SELECT e.source, up.tier+1, up.path || e.source
  FROM up JOIN supply_edge e ON e.target = up.id
  WHERE up.tier < 4 AND NOT (e.source = ANY(up.path))
) SELECT id, MIN(tier) AS tier FROM up GROUP BY id;

-- Hidden concentration: upstream nodes reached by 2 or more direct suppliers
-- (run the closure per direct supplier, then group on upstream id)
SELECT upstream_id, COUNT(DISTINCT direct_id) AS paths
FROM closure_by_direct GROUP BY upstream_id HAVING COUNT(DISTINCT direct_id) >= 2;
```
- Blast radius: reverse closure from a failed node, returning buyers with depth; highlighted on the graph by the same `successors()` call.
- Alternatives: opted-in suppliers in the same category with a published price range and clean risk.

## 4. Agents (discovery, monitoring, procurement)
- **Discovery.** Input: a company name typed by the judge, or a seed list. Tools: Context.dev enrichment and news search (method names to verify on day 1). Output: new node as `unregistered` and an `inferred` edge with confidence and URLs. Validation: two URLs or one register record. The node animates into the graph as it arrives.
- **Monitoring.** Triggers: Context.dev monitor webhooks on supplier domains (news, recall, insolvency, strike keywords), plus a manual "re-check" button. Output: `risk_signal` rows, which change the node's risk ring live. Each signal stores its URL and a snapshot hash.
- **Procurement.** Trigger: a high risk signal on an upstream node the hotel depends on. Gates: alternative is opted in; price is published; order passes a human approval step; only then the Valio mock order call. Each gate writes an audit row shown in the timeline.

## 5. Risk engine
- **Geopolitical:** country and region table with cited sources, plus news keywords. Adds a country ring to nodes.
- **Regulatory:** sanctions name match (OpenSanctions, EU sanctions list), certificate expiry from Valio catalogue attributes, CSDDD flag from supplier declaration. EUDR is not applied to dairy.
- **Concentration:** single-source and shared-upstream queries above. Shown as an amber chip on the upstream node.
- **Financial health:** enrichment changes (headcount, insolvency news). Assumption: Context.dev exposes these fields.
- **Live events:** monitor webhooks on news and recall terms. Red pulse on the node for 10 seconds.
- **Price premium:** published prices only, shown as a label on alternatives.
- Scoring: severity is max of critical signals, else a weighted sum mapped to `low|medium|high|critical`. Risk level drives node ring colour and a numeric halo size.

## 6. Screens and graph view
- **Encoding (the core of the UX):**
  - Direction: left-to-right. Upstream tiers sit left, the hotel sits far right, arrowheads point to the buyer.
  - Tier: fixed x-column per tier from a preset layout, so the depth is readable without a legend.
  - Trust: edge style. `inferred` dashed, opacity from confidence; `claimed` thin grey; `agreed` solid blue, medium width; `audited` thick navy with a small "A" label.
  - Risk: node ring colour (amber high, red critical), plus a pulse on new signals.
  - Registered vs unregistered: rounded rectangle vs dashed-border ellipse.
  - Clusters: collapsed private upstream as a stacked grey card with count.
- **Interactions:** click a node to highlight its upstream with `predecessors()` and dim everything else; click an edge to see confidence and source URLs; "replay growth" slider filters by `created_at`; risk-only toggle hides nodes with no signal; expand-collapse on clusters.
- **Screens:** (1) Home: chain stats and the graph. (2) Graph drawer: node details, signals, sources. (3) Alternatives: cards, same graph in mini view. (4) Approval: proposal with evidence and a graph highlight of the switch. (5) Audit timeline. (6) Supplier and auditor stamps: confirm edge and audit stamp buttons update the edge live.

## 7. Demo script (timed beats)
- **0:00–0:20** Hotel login. Graph appears with a fade-in. Narrate direction and tiers.
- **0:20–0:50** Click the dairy node. Chain highlights. Edge tooltip shows `inferred` 0.82 with two URLs.
- **0:50–1:20** Risk alert: red ring on an upstream dairy producer, with a DEMO list entry and a source link. Replay slider shows its edge appearing.
- **1:20–1:50** Live beat: judge types a new company name. Discovery enriches it, the node drops in live, with URLs.
- **1:50–2:20** Supplier confirms an edge: dashed to solid blue. Auditor stamps it: thick navy with "A".
- **2:20–3:00** Procurement: alternative cards, approval screen with the switch highlighted on the graph, approve, Valio mock order ID.
- **3:00–3:30** Exception: partial availability. Substitute rejected, shown as a red-dashed edge. Audit timeline.
- **3:30–4:00** Close: privacy point (private clusters) and production path.

## 9. Judging-criteria mapping
- **Valio (30%):** approval-gated order through the mock API; audit timeline; partial-availability substitute shown on the graph.
- **Feasibility (25%):** one store, one canvas library, preset layout (no slow force simulation on stage). Hand-crafted seed guarantees the story.
- **Context.dev (15%):** discovery and monitor webhooks feed the graph live, with URLs on screen.
- **Trust and privacy (10%):** trust is a visible edge channel; private upstream is clustered, not shown; buyers see risk warnings and opted-in alternatives only.
- **Concreteness (10%):** schema, SQL, encoding table.
- **Side bounties (10%):** Gemini, Aiven, Codex, CRACI. Cala skipped.

## 10. Risks and cuts
- Cut order: replay slider, force layout toggle, cluster expand, ArcadeDB (already out), Codex logging.
- Risks: Cytoscape with more than about 300 elements on stage can lag (mitigate by capping the demo graph at about 150 visible nodes); edge overlap on busy tiers (mitigate with preset ordering and manual y offsets); live webhook reachability (fallback: scripted replay of recorded webhook payloads, labelled as recorded); CDN version drift (pin versions).

## 11. Biggest weakness of this proposal
The graph is only as persuasive as the seed. If the hand-crafted supply map looks sparse or the tiers are shallow, the visuals undersell the network, and the judges may judge the picture rather than the data behind it. The Valio mock data is also flat, so the tier-by-tier story depends on our own seed rather than the sponsor's data.

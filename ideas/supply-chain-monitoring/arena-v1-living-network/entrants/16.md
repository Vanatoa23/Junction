# Entrant 16: Tracewell (lens: Explainability and audit trail)

## 0. Bold bet
Every action in the network, whether by a human, an agent or the system, is stored as a "why card": one plain-English reason, the exact evidence it rests on (URL, retrieval time, excerpt, content hash), the rule that fired, and who approved it. The audit trail is the main screen, and judges can verify its integrity live, which no other entrant is likely to show.

## 1. Summary and name
- **Tracewell**: a living supplier graph centred on Valio Aimo where every edge, risk and order carries its own justification and a tamper-evident history.
- Persona: a fictional hotel group ("Hotel Lumi Group") buying through Valio. It sees its supply map, a risk alert on a dairy upstream co-op (seeded dummy plus one live-scanned real source), opt-in alternatives with price bands, a procurement proposal, a manager approval, a mock Valio order, and a Trail showing every step.
- Assumption: dummy companies use fictional names; real companies appear only where they were scraped live.

## 2. Architecture and DB choice
- **Postgres on Aiven** is the single source of truth (graph as edge table with recursive CTEs, plus events, decisions, auth). Reason: four engineers, 48 hours, one engine to debug, and Aiven is a side bounty.
- **ArcadeDB: not on the critical path.** Optional read-only Cypher mirror only if Saturday night is green. Plain Postgres handles demo scale.
- Components: React web app; TypeScript API and agent worker in one repo, deployed to Aiven Runtime (assumption: Runtime runs a container); Context.dev webhook endpoint; Gemini client; Valio mock client.
- **Core rule: no state change without an event_log row in the same transaction.** Agent flow: tool call → evidence row → claim JSON → validator → graph/risk/decision write plus event row → UI.

## 3. Data model and key queries
Tables:
- `company(id, name, country, industry, status[unregistered|registered], invited_at, source_url)`
- `edge(id, src_id, dst_id, category, trust[inferred|claimed|agreed|audited], confidence, created_run_id)`
- `edge_evidence(id, edge_id, kind[web|news|partner|declaration|confirmation|audit_stamp], url, excerpt, retrieved_at, sha256)`
- `risk_signal(id, company_id, type, severity 1-5, score, why, evidence_ids[], run_id, status)`
- `score_factor(risk_id, factor, weight, value, confidence, age_days, contribution)`
- `visibility(company_id, opted_in bool)`; `price_publication(company_id, sku, min, max, currency, published_at)`
- `decision(id, trigger_risk_id, run_id, option jsonb, rejected jsonb, status[pending|approved|rejected|ordered], approver, approved_at)`
- `event_log(seq, ts, actor_type[human|agent|system|auditor], actor_id, verb, subject_type, subject_id, why, evidence_ids[], prev_hash, hash)`, where `hash = sha256(prev_hash || canonical_json(row))`.

Trust is derived, not free-set: `agreed` requires two confirm events in event_log (one per side); `audited` requires an audit_stamp event; `inferred` confidence follows our rule: 1 source = 0.4, 2 independent = 0.7, 3+ = 0.85.

Enforcement:
- `visible_graph(viewer)` is the only function that returns edges to the API. It returns the viewer's own map, risk warnings on upstream nodes and nothing else. A unit test asserts no private edge leaks.
- Alternatives query filters `opted_in` and published prices only.
- Industry aggregates are returned only when n >= 5, and the UI shows "suppressed (n<5)" otherwise.

Queries (Postgres):
- Upstream traversal (depth ≤ 4, cycle-safe):
  `WITH RECURSIVE up AS (SELECT src_id, dst_id, 1 d, ARRAY[dst_id] p FROM edge WHERE dst_id=$valio UNION ALL SELECT e.src_id, e.dst_id, up.d+1, up.p||e.src_id FROM edge e JOIN up ON e.dst_id=up.src_id WHERE up.d<4 AND NOT e.src_id=ANY(up.p)) SELECT * FROM up;`
- Hidden concentration: upstream nodes with `COUNT(DISTINCT e1.src_id) >= 2` where `e1.dst_id=$buyer` and `e2.dst_id=e1.src_id`, grouped by `e2.src_id`.
- Blast radius: downward recursion from `$failed` (`src_id=cur.dst_id`), returning distinct buyers reached and the path for each.
- Alternatives: `company JOIN visibility(opted_in) JOIN price_publication WHERE category=$cat AND trust IN ('agreed','audited') ORDER BY max_price LIMIT 5`.

## 4. Agents (discovery, monitoring, procurement)
Shared contract: each run has a `run_id` and writes inputs, tool calls, rejected claims and reasons to the Trail. Gemini must return JSON claims that cite only evidence IDs we supplied. The validator rejects any claim with an unknown ID.
- **Discovery.** Input: Valio supplier list (mock API) and seed categories (dairy, eggs, coffee, cocoa). Tools: Context.dev company enrichment and news search, with Exa as fallback. Output: `inferred` edges and unregistered companies with invitations. Validation: at least one URL, confidence rule above. No human gate for inferred edges, which are clearly labelled. Example why: "Nordic Dairy Co-op listed as Valio milk supplier in 2 sources: [url1] [url2]."
- **Monitoring.** Context.dev monitors on supplier domains and risk keywords, with a webhook to `/hooks/ctx`. Fallback: a scheduled 15-minute poll. Output: `risk_signal` rows with `score_factor`s. "Scan now" button runs live calls against three pre-chosen supplier domains and shows new evidence with timestamps.
- **Procurement.** Trigger: severity >= 3, or a price premium above 8% against a published alternative. Tools: alternatives query and Valio product, availability and price (mock). Output: a `decision` with the chosen option and a `rejected` list with reasons (e.g. "B: 5-day lead time; C: certification expired"). Gate: status stays `pending` until a manager clicks Approve. The order call uses the decision ID as its idempotency key. Partial availability creates a substitution decision that needs re-approval.

## 5. Risk engine
Score = min(100, Σ weight × value × confidence × decay(age)), with a 30-day half-life. Each factor is stored in `score_factor`, so the UI can show the arithmetic.
- **Geopolitical:** seeded country-risk index (assumption) × news hits on country keywords (Context.dev news).
- **Regulatory:** EU consolidated sanctions CSV, downloaded once and hashed, fuzzy-matched on name. Expired certificates from the partner dataset. CSDDD and EUDR flag when the category is in {cocoa, soy, palm, beef, coffee, wood} and no deforestation declaration is on file.
- **Concentration:** shared-upstream query above, plus single-source flag when one supplier exceeds 80% of category spend (Valio data).
- **Financial:** Context.dev enrichment (headcount and funding change) plus negative-news keywords (insolvency, layoffs).
- **Live events:** monitor hits on recall, strike and outage keywords.
- **Price premium:** unit price against the lowest opt-in published alternative, only when published.

## 6. Screens and graph view
1. **Map:** arrows show direction, upstream on the left. Edge style encodes trust: dotted = inferred, solid = claimed, thick = agreed, double = audited. Red ring = open risk, amber = concentration. Clicking an edge opens a **Why panel**: evidence links, confidence, confirmers.
2. **Risk alert:** headline, score breakdown bars with the sum visible, evidence links, and a "Why you see this" line citing the visibility rule.
3. **Alternatives:** opt-in badge, price band, aggregate "used by X% of peers (n=…)" or "suppressed (n<5)". A hidden-supplier note reads "not shown: not opted in".
4. **Proposal:** options table with rejected options and reasons, Approve and Reject buttons, and the approver recorded.
5. **Trail:** chronological log, filterable by actor type. Each row shows time, actor, verb, the why sentence and evidence chips. Buttons: "Verify chain" (shows a checkmark and hash prefix) and "Export JSON".
6. **Confirm and stamp:** supplier view lists claimed edges to confirm; auditor view stamps edges.

## 7. Demo script (about 4 min)
- 0:00–0:25: Hotel login, map. "Every edge says how we know it."
- 0:25–0:55: Click an inferred edge (two URLs, confidence 0.7), then a claimed edge.
- 0:55–1:30: Press "Scan now". Real Context.dev pulls appear with timestamps; a new inferred company is added. Cached last-good result is ready if the call stalls.
- 1:30–2:05: Risk alert with score breakdown. Concentration shows three suppliers sharing one upstream co-op.
- 2:05–2:40: Three opt-in alternatives with price bands. A non-opted-in supplier is hidden with its "not shown" note.
- 2:40–3:20: Procurement proposal with rejected options. Manager approves. Mock Valio order ID returns.
- 3:20–3:45: Exception. Partial availability triggers a substitution that needs re-approval.
- 3:45–4:10: Trail. Click "Verify chain" (passes), then "Tamper" on one row, then verify again (fails, naming the row).
- 4:10–4:25: Supplier confirms (claimed to agreed); auditor stamps (audited). Both appear in the Trail.

## 9. Judging-criteria mapping
- **Valio end-to-end (30%):** a real order goes through the mock API after a gated approval.
- **Buyer need (20%):** risk alert, opt-in alternatives, price bands.
- **Autonomy and controls (20%):** strongest area. Every decision has a why, an approver, rejected options and a verifiable chain.
- **Exceptions (15%):** partial-availability substitution is visible in the Trail.
- **Open standards (15%):** decision records as JSON Schema, SHA-256 hash chain, JSON export (assumption: judges value a standard export).
- **Context.dev (15%):** monitors and webhooks, enrichment, news, with latency and `retrieved_at` shown per call.
- **Feasibility (25%):** one database and one engine.
- **Privacy (10%):** single visibility function, n >= 5 aggregates.
- **Side bounties:** Gemini (validator and classifier), Aiven (Postgres and Runtime), CRACI (CI on the repo producing an SBOM). Codex only if genuinely used in development.

## 10. Risks and cuts
- Cut order: (1) ArcadeDB mirror, never started; (2) audit stamp becomes a single button; (3) webhooks drop to scheduled polling; (4) map library becomes a static Cytoscape layout; (5) Gemini claims fall back to rule-based output.
- Biggest technical risks: Context.dev latency or quota during the demo (mitigation: cached last-good result, labelled with its timestamp); malformed LLM JSON (mitigation: schema validation and rule fallback); explainability overhead costs about 20% of build time.

## 11. Biggest weakness of this proposal
The why-cards are only as good as the evidence behind them. If the live scan returns little, the Trail looks thin and the headline feature underdelivers. We also spend effort on audit surfaces that judges may read as polish, so if the order flow is shaky we lose the 30% end-to-end criterion.

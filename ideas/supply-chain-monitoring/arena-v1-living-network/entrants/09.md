# Entrant 09: Lattice, Standards-First Supply Network (lens: open standards)

## 0. Bold bet
Every party, product, order and claim is stored in the shape a real GS1, UN/CEFACT, Peppol or schema.org consumer expects, so the "credible path to production" is visible in the data itself, not on a slide. Judges weighting open standards and auditability at 15% plus 20% will see a UBL 2.1 order with GLN/GTIN identifiers, a hash-chained audit log and JSON-LD evidence, which no bespoke-JSON entrant can match.

## 1. Summary and name
- **Lattice**: a living supply network where each company is keyed by GLN, each product by GTIN, each edge carries trust, confidence and PROV-style source links, and every agent action is an auditable event.
- Demo: Nordic Harbour Hotels (fictional) buys through Valio Aimo. Alternatives appear only from opted-in sellers with published prices.
- Assumptions: Valio's synthetic catalogue includes GTINs and a seed GLN per supplier. Web discovery never invents a GLN.

## 2. Architecture and DB choice
- **Postgres on Aiven** is primary. Recursive CTEs handle 5-hop traversal at demo scale (under 10k nodes), JSONB holds UBL and JSON-LD documents, and Row-Level Security enforces visibility. Aiven hosting also earns its side bounty.
- **ArcadeDB: stretch only.** Its blast-radius Cypher can run as a read-only side panel if M3 finishes early. A hybrid is rejected because two stores double failure modes in 48h.
- Components: Next.js UI (Cytoscape.js graph) to FastAPI to Postgres. An agent worker (Python) calls Gemini with JSON-schema output, Context.dev (extract, news, monitors, webhooks) and the Valio mock client. Exa is optional.
- Flow: Context.dev monitor webhook, then `risk_signal`, then risk engine, then alert, then procurement agent drafts UBL Order, then human approval, then POST to Valio mock, then OrderResponse stored, all as `audit_event` rows.

## 3. Data model and key queries
- `party(id, gln char13 unique null, name, country iso3166, vat_id, status{unregistered,invited,registered}, jsonld)`: schema.org Organization, with `identifier` as PropertyValue `propertyID="GLN"`.
- `product(gtin char14 pk, gpc_brick, hs_code, jsonld)`: schema.org Product. GS1 GPC brick groups alternatives.
- `edge(id, seller_id, buyer_id, gtin null, trust{inferred,claimed,agreed,audited}, confidence, visibility{private,buyer_risk,aggregate,public})`.
- `edge_confirmation(edge_id, party_id, role{seller,buyer,auditor}, at, evidence)`. Trust is derived by trigger from confirmations, never set by hand: one side is `claimed`, both is `agreed`, auditor row is `audited`.
- `evidence(id, edge_id|party_id, source_url, retrieved_at, excerpt, prov jsonb)`: PROV-O entity, activity (agent run), agent.
- `price_publication(gtin, seller_id, unit_code UN/ECE Rec 20 e.g. C62, KGM, LTR, price_min, price_max, currency iso4217, published bool)`.
- `risk_signal(party_id, type, severity, confidence, score, source_url, status)`.
- `order_draft(id, buyer_id, seller_id, ubl_xml, payload_hash, status{draft,pending_approval,approved,placed,rejected}, approver_id)`.
- `audit_event(id, ts, actor, verb, object_ref, payload, prev_hash, hash)`: EPCIS-inspired what/when/where/why, hash-chained.
- Visibility is enforced by RLS plus a `visible_edges(viewer)` view. Buyers see their own edges, risk signals on upstream parties, and aggregates. Alternatives need `party.opt_in_visible`. Prices need `price_publication.published`.

Upstream traversal:
```sql
WITH RECURSIVE up AS (
 SELECT seller_id, buyer_id, 1 depth, ARRAY[buyer_id, seller_id] path, seller_id first_hop
 FROM edge WHERE buyer_id = $buyer
 UNION ALL
 SELECT e.seller_id, e.buyer_id, up.depth+1, up.path || e.seller_id, up.first_hop
 FROM edge e JOIN up ON e.buyer_id = up.seller_id
 WHERE up.depth < 5 AND NOT e.seller_id = ANY(up.path))
SELECT ...
```
- **Hidden concentration:** `GROUP BY seller_id HAVING count(DISTINCT first_hop) >= 2` over `up`.
- **Blast radius:** recursive downstream from the failing party, joined to order volume.
- **Alternatives:** same `gpc_brick`, joined to `price_publication` where published, filtered to opted-in sellers, `ORDER BY price_min LIMIT 5`.

## 4. Agents (discovery, monitoring, procurement)
- **Common:** Gemini structured output validated against a JSON schema, with one retry. Every row carries `source_url`, `retrieved_at` and `confidence`. Below 0.6 is stored as a candidate, not an edge.
- **Discovery.** Inputs: seed list, Context.dev company enrichment, news search, and structured extraction of supplier pages. It parses schema.org JSON-LD where present. Output: unregistered party plus `inferred` edge with confidence and URL. Validation: GS1 mod-10 check digit on any GLN or GTIN. GEPIR lookup is assumed unavailable for the demo.
- **Monitoring.** Context.dev monitors on supplier domains and news queries fire webhooks. Gemini classifies each change into a risk type. Sanctions are matched against a snapshot of the EU consolidated list and OFAC SDN, using normalised name plus country (assumption: offline snapshot). Output: `risk_signal` with URL.
- **Procurement.** Inputs: risk signal, alternatives from `price_publication`, Valio mock catalogue and stock. Output: UBL 2.1 Order with Peppol BIS Order customisation ID (to verify before demo), units from UN/ECE Rec 20, and currency from ISO 4217. Schema and required-field checks run before save. Partial availability splits lines or substitutes within the same GPC brick. Approval gate: POST only when an approval row exists whose `payload_hash` matches the sent payload. Assumption: the Valio mock accepts a JSON envelope around the UBL; the response is stored as UBL OrderResponse.

## 5. Risk engine
- Score = severity x confidence x recency decay x exposure, where exposure is the buyer's spend share via that party from order history. Upstream risk propagates with 0.5 damping per hop.
- **Geopolitical:** hand-set country index (assumption) plus regional news from Context.dev.
- **Regulatory:** sanctions match scores 100 after normalisation. Certificate expiry comes from supplier JSON-LD or evidence. EUDR: HS code in scope (palm, soy, cocoa) is flagged for hidden ingredient upstreams. CSDDD is flagged, not scored.
- **Concentration:** share of buyer supply through a shared upstream, when two or more direct suppliers rely on it.
- **Financial:** insolvency, layoffs or restructuring keywords in news, plus headcount delta from enrichment.
- **Live events:** recall feed snapshot (Ruokavirasto, assumption) and strike news.
- **Price premium:** (seller price minus cheapest published alternative) / cheapest, only where published.

## 6. Screens and graph view
- **Supply map:** arrows point seller to buyer. Line style encodes trust: dotted `inferred`, solid `claimed`, double `agreed`, thick with badge `audited`. Edge label shows confidence %. Node colour encodes risk (grey, amber, red). Dashed outline marks `unregistered`.
- **Risk inbox:** cards with score, "why" text and source-URL chips.
- **Alternatives:** opted-in suppliers with price range, unit, lead time and certificates, plus "Propose switch".
- **Approval:** UBL preview, diff against current order, payload hash, approve or reject.
- **Audit timeline:** hash-chain status and every agent step.
- **Supplier portal** (confirm edge) and **auditor console** (stamp audited).
- **Discovery run log** with live source URLs.

## 7. Demo script (4 min)
- **0:00–0:20** Pitch: GLN/GTIN network, standards in and out.
- **0:20–0:50** Hotel login, supply map, trust legend, click an edge to show evidence URLs.
- **0:50–1:20** Live discovery: Context.dev pulls a real dairy supplier page, JSON-LD parsed, new `inferred` node appears with URL and confidence.
- **1:20–1:45** Supplier confirms in second window: `claimed` to `agreed` live.
- **1:45–2:15** Risk alert from monitor webhook (staged replay as fallback) with concentration warning on shared upstream.
- **2:15–2:45** Alternatives: opted-in only, published price ranges. A private supplier is absent.
- **2:45–3:20** Agent drafts UBL order, diff, manager approves, hash check, POST to Valio mock, substitution for partial stock.
- **3:20–3:40** Auditor stamps `audited`, audit timeline shows the hash chain.
- **3:40–4:00** Blast-radius query, then the production path.

## 9. Judging-criteria mapping
- **Valio (30% demo, 20% need, 20% controls, 15% exceptions, 15% standards):** full chain; alternatives with published prices; approval hash, hash-chained audit and EPCIS-style events; partial-stock substitution within GPC brick; GLN, GTIN, UBL 2.1, UN/ECE Rec 20, ISO 3166 and 4217, schema.org, PROV-O.
- **Context.dev (15%):** live discovery, monitors with webhooks, news with source URLs.
- **Trust and privacy (10%):** enforced in the database, not the UI.
- **Concreteness (10%):** SQL, schemas, timed script.
- **Side bounties:** Gemini (agents), Aiven (Postgres), CRACI (CI), Codex (if meaningful). Cala skipped: no founder angle.

## 10. Risks and cuts
- **Cut order:** ArcadeDB, Exa, Cala, live webhook (use replay), Oxylabs, Modal. Keep UBL generation, validation and the hash chain; they are cheap and carry the judging weight.
- **Risks:** Valio mock may not accept UBL (JSON envelope fallback). GEPIR not available (no web-derived GLNs). Monitor latency (replay). Gemini schema drift (validate and retry). Sanctions snapshot size.

## 11. Biggest weakness of this proposal
Standards mapping (UBL, JSON-LD, check digits, PROV) costs roughly a day of the 48h. If the demo does not visibly move, judges may read it as paperwork rather than fit. The Valio mock API shape is also an unverified assumption.

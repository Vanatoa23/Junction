# Entrant 17: Upstream (lens: hidden concentration)

## 0. Bold bet
Three suppliers that look diversified often converge on one upstream producer, so the headline screen is "3 dairy suppliers, effectively 1 source." Every other feature (agents, alternatives, approvals) exists to find, prove and fix that hidden hub.

## 1. Summary and name
- **Upstream**: a supply-chain network where buyers see the independent sources behind their suppliers, not just direct vendors. Shared upstream producers are found by graph traversal, evidenced with URLs, and turned into an approved, diversity-aware switch through Valio Aimo.
- Demo: the hotel sees 3 dairy suppliers sourcing from synthetic hub "Maitohuone Oy"; a live discovery run adds a link with URLs; alternatives must be upstream-disjoint; the procurement agent proposes a switch; a manager approves; Valio mock API places the order; all steps are audited.

## 2. Architecture and DB choice
- **Postgres (Aiven managed) as primary store.** Demo graph is under ~500 nodes; recursive CTEs cover 4-tier upstream traversal easily. Fewer moving parts than ArcadeDB for 4 engineers in 48h.
- **ArcadeDB: optional Cypher mirror, cut line Saturday 18:00.** Only if the hub query already works in SQL.
- Components: FastAPI + in-process scheduler; React + Cytoscape.js; Gemini function calling; Context.dev SDK; Exa (optional); Valio mock client; hash-chained `audit_event` table.
- Assumption (verify Friday): Context.dev extraction accepts a JSON schema and returns source URL. Fallback: raw scrape plus Gemini extraction with cited quote.

## 3. Data model and key queries
- `company(id, name, country, kind [registered|unregistered|inferred], domain, sanctions_status, cert_expiry)`
- `edge(id, src_id, dst_id, category, trust [inferred|claimed|agreed|audited], confidence, visibility [private|risk_only|public])`. `src` is the supplier, `dst` the buyer.
- `evidence(id, edge_id|company_id, url, retrieved_at, quote, run_id)`
- `price_point(company_id, sku, price, published)`; `alt_optin(company_id, category, visible)`
- `risk_signal(id, company_id, type, score, confidence, path_json, status)`
- `order_proposal(id, buyer_id, sku, qty, from_id, to_id, price, reason, status [proposed|approved|rejected|placed], approved_by, valio_order_id)`
- `audit_event(id, ts, actor, action, payload, prev_hash, hash)`

**Visibility.** The API never returns another company's edges. A buyer gets its own edges, derived `risk_signal` rows, aggregates, and opted-in alternatives. A hub name appears only if the hub edge is `public` (inferred from public sources) or agreed by the supplier. Path trust = weakest edge; path confidence = min edge confidence.

**Upstream traversal (4 tiers)**
```sql
WITH RECURSIVE up(src, node, depth, path) AS (
  SELECT e.src_id, e.src_id, 1, ARRAY[e.dst_id, e.src_id]
  FROM edge e WHERE e.dst_id = $buyer
  UNION ALL
  SELECT up.src, e.src_id, up.depth+1, up.path || e.src_id
  FROM up JOIN edge e ON e.dst_id = up.node
  WHERE up.depth < 4 AND NOT e.src_id = ANY(up.path)
)
SELECT node AS hub, count(DISTINCT src) AS n_direct, array_agg(DISTINCT src) AS via
FROM up WHERE depth >= 2 GROUP BY node HAVING count(DISTINCT src) >= 2;
```
- **Concentration score** = `(n_direct - 1) / (direct_in_category - 1) * trust_factor`, trust factor inferred 0.6, claimed 0.8, agreed/audited 1.0.
- **Blast radius**: reverse traversal from hub, summing buyer spend (or SKU count) per path.
- **Alternatives**: category match, opted in, published price, no path to hub.

## 4. Agents
- **Discovery** (Gemini + Context.dev extract + Exa news). Input: supplier domains and seed pages (sourcing, certifications, press). Output schema per page: `{upstream_sources: [{name, domain, product, quote, url}]}`. Writes `company(kind=inferred)`, `edge(trust=inferred)` and `evidence`. Confidence starts at 0.5, +0.2 if the quote names the category, +0.2 if two independent pages agree, capped at 0.9. Rejects items without URL and quote.
- **Monitoring** (Context.dev monitors and webhook). Watches sourcing and certificate pages; on change, re-extracts that page, diffs it, and writes `risk_signal`.
- **Procurement** (Gemini tool-use over Valio). Tools: `valio.catalog.search`, `valio.price`, `valio.availability`, `hub_check(alt, hub)`. Output: `order_proposal` with reason and evidence URLs. Guardrail: the order endpoint refuses unless `status=approved` and an approver id is set. The agent has no direct order rights. Partial availability falls through to the next upstream-disjoint alternative.

## 5. Risk engine
Deterministic scores; the LLM writes summaries but never sets scores.
- **Concentration (hero)**: hub query, signal at score ≥ 0.4. Source: Context.dev pages plus seeded partner data.
- **Regulatory**: seeded sanctions CSV (public list, normalized name match); CSDDD/EUDR flags from certificate fields with expiry. Source: seed plus Context.dev cert pages.
- **Geopolitical, financial, live events**: static country table (assumption) plus Exa news with date filter (conflict, layoffs, insolvency, recall, strike), shown with URL.
- **Price premium**: only when both sides publish; flag above 10% over cheapest upstream-disjoint alternative.
- Every signal stores `path_json`, confidence and evidence URLs.

## 6. Screens and graph view
- **Buyer login**: banner "3 dairy suppliers, effectively 1 source."
- **Supply map**: Cytoscape, centred on buyer. Arrow = supply flow. Colour = trust (inferred dashed grey, claimed amber, agreed solid blue, audited solid green). Width = confidence. Red border = open signal. Hub pulses with a "3 paths" badge.
- **Risk detail**: hub, paths, evidence URLs, blast radius, score breakdown.
- **Alternatives**: cards with price range (published only), opt-in badge, "independent of hub" check.
- **Procurement inbox** (Approve/Reject) and **audit log** (hash check). **Supplier view**: confirm edge and opt-in toggle.

## 7. Demo script (about 4 min)
- 0:00 (20s): "Three suppliers. Three brands. One upstream dairy." Graph on screen.
- 0:20 (40s): Hotel login; banner; click hub; paths and evidence.
- 1:00 (50s): Live run: "Discover now" scrapes a real supplier sourcing page via Context.dev; new upstream link appears dashed with URL and quote; score updates in ~20s.
- 1:50 (30s): Pre-staged page change fires the webhook; certificate-missing signal appears.
- 2:20 (40s): Two opted-in, upstream-disjoint alternatives with price ranges; a third alternative is auto-rejected for sharing the hub.

## 9. Judging-criteria mapping
- **Valio (30/20/20/15/15)**: end-to-end mock order; hidden-concentration switch meets buyer need; approval gate, no agent order rights, hash-chained audit; partial-availability fallback; JSON Schema and OpenAPI.
- **Context.dev (15%)**: scrape and extraction in the core flow; monitor and webhook for real-timeness; latency on screen; URLs on every inferred fact.
- **Feasibility (25%)**: one database, one LLM, one graph view.
- **Trust and privacy (10%)**: per-edge visibility; hub names gated by public or agreed trust.
- **Side bounties**: Gemini (main LLM), Aiven (DB and hosting), CRACI (CI and SBOM), Codex (only if genuinely used in dev; assumption). Cala skipped.

## 10. Risks and cuts
- **Cut order**: ArcadeDB, Exa, geopolitical table, supplier mobile view, Oxylabs, Modal/Verda, Cala.
- **Technical risks**: extraction accuracy (pre-tested pages, quoted schema, raw-scrape fallback); stage network failure (pre-run snapshot, backup video); webhook latency (manual trigger to same handler).
- **Data and privacy risk**: hubs under 0.5 confidence stay in the ops view only. Supplier-to-upstream links may need consent; demo uses opt-in suppliers.

## 11. Biggest weakness of this proposal (be honest)
The best moment depends on inferring real upstream links from sparse web pages, so the demo partly leans on seeded hub data. Judges may notice. A weak hub inference driving a costly switch is the worst failure, and confidence gating only partly contains it.

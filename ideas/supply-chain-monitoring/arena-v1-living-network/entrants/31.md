# Entrant 31: Tracelink (lens: no agent framework, plain loops and state machines)

## 0. Bold bet
We ship no agent framework: each agent is a plain tool-calling loop of about 60 lines around the Gemini SDK, and every business object (edge, risk, proposal, job) is a row that moves only through a named transition table. This makes the agents debuggable at 3 a.m. on Saturday, and it turns the audit trail into the demo, because every agent step is already a transition the judges can replay.

## 1. Summary and name
- **Tracelink**: a hotel buyer sees the suppliers behind its suppliers, gets warned before a shortage, and approves a switch that a Valio order then executes.
- Demo persona: "Pohjan Hotellit" (dummy hotel chain) buying dairy through Valio Aimo.
- Why frameworks lose here: LangGraph, CrewAI and similar add a dependency tree, a second state model and version churn, and none of them removes a single hour of schema, UI or mock-API work. Our loop is ours to debug.

## 2. Architecture and DB choice
- **Database: Postgres on Aiven** (single store). Recursive CTEs cover multi-tier traversal. `pgvector` covers alternative search (assumption: available on Aiven Postgres; verify Friday). ArcadeDB is rejected for the build: a second engine and a second query language cost days we do not have. It stays as the production-path slide.
- **Stack**: one TypeScript repo. Node worker and Express API share the same zod schemas. React + Cytoscape.js frontend. Gemini called through its official SDK.
- **Components**:
  - API: reads go through a projection function (section 3); writes go through transition functions only.
  - Worker: one process with three cron-style timers (discovery on demand, monitor every 60s, procurement on new signals). Jobs are rows in `job`, claimed with `SELECT ... FOR UPDATE SKIP LOCKED`.
  - No queue, no Kafka, no Redis. Valkey is unnecessary at this scale.
- **Tool loop** (`runAgent(system, tools, input, maxSteps=6)`): call model, if it returns a function call, validate args with zod, run the tool, append result, repeat. Each step writes one `agent_step` row. Output is accepted only if it matches the agent's zod output schema; otherwise one retry, then the job fails visibly.

## 3. Data model and key queries
- **Tables**: `company(id, name, country, nace, registered, opted_in_alt, is_dummy)`, `product(id, company_id, sku, category, published_price_min, published_price_max)`, `edge(id, from_id, to_id, product_id, state, confidence, sources jsonb)`, `edge_event(id, edge_id, event, actor, at, prev_state, next_state)`, `risk(id, company_id, kind, severity, confidence, source_url, state)`, `proposal(id, buyer_id, state, payload jsonb)`, `proposal_event`, `job(id, kind, state, input, output)`, `agent_step`, `audit(id, at, actor, action, ref, payload, prev_hash, hash)`.
- **Trust as a state machine**, not a column you set:
  - `inferred --(agent_suggest)--> inferred` (confidence updates only)
  - `inferred --(buyer_accept)--> claimed`
  - `claimed --(supplier_confirm)--> agreed`
  - `agreed --(auditor_stamp)--> audited`
  - Any other event returns 409 and writes nothing. `agreed` is refused unless both `claimed` and `supplier_confirm` events exist in `edge_event`.
- **Visibility as a projection**: `project(viewer)` is a pure TypeScript function that takes the rows and returns the viewer's view. Rules: own edges in full; upstream nodes as `{id, risk[]}` only; `industry_usage` as aggregates with cohort size of 5 or more; alternatives only where `opted_in_alt`; prices only where `published_*` is set. Unit-tested with 10 cases, because privacy is 10% of the score.
- **Upstream traversal**: `WITH RECURSIVE up AS (SELECT from_id, to_id, 1 AS depth FROM edge WHERE to_id = $buyer_supplier_set UNION ALL SELECT e.from_id, e.to_id, up.depth+1 FROM edge e JOIN up ON e.to_id = up.from_id WHERE up.depth < 4) SELECT * FROM up;`
- **Hidden concentration**: `SELECT from_id, count(DISTINCT to_id) AS direct_hits FROM up JOIN direct_suppliers ON ... GROUP BY from_id HAVING count(DISTINCT to_id) >= 2;`
- **Blast radius**: downstream recursion from the failed node, joined to `product` and the buyer's order lines; returns SKU count and line value.
- **Alternatives**: `SELECT id FROM company WHERE opted_in_alt AND category = $c ORDER BY embedding <=> $ref LIMIT 5`, then keep those with published price bounds.

## 4. Agents (discovery, monitoring, procurement)
Each agent = one loop plus a fixed tool list. All tools are plain functions with zod schemas.
- **Discovery**
  - Input: supplier name or Valio supplier row.
  - Tools: `ctx_company(name)`, `ctx_news(query, since)` (Context.dev REST, called directly; MCP skipped to save setup), `db_upsert_edge_candidate`.
  - Output: candidate edges, each with `confidence` and `sources[]`.
  - Validation: the model must return a verbatim quote from a fetched source; a candidate without a matching quote is dropped in code, not by the model.
  - Human: candidates land as `inferred`; the buyer's "accept" event moves them to `claimed`.
- **Monitoring**
  - Input: all companies with edges into the buyer's upstream set.
  - Tools: `ctx_news(name, since=last_run)`, `db_insert_risk`.
  - Output: risk rows with `kind` from a closed enum (strike, recall, outage, sanction_hit, insolvency, negative_news).
  - Validation: `source_url` required; kind outside enum rejected.
  - Assumption: Context.dev monitor webhooks are a stretch goal; polling is the default.
- **Procurement**
  - Input: one open risk plus buyer's SKUs for that supplier.
  - Tools: `valio_search`, `valio_price`, `valio_availability`, `make_proposal`, read-only only. `valio_order` is absent from the loop's tool list.
  - Output: a `proposal` in state `proposed`.
  - Human: `approve` event moves it to `approved`; only then a separate, non-agent function calls `valio_order`. The agent cannot reach the order function, by construction.
  - Assumed Valio mock shapes (label on slide): `GET /products?q=`, `GET /prices/{sku}`, `GET /availability/{sku}`, `POST /orders` with an idempotency key.

## 5. Risk engine
- **Deterministic first**: concentration (SQL), single-source (count of suppliers per SKU), price premium (buyer price minus cheapest published bound).
- **LLM-classified second**: live events, insolvency and sanctions-keyword hits, using the monitoring loop. The model picks from the enum; code assigns severity from a fixed table.
- **Seeded and labelled**: geopolitical scores and EUDR or CSDDD flags come from a dummy table, marked "seeded" on screen. We do not claim live sanctions screening.
- **Scoring**: severity (1 to 5) times share of buyer spend exposed. Sorted for the inbox.

## 6. Screens and graph view
- **Network**: Cytoscape canvas, buyer at centre, arrows toward buyer for supply. Edge styles encode the state machine (dashed inferred, solid claimed, double agreed, gold-ring audited). Node red ring = open risk. Hovering an inferred edge shows confidence and source URLs.
- **Inbox**: risks sorted by score, each with its source and blast radius.
- **Proposal**: a state rail (proposed, approved, ordered, or substitution-needed), the diff, approve and reject buttons.
- **Ledger**: the append-only audit timeline, with hash-check badge and a "replay" button that re-renders state from events.
- **Partner view**: one page with a role switch (supplier or auditor) for "confirm edge" and "stamp".

## 7. Demo script (timed beats)
- **0:00** Problem in one sentence; a single state diagram of the trust levels.
- **0:25** Log in as Pohjan Hotellit. Network shows 5 direct suppliers, one visible tier.
- **0:55** Press "Scan upstream". The job rail moves queued, running, done. Three new dashed nodes appear, each with source URLs read aloud. This is the live Context.dev run.
- **1:35** Inbox: strike notice on a dairy co-op shared by three direct suppliers. Blast radius: 14 SKUs.
- **2:05** Alternatives: three opted-in suppliers with price bars and a "used by 38% of peers" aggregate. Point out the non-opted-in ones are not shown.
- **2:35** Procurement proposal moves to `proposed`. Approve. Order request posts to Valio mock; confirmation number appears.
- **3:05** Exception: one SKU partially available, so the loop proposes a substitute; it needs its own approval. Approve it.
- **3:35** Partner view: supplier confirms (claimed to agreed); auditor stamps (agreed to audited). Network recolours.
- **3:55** Ledger: show the hash chain and replay the proposal from events. Close.

## 9. Judging-criteria mapping
- **Valio (30 / 20 / 20 / 15 / 15)**: beats 2 to 5 are request, approval, order and substitution. Ledger and approval-by-construction give guardrails and auditability. Substitution covers exceptions. Idempotent orders and plain REST with JSON cover open standards.
- **Context.dev (15%)**: beat 3 live run with URLs; monitoring timer shows real-timeness; quote validation shows sourcing.
- **Trust and privacy (10%)**: trust is a transition table, visibility is a tested projection. Beat 2 and 4 show it.
- **Concreteness (10%)**: schemas, SQL and transition events are the implementation.
- **Side bounties**: Gemini as the only LLM (beat 3), Aiven Postgres (beat 4), Codex used for test generation and logged, CRACI in CI from day one.

## 10. Risks and cuts
- **Cut order**: webhooks, Cala, geopolitical scoring, financial health, Exa, ArcadeDB.
- **Risk: Gemini function-calling shape drifts** between SDK versions. Mitigation: pin SDK version Friday; the loop is 60 lines, so we can patch it ourselves.
- **Risk: Context.dev latency on stage**. Mitigation: the job rail shows progress; cached response from Friday is replayed with a visible "cached at" label if the live call exceeds 8s.
- **Risk: Valio mock shape differs**. Mitigation: adapter file; stub mirrors our assumed shape.
- **Risk: transition table bugs**. Mitigation: 10 unit tests on the trust machine written Friday.

## 11. Biggest weakness of this proposal (be honest)
Hand-rolled loops are less impressive to a judge who expects "agentic" architecture, and we give up the visual agent-graph view that frameworks produce for free. We are also writing the tool loop, validation and retries ourselves, so one subtle bug in it could cost the Saturday night milestone.

# Entrant 14: Degrade Gracefully (lens: robustness to exceptions)

## 0. Bold bet
Most entrants will demo the happy path. We make every failure a visible, approvable object: partial stock, substitutions, missed delivery dates, price drift and API outages each become an exception card with a solver-proposed fix, a human decision and an audit trail. Judges press an "Inject exception" panel, and the order still lands, logged.

## 1. Summary and name
- Name: **Fallback** ("Supply that keeps working when suppliers don't").
- A hotel chain sees its upstream map, gets a recall alert on a dairy producer, and receives a split-order proposal (opted-in alternative plus Valio substitutes). Nothing ships until a manager approves.
- Assumption (labelled): the Valio mock exposes search, availability, quote and order endpoints with `client_reference` and idempotency keys. If not, a shim returns the same shapes.

## 2. Architecture and DB choice
- **Postgres only (Aiven)**: graph, orders, approvals, audit and visibility in one store. Upstream traversal uses `WITH RECURSIVE`, depth capped at 4.
- **ArcadeDB: cut from core**, since it is a second moving part we cannot fall back from. Stretch only: a read-only mirror behind a flag.
- Services: TypeScript API, a worker polling a `job` table for agents, React + Cytoscape.js UI. Gemini for extraction and planning; Context.dev SDK for scrape, news and monitors.
- Containment: every external call goes through `callExternal()`: timeout, retry with jitter, circuit breaker, typed result `ok | degraded | failed`. Degraded data shows a yellow "cached 14:02" badge, never "live".

## 3. Data model and key queries
- `company(id, name, country, kind, opted_in_alt, tenant_id)`
- `edge(id, from_id, to_id, trust[inferred|claimed|agreed|audited], confidence, sources jsonb, confirmed_from, confirmed_to, audited_by)`. Trust is derived from the flags and audit row, never set directly.
- `price_publication(company_id, sku, range_low, range_high, valid_until)`. No row means no visible price.
- `order_proposal(id, status, version, price_lock_expires_at)`, `order_line(proposal_id, sku, supplier_id, qty, unit_price, eta, reason)`.
- `exception(id, proposal_id, type, detail jsonb, status)`; `audit_event(id, ts, actor, action, payload jsonb, prev_hash, hash)`, append-only.
- Visibility is enforced in the query layer: every read takes `viewer_id`. Buyers receive only risk signals, opted-in alternatives, published prices, and industry usage when at least 5 companies are counted.

Key queries:
- Upstream: `WITH RECURSIVE up AS (SELECT from_id, to_id, 1 d FROM edge WHERE to_id=$hotel UNION ALL SELECT e.from_id, e.to_id, up.d+1 FROM edge e JOIN up ON e.to_id=up.from_id WHERE up.d<4) SELECT * FROM up;`
- Hidden concentration: upstream rows grouped by `from_id` with `count(DISTINCT direct_supplier) >= 2`.
- Blast radius: same recursion downstream from a failed supplier, summing hotel `order_line.qty`.
- Alternatives: opted-in companies with a valid published price in the category, ordered by pgvector distance to the SKU embedding (falls back to category match if pgvector is unavailable; assumption).

## 4. Agents (discovery, monitoring, procurement)
- **Discovery**: Context.dev `search` and `extract` return fetched pages; Gemini returns typed `{supplier, product, confidence}`. Validation: a fetched source URL, confidence >= 0.6, domain dedupe. Output: `inferred` edge. On timeout, reuse the seeded snapshot and mark the run `degraded`.
- **Monitoring**: Context.dev monitor webhooks, with a 60-second poll backup. Changes become `risk_signal` rows with severity, URL and fetched_at, deduplicated by content hash.
- **Procurement**: triggered by a risk signal or premium. Tools: `valio.search`, `valio.availability`, `valio.quote`, `valio.order`. Writes an `order_proposal` in `PROPOSED`. Only the approval endpoint can call `valio.order`, with a token bound to the proposal `version`.

**Exception catalogue:**
1. **Partial availability**: Alt A has 40 of 70 units. The solver fills the remaining 30 from Valio's in-stock substitute or a second alternative whose lead time fits. Each line carries a reason.
2. **Substitution**: the substitute's certificate set must be a superset of the original's. Mismatches are blocked, not warned.
3. **Delivery constraint**: delivery by Thursday 08:00. Lines whose ETA misses it are excluded and listed as `excluded: eta 5d > required 2d`.
4. **Price drift**: quotes lock for 10 minutes. A move over 2% resets the proposal to `PROPOSED`, bumps the version and requires re-approval.
5. **API failure during order**: send with `Idempotency-Key = proposal_id:line`. On timeout the line becomes `UNKNOWN`; we query `valio.order_by_reference` before any retry, so duplicates are impossible. Placed lines stay placed; failed lines become a new exception card.
6. **Source or LLM outage**: cached data with the degraded badge; rule-based scoring still runs.
7. **Approval expiry**: unapproved for 30 minutes means re-quote.

## 5. Risk engine
- Rules first, LLM second, so scores run when Gemini is down.
- Geopolitical: country table plus Context.dev news on conflict keywords. Regulatory: bundled EU sanctions snapshot (offline), certificate expiry, CSDDD/EUDR rule table.
- Concentration: single-source count per SKU and the hidden-upstream query. Financial and live events: Context.dev monitor hits, scored by source count and recency. Price premium: only against published ranges.
- Every score stores its inputs and source URLs.

## 6. Screens and graph view
- **Hotel dashboard**: own map (private), risk count, open exception cards.
- **Exception inbox**: detail, proposed fix, Approve / Reject, audit hash.
- **Proposal view**: split and excluded lines with reasons, price-lock countdown.
- **Audit log**: hash-chained events, "verify chain" button.
- **Inject panel** (`DEMO=1`): "stock to 40%", "timeout on order", "Context.dev offline", "price +5%".
- **Graph**: suppliers left, hotel centre, customers right; edge colour by trust; `inferred` thickness by confidence; red border for risk; dashed for unregistered; hatched fill for cached data.

## 7. Demo script (about 4 minutes)
1. (0:00) Hotel login. Map: 14 suppliers, trust levels and source links visible.
2. (0:40) Live discovery pulls a fresh news page through Context.dev; new `inferred` edge shows URL and fetch time.
3. (1:10) Recall alert on the upstream dairy producer; hidden shared upstream appears.
4. (1:40) Judge presses **Stock to 40%**. Split: 40 from Alt A (published range), 30 from Valio substitute (cert check passed), one line excluded for missing Thursday 08:00.
5. (2:20) Judge presses **Timeout on order**. `UNKNOWN`, lookup by reference, retry with same key. Exactly one order.
6. (2:50) Supplier confirms Alt A (`claimed` to `agreed`); auditor stamps Valio edge `audited`.
7. (3:20) Manager approves; order placed. Verify chain passes. Judge presses **Price +5%**: approval resets and re-quotes.
8. (3:45) Close: every failure shown is one production will throw; none stopped the order silently.

## 9. Judging-criteria mapping
- Valio end-to-end (30%): search, quote, approval, order and audit all run through the mock API.
- Exceptions and buyer need (15% and 20%): a split, substituted order the hotel actually receives, with seven cataloged cases and visible `UNKNOWN` recovery.
- Autonomy and controls (20%): approval gate, version-bound token, hash-chained log.
- Open standards (15%): idempotency keys, source records with URLs, stated production path.
- Context.dev: live discovery and monitor webhooks in the core flow, with URLs and fetch times on screen.
- Trust and privacy (10%): trust derived from confirmations; buyer queries exclude private maps and unpublished prices.
- Bounties: Gemini, Aiven, CRACI (CI and SBOM); Codex only if used.

## 10. Risks and cuts
- Cut first: ArcadeDB mirror, Cala, Oxylabs, Modal/Verda, embeddings.
- Cut second: exception 7 and verify-chain.
- Biggest risks: Valio mock endpoints differ from assumptions (shim decided Friday night); split-solver edge cases (greedy, fixed priority, not optimisation); Context.dev latency on stage (cached result ready).

## 11. Biggest weakness of this proposal (be honest)
We spend effort on failure paths judges may never trigger, and we drop the ArcadeDB story. A polished happy path could beat a working inject panel, which also depends on Valio's mock being scriptable.

# Entrant 46: Judge-Proof Sandbox (lens: survive judges trying it)

## 0. Bold bet
Judges get a sandbox they cannot break: every visitor works in an isolated, reset-able copy of the seeded network, and every live call sits behind a cache, rate limit and timeout with a visible fallback label. We win because the demo works when a judge types "Nestlé" or "asdf" at 14:00 on Sunday, not only when the presenter follows the script.

## 1. Summary and name
**Tributary Sandbox.** A supply-chain network where the hotel persona, supplier, auditor and Valio ops roles each have a one-click judge login. Anyone can type a company name into a live discovery box; the system returns sourced, `inferred` edges or an honest "no public evidence". Orders go through Valio's mock API only after a manager approves. Every visitor's changes live in a session sandbox that resets with one button.

## 2. Architecture and DB choice
- **One deployable app** on Aiven Runtime: Python FastAPI backend, React + Cytoscape.js frontend, background worker for agents (same repo, two processes).
- **Aiven Postgres** as the only store (Aiven bounty). ArcadeDB cut: adds a Docker service and a query language nobody on the team knows, and Postgres recursive CTEs cover upstream, concentration, blast radius and alternatives.
- **External:** Gemini (extraction, classification, rationale), Context.dev (company enrichment, news search, monitors with webhooks), Valio mock API (catalogue, availability, orders). Exa only as a backup search.
- **No message bus.** Work queue is a Postgres table (`job`) polled by the worker with `SELECT ... FOR UPDATE SKIP LOCKED`. This is less impressive than Kafka but removes a setup risk the judges never see.
- **Degrade ladder:** live -> cached (labelled with age) -> seed-only (labelled "offline mode"). Status bar on every screen shows Gemini, Context.dev and Valio each as live, cached or down.

## 3. Data model and key queries
- **Sandbox isolation:** every user-generated row has `sandbox_id`. Seed rows have `sandbox_id = 'seed'` and are read-only. A session writes only its own rows.
- **Tables:** `company(id, sandbox_id, name, name_norm, country, registered, opted_in)`, `edge(id, sandbox_id, src, dst, trust, confidence, sources jsonb, owner, visibility)`, `lookup_cache(name_norm PK, result jsonb, fetched_at, expires_at)`, `risk_signal`, `proposal(state, ...)`, `approval`, `order(idem_key UNIQUE)`, `job(kind, payload, status, attempts)`.
- **Trust rule:** rank only increases (`inferred` < `claimed` < `agreed` < `audited`), enforced by a trigger on `edge`. `agreed` needs two confirmations; `audited` needs the auditor role.
- **Visibility:** hotel-facing queries use views `v_my_map`, `v_risk`, `v_peer_usage` (minimum group of 5), `v_alternatives` (opted-in only), and published prices only.
- **Upstream traversal (depth 3):**
```sql
WITH RECURSIVE up AS (
  SELECT src, dst, 1 AS d, ARRAY[dst] AS p FROM edge WHERE dst = $1 AND sandbox_id IN ('seed', $2)
  UNION ALL
  SELECT e.src, e.dst, up.d+1, up.p||e.dst FROM edge e JOIN up ON e.dst = up.src
  WHERE up.d < 3 AND NOT e.dst = ANY(up.p) AND e.sandbox_id IN ('seed', $2))
SELECT * FROM up;
```
- **Hidden concentration:** upstream firms supplying at least two direct suppliers of the buyer (`GROUP BY s2.src HAVING count(DISTINCT s1.src) >= 2`).
- **Blast radius:** same recursion, walking `src -> dst` from the failed node.
- **Alternatives:** same category, `opted_in`, with a `price_publish` row, excluding current suppliers.
- **Reset:** `DELETE FROM <all tables> WHERE sandbox_id = $1`, then the seed is untouched. Target under 300 ms.

## 4. Agents (discovery, monitoring, procurement)
- **Live discovery box (the judge's entry point):** input is trimmed, NFKC-normalised, 2–80 characters, letters/digits/spaces/&/-/. only. Flow:
  1. `name_norm` lookup in `lookup_cache` (24 h TTL). Hit: return immediately, labelled "cached".
  2. Miss: enqueue `job`; worker calls Context.dev company enrichment and news search with an 8 s timeout each.
  3. Gemini extracts `{company, relation, country, quote, url}` with a JSON schema. Prompt states that page text is data, never instructions.
  4. **Verification:** a candidate edge is kept only if its quote appears verbatim in the fetched page and it has at least two URLs. Otherwise "no public evidence" is shown.
  5. Output: `inferred` edges with confidence and URLs, written to the caller's sandbox.
- **Rate limits:** 3 live lookups per session per minute, 20 per hour globally; concurrency 2 for Gemini; queue position shown. Over limit: cached or seed result with a notice, never an error page.
- **Monitoring:** Context.dev monitors on seed companies post to a webhook. Handler is idempotent on the monitor event id. Classifications become `risk_signal` rows.
- **Procurement:** triggered by risk above threshold; asks Valio catalogue for affected SKUs; proposes substitutes from `v_alternatives`. Proposal state machine: `draft -> pending_approval -> approved -> ordered`, or `rejected`. The Order endpoint rejects any state other than `approved`, and the idempotency key is the proposal id, so double clicks do nothing.

## 5. Risk engine
- Per signal `c = severity x confidence x 0.5^(age_days/14)`; company risk `= 1 - prod(1 - c)` per type; buyer exposure `= max(own, 0.5 x upstream)` per hop.
- **Types:** geopolitical (static country index, labelled assumption); regulatory (sanctions name match on a public list, certificate expiry from supplier JSON; CSDDD flag stub; EUDR not applied to dairy); concentration (shared-upstream query); financial and live events (Gemini classification of Context.dev news); price premium (only where prices are published).
- Pre-seeded signals for the dairy producer guarantee the story; live discovery adds to them.

## 6. Screens and graph view
1. **Role login:** four large buttons (Hotel manager, Supplier, Auditor, Valio ops). Each signs into a fresh sandbox. No sign-up, no password to type.
2. **Supply map:** Valio centre, upstream left. Dashed amber `inferred` with confidence, grey `claimed`, dark `agreed`, gold double `audited`. Red or amber border for risk. Grey unregistered nodes marked "invite".
3. **Lookup box (top bar):** "Type any company". Shows result state: cached, live (with timing), or "no public evidence".
4. **Reset sandbox** in the user menu, with confirmation.
5. **Alert, alternatives, proposal and approval, audit timeline:** as in the brief. Timeline items show actor and source URLs.
6. **Status bar:** Gemini, Context.dev, Valio each live, cached or down.

## 7. Demo script (about 4 min)
- 0:00 Presenter signs in as Hotel manager; the judge gets a "Try it" card to use later.
- 0:25 Supply map; dashed `inferred` dairy producer with URLs.
- 0:50 Supplier role confirms the edge (`claimed` to `agreed`); audit line appears.
- 1:15 **Live beat:** presenter types a company with a recent news story. Worker runs; news with URLs appears as risk within about 15 s. Fallback: cached result labelled.
- 1:50 Risk alert propagates to Valio and the hotel; alternatives with price ranges; concentration card.
- 2:30 Proposal, approval, Valio mock order id.
- 3:00 Auditor stamps `audited`. Privacy: peer-usage aggregate only.
- 3:20 **Judge hour:** hand over the keyboard. Judge types a nonsense name ("zzqx"): "no public evidence" in under 2 s. Judge tries Approve twice: one order. Judge hits Reset: the map returns to seed.

**Adversarial pass (M3):** fifty junk inputs (empty, emoji, SQL-looking, 300 chars, prompt-injection text inside a fake news page), double-clicked approvals, rapid lookups, reset during a running job.

## 9. Judging-criteria mapping
- **Valio (30%):** order only after approval; exceptions and rejections visible in audit; idempotent orders.
- **Feasibility and demo reliability (25%):** this lens's core. Degrade ladder, sandboxes and an adversarial pass.
- **Context.dev (15%):** live lookup with timeouts, URLs shown, monitors with webhook handler.
- **Trust and privacy (10%):** trust trigger; visibility views; sandbox isolation.
- **Concreteness (10%):** SQL, state machine, rate-limit numbers.
- **Side bounties (10%):** Gemini (extraction and rationale), Aiven (Postgres and Runtime), CRACI in CI. Skip Cala, Modal, Oxylabs.

## 10. Risks and cuts
- **Cut order:** Exa, Oxylabs, Modal, Cala, price premium, ArcadeDB (never in). Keep sandboxing, verification and the state machine; they are the lens.
- **Technical risks:** Context.dev or Gemini quota exhausted mid-demo (pre-warm cache for demo names; cached label); Aiven Runtime cold start (deploy Friday, keep warm); webhook public URL (tunnel or polling fallback); sandbox table growth (expire sessions after 2 h).

## 11. Biggest weakness of this proposal
It optimises for not breaking, so the wow factor is smaller: the live lookup is capped and cached, and judges may see "cached" more often than they expect. Sandboxing and verification also add schema and worker code that the brief does not reward directly. If the team skips the adversarial pass, the robustness story becomes a claim, not a fact.

# Entrant 55: Overnight Harvest (lens: batch discovery at scale)

## 0. Bold bet
Other entrants will show a graph of twenty hand-picked companies. We run a Saturday-night batch over all ~700 Valio suppliers, two tiers upstream, so Sunday's demo graph has thousands of real, sourced nodes and the concentration and blast-radius numbers are computed from data, not typed in. Judges see a batch-run report, then the live monitor fires on stage.

## 1. Summary and name
- Name: **Harvest** ("the supply graph, grown overnight").
- Hotel chain logs in and sees its Valio-rooted map: about 700 direct suppliers, 2,000 to 4,000 upstream companies, each edge tagged `inferred` with confidence and source URLs. A recall on an upstream dairy producer triggers a risk alert and a procurement proposal that a manager approves before the Valio mock order.
- Assumptions (labelled): Valio's ~700-row supplier master includes name, country and domain where given. Context.dev crawl accepts a URL list and returns markdown with URLs and fetch times. Modal supports `.map()` fan-out and cron. Valio mock exposes search, quote and order.

## 2. Architecture and DB choice
- **Postgres (Aiven) as system of record**, graph included (`edge` table, `WITH RECURSIVE`). At ~4k nodes and ~8k edges, recursive CTEs answer in milliseconds. ArcadeDB is out: a second engine doubles failure modes.
- **Batch plane**: Modal functions write to staging tables, so a failed stage never corrupts the graph.
- **Live plane**: small FastAPI service receives Context.dev monitor webhooks and runs procurement. Same Postgres.
- Gemini (structured JSON with citations) does extraction.
- Local fallback: `--local` asyncio runner (concurrency 20). Modal is an accelerator, not a dependency: about 90 minutes instead of 20.

## 3. Data model and key queries
- `company(id, name, domain, country, kind[registered|unregistered|inferred], opted_in_alt, tenant_id)`
- `edge(id, from_id, to_id, trust[inferred|claimed|agreed|audited], confidence, source_ids[], confirmed_from, confirmed_to, audited_by)`. Trust is derived from flags, never set directly.
- `raw_doc(id, url, sha256, fetched_at, provider)`: every extracted fact points here.
- `batch_item(run_id, supplier_id, stage, status[ok|empty|failed|rejected], attempts, error)`: checkpoints for resume.
- `risk_signal(id, company_id, type, severity, source_id, detected_at)`; `price_publication(company_id, sku, range_low, range_high, valid_until)`.
- Visibility: every query takes `viewer_id`; buyers see risk signals, opted-in alternatives, published prices, and industry usage when at least 5 companies are counted.

Key queries:
- Upstream: `WITH RECURSIVE up AS (SELECT from_id, to_id, 1 d FROM edge WHERE to_id=$hotel_supplier_set UNION ALL SELECT e.from_id, e.to_id, up.d+1 FROM edge e JOIN up ON e.to_id=up.from_id WHERE up.d<4) SELECT DISTINCT from_id FROM up;`
- Hidden concentration: `SELECT from_id, count(DISTINCT to_id) n FROM up GROUP BY from_id HAVING count(DISTINCT to_id) >= 3 ORDER BY n DESC;`. This is the payoff: at scale it finds real shared upstream producers.
- Blast radius: downstream recursion from a failed node, joined to `order_line` for the hotel's exposed volume.
- Alternatives: opted-in companies with a valid published price in the same category, ranked by pgvector distance (fallback: category match; assumption).

## 4. Agents (discovery, monitoring, procurement)
- **Discovery (batch, Saturday 20:00)**, each stage a Modal `.map()` over suppliers:
  1. Resolve: domain from master, else Context.dev company lookup. No match means an `unregistered` node, no invented edges.
  2. Crawl: supplier site (sourcing, certificate pages) plus 12-month news search.
  3. Extract: Gemini returns `{upstream_company, role, country, cert, source_url}`. Reject unless `source_url` is in the crawl result, `confidence >= 0.6`, and the schema validates.
  4. Load: idempotent upsert of `inferred` edges keyed by `(from, to, kind)`.
- Expect about 40% of suppliers with usable public evidence; the rest carry a "no public evidence" tag.
- **Monitoring**: Context.dev monitors on the 50 most-connected upstream nodes; webhooks write `risk_signal`. A Modal cron re-polls every 30 minutes as backup.
- **Procurement**: triggered by a signal or premium. Gemini tool-use over `valio.search`, `valio.availability`, `valio.quote`. Writes `order_proposal` in `PROPOSED`. Only the approval endpoint calls `valio.order`, with a token bound to proposal version and an idempotency key per line.

## 5. Risk engine
- Concentration: computed from the batch graph (count of direct suppliers sharing an upstream).
- Regulatory: sanctions name-match against a bundled EU consolidated-list snapshot; certificate expiry from extracted `cert` facts; CSDDD and EUDR flags from a rule table keyed by commodity (dairy, cocoa, palm).
- Geopolitical: country table plus news hits from the batch on conflict keywords.
- Financial and live events: monitor hits (insolvency, layoff, recall, strike) scored by source count and recency.
- Price premium: only against published ranges.
- Each score stores inputs and source ids, so the UI can explain it.

## 6. Screens and graph view
- **Batch report** (judge-facing): run start and end, suppliers processed, nodes and edges added, share with sources, empty and failed counts, cost. This is the scale proof.
- **Hotel dashboard**: own map, risk count, exception inbox.
- **Proposal view**: lines, reasons, price-lock countdown, approve.
- **Graph view**: 4k nodes is too many, so it opens as a two-hop ego network with progressive expansion. Edge colour by trust, thickness by confidence, red border for risk, dashed for unregistered; click an edge for source URLs and fetch times.

## 7. Demo script (about 4 minutes)
1. (0:00) Show the batch report from Saturday night: 700 suppliers, 3,000+ nodes, 62% of edges with sources.
2. (0:45) Hotel login. Ego network loads; click the dairy producer; two suppliers share it, so concentration shows the real count.
3. (1:30) Live: Context.dev monitor fires a recall on the dairy producer (or a test page replay if the live site is quiet). Risk alert shows URL and fetch time within seconds.
4. (2:10) Procurement proposal: opted-in alternative with a published range plus a Valio substitute. Manager approves.
5. (2:50) Order placed through Valio mock. Audit log shows every step; the source of each edge is one click away.
6. (3:20) Supplier confirms an edge (`claimed` to `agreed`); auditor stamps one `audited`.

## 8. 48h build plan (4 engineers, 4 milestones)
- **Fri night (M1)**: Postgres schema; Valio supplier master loaded; Modal hello-world `.map()` over 700 rows; Context.dev call wrapper.
- **Sat (M2)**: resolve, crawl and extract stages working on 20 suppliers end to end; loader with idempotent upserts; `batch_item` checkpoints. Launch the full run at 20:00.
- **Sat night (M3)**: overnight run (engineer on call to restart failed items); meanwhile build monitor webhook, procurement agent, approval endpoint, UI shell and ego-network view on the partial graph.
- **Sun morning (M4)**: re-run failed items only (under 30 minutes); freeze graph snapshot at 09:00; two dry runs; backup video at 10:00; code freeze at 11:00.

## 9. Judging-criteria mapping
- Context.dev (15%): batch crawl and monitor webhooks sit in the core flow; each edge shows URL and fetch time.
- Feasibility (25%): restartable batch with laptop fallback; small live path.
- Valio end-to-end (30%) and buyer need (20%): proposal, approval and order run through the mock; concentration uses real graph size.
- Trust and privacy (10%): the batch writes only `inferred` edges; the hotel's own map stays private.
- Bounties: Gemini, Aiven, Modal (batch compute), CRACI (CI and SBOM).

## 10. Risks and cuts
- Cut first: ArcadeDB, pgvector (category match instead), Cala, Oxylabs.
- Cut second: the second supplier tier, keeping only tier 1 if the run is late.
- Biggest risks: Context.dev batch quotas or latency (mitigate: cap crawl pages per supplier, use cached results); Modal account setup delay (mitigate: `--local` runner); noisy extraction creating false edges (mitigate: confidence threshold, source-in-crawl check, and a "rejected" count shown on the batch report).

## 11. Biggest weakness of this proposal (be honest)
The overnight run is only as good as public web coverage of small Nordic suppliers, and a Sunday demo can fail if the run half-finishes. Extraction errors would show as wrong edges on stage, and we might spend Saturday on infrastructure instead of on the procurement flow judges will actually watch.

# Entrant 03: Tracewell, minimal demo (lens: Ruthless minimal viable demo)

## 0. Bold bet
One Postgres, one Python app, three agent functions behind two buttons. Everything off the 4-minute demo path is cut, and live Context.dev calls happen in the first minute so judges see real source URLs appear. This wins on reliability and full Valio beat coverage, not graph-database depth.

## 1. Summary and name
Tracewell: a hotel buyer sees its supply map centred on Valio Aimo, scans live for upstream dairy producers, gets a sourced risk alert, compares opted-in alternatives with published prices, approves an agent-proposed switch, and the order goes through Valio's mock API into an append-only log. Name is a suggestion.

## 2. Architecture and DB choice
- **Postgres 16 only.** Hosted on Aiven (Aiven bounty), local Docker fallback. Recursive CTEs handle upstream traversal, blast radius and concentration at demo scale (about 150 companies). ArcadeDB is cut: it adds a Docker/Helm setup and a second query language. Upgrade path only if time remains.
- **Components:** one FastAPI app (JSON API plus server-rendered pages; agent runs are synchronous requests). Cytoscape.js for the graph. Gemini with function calling. Context.dev Python SDK. A thin Valio mock-API client. No queues, no separate agent service.
- **Flow:** Scan button, then Context.dev calls, then Gemini extracts candidates, then a validator writes `inferred` rows, then the graph reloads.

## 3. Data model and key queries
Tables:
- `company(id, name, country, industry, is_buyer, registered, visible_to_buyers, is_auditor)`
- `edge(id, seller_id, buyer_id, trust enum[inferred,claimed,agreed,audited], confidence numeric null, source_urls jsonb, declared_by, confirmed_by_buyer bool, audited_by null, created_at)`. Direction is seller to buyer.
- `price_point(company_id, sku, unit_price, currency, published bool, source_url)`
- `risk_signal(id, company_id, type, severity 1-5, detail, source_urls jsonb, observed_at)`
- `audit_log(id, actor, action, payload jsonb, created_at)`. Append-only: UPDATE and DELETE revoked from the app role.
- `purchase_order(id, buyer_id, proposal jsonb, status [pending_approval,approved,placed,rejected], approved_by, valio_ref)`

Trust transitions: agent or declaration writes `inferred` or `claimed`; supplier or buyer confirmation sets `agreed`; auditor stamp sets `audited`. Every transition writes `audit_log`.

Visibility: one SQL function `visible_view(viewer)` is the only read path for non-owners. Non-owners get `visible_to_buyers` companies, aggregates with k-anonymity (suppressed when fewer than 5 buyers), risk signals on the viewer's upstream nodes, and published prices only. Templates never query base tables.

Key queries (demo SQL, sketched):
- Upstream, depth 3: `WITH RECURSIVE up AS (SELECT seller_id s, buyer_id b, 1 d FROM edge WHERE buyer_id=$hotel UNION ALL SELECT e.seller_id, e.buyer_id, up.d+1 FROM edge e JOIN up ON e.buyer_id=up.s WHERE up.d<3) SELECT * FROM up;`
- Hidden concentration: `SELECT e.seller_id upstream, count(DISTINCT e.buyer_id) n FROM edge e WHERE e.buyer_id IN (SELECT seller_id FROM edge WHERE buyer_id=$hotel) GROUP BY 1 HAVING count(DISTINCT e.buyer_id)>=2;`
- Blast radius of X: recursive downstream walk from `seller_id=X`.
- Alternatives: published `price_point` rows for the sku, `visible_to_buyers=true`, ordered by price.
- Industry share: buyers in the industry with an edge from X, returned only if n is at least 5.

## 4. Agents (discovery, monitoring, procurement)
One module, three Gemini function-calling loops, at most four tool calls each.
- **Discovery.** Input: a dairy supplier name from the seed. Tools: Context.dev company enrichment and news search (90 days). Output: `{name, country, relation, confidence, source_urls[]}`. Validation: at least 2 source URLs, confidence at least 0.6, and the company name appears in fetched text. Accepted candidates become `company(registered=false)` plus `edge(trust=inferred)`. The invite is a logged stub.
- **Monitoring.** Re-check button on a supplier. Context.dev news search filtered to 14 days. Gemini classifies hits (recall, strike, insolvency, layoffs, sanctions) with severity and a required source URL. Webhooks are not needed; polling is enough.
- **Procurement.** Triggered at severity 4 or higher when a published substitute exists. Tools: `query_alternatives(sku)`, `propose_order()`. Writes `status=pending_approval`. `place_order` refuses unless `status=approved` by a human user. Enforced in code, not in the prompt.
- Valio mock contract (assumption, verify Friday): `GET /products?q=` and `POST /orders` with a fixed price reference.

## 5. Risk engine
Rules first, no ML. Each risk type has one rule, and the output is one `risk_signal` row. Supplier score is the max severity, not a sum.
- **Geopolitical:** static tier table for about 8 countries (assumption: seeded from a public index with its URL). Tier 3 or higher gives severity 3 to 4.
- **Regulatory:** exact name match against a 20-entry sanctions snapshot (assumption). Expired certification gives severity 3. EUDR and CSDDD are a boolean checklist per supplier.
- **Concentration:** the hidden-concentration query. Severity equals `min(5, direct_suppliers)`.
- **Financial and live events:** Context.dev news search, classified by Gemini. Severity comes from the classifier, and the source URL is required.
- **Price premium:** buyer's current unit price against the cheapest published alternative. Above 15% gives severity 2.

## 6. Screens and graph view
Four screens:
1. **Login:** persona picker for the hotel. No real auth (assumption for the demo).
2. **Supply map:** Cytoscape graph centred on the hotel. Node colour is max risk (grey, amber, red). Edge style is trust: solid for `agreed`, dashed for `claimed`, dotted for `inferred` with a confidence label, double for `audited`. Arrows run supplier to buyer. Buttons: Scan upstream, Re-check news. Clicking a node opens a side panel with trust, confidence and source URLs.
3. **Alert and alternatives:** risk detail with citations, then a table of opted-in alternatives showing price range, the opt-in badge and "used by X% of industry buyers".
4. **Proposal and log:** proposal card with Approve, order status with Valio reference, audit log table.
Supplier and auditor: one page each, one action (confirm edge, stamp audited).

## 7. Demo script (4 minutes)
- **0:00-0:30** Hotel logs in. Graph shows Valio Aimo, the hotel, and the three edge styles in one sentence.
- **0:30-1:20** Scan upstream. Live Context.dev calls. A new `inferred` dairy node appears with confidence and two URLs. Judge clicks a URL.
- **1:20-1:50** Re-check news on the dairy producer. Live hits. A recall signal appears with a URL, and the node turns red.
- **1:50-2:20** Concentration alert: three direct suppliers share one creamery. Blast radius number.
- **2:20-2:50** Opted-in alternatives with price ranges; aggregate "used by 14% of industry buyers".
- **2:50-3:20** Proposal. Manager clicks Approve. Valio mock order placed, reference shown.
- **3:20-3:40** Supplier confirms edge (claimed to agreed) in a second tab. Auditor stamps audited.
- **3:40-4:00** Audit log walk-through. Close. A failed live call falls back to a timestamped cached response.

## 8. 48h build plan (4 engineers, 4 milestones)
- **M1, Friday night:** E1 schema, seed (about 40 Valio suppliers plus about 20 hand-made companies), visibility function. E4 graph renders from seed.
- **M2, Saturday:** E2 Context.dev discovery, validator and risk rules, live. E3 Valio client and alternatives query.
- **M3, Saturday night:** E3 proposal, approval gate, order, audit log. E4 trust transitions and side panel. All: cache fallback for live calls.
- **M4, Sunday morning:** rehearse three times, record a backup video, E1 adds a CRACI action with SBOM (about 20 minutes). Bug fixes only.
- **Stacking:** Gemini, Aiven, Context.dev (core), CRACI. Codex not planned.

## 9. Judging-criteria mapping
- **Valio (30% end to end, 20% need, 20% controls, 15% exceptions, 15% standards):** one working order path, approval enforced in code, append-only log, JSON proposal schema. Exception substitution is a stretch goal.
- **Context.dev (15%):** discovery and re-check both live, URLs on screen, and a second run shows a change the first did not.
- **Trust and privacy (10%):** visibility function, k-anonymity threshold of 5.
- **Concreteness (10%):** schemas and SQL above.
- **Side bounties (10%):** Gemini, Aiven, CRACI, without touching the core.
- Cala not entered: no founder or investor angle in the core flow.

## 10. Risks and cuts
- **Cut order:** Cala, ArcadeDB, Oxylabs, Modal, Exa, Websets, monitor webhooks, supplier and auditor pages (reduced to side-panel buttons), partial-availability substitution, Codex.
- **Context.dev latency or limits:** cached last-good responses with timestamps.
- **Gemini quota:** pre-run scans Saturday night and store results.
- **Valio API shape unknown:** agree the contract Friday; stub locally if late.
- **Recursive CTE bugs:** test against the seed Friday.

## 11. Biggest weakness of this proposal (be honest)
Postgres-only undersells the graph story; judges may ask why this is not a graph database, and recursive CTEs look weaker than Cypher. The rule-based risk engine is thin, and network growth shows only as one invite stub, not a multi-company cascade.

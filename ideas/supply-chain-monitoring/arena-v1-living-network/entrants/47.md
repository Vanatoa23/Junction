# Entrant 47: Vouch, tenant-scoped identity for people and agents (lens: multi-tenant auth and RBAC)

## 0. Bold bet
Every company is a tenant, every human and every agent is a principal with explicit, narrow scopes, and the rule "agents can never approve or place orders" is enforced by the token system rather than by prompts. The demo shows an agent token being refused an order call and a manager revoking an agent in one click, which turns the autonomy-and-controls criterion into something judges can click through.

## 1. Summary and name
- **Vouch**: a living supply network where each company operates in its own tenant, sees only what its role allows, and lets AI agents act through scoped tokens that humans can inspect and revoke.
- Demo tenants: Valio Aimo (hub, with manager and catalogue roles), a hotel chain (buyer), a dairy producer (supplier), an auditor firm (simulated), and three agent service accounts.
- Assumption: no external identity provider. Seeded accounts with hashed passwords, and a persona picker on the login screen to save time on stage.

## 2. Architecture and DB choice
- **One repo, one service:** Node 22 with TypeScript, Hono for HTTP, Drizzle on Postgres, a Vite React SPA served by the same process.
- **Database: Postgres (Aiven).** Tenant isolation, scope checks and the graph (recursive CTEs) all live in one database, so authorization and data stay in one transaction. ArcadeDB adds a second auth boundary we cannot defend in 48h. Stretch only: export edges to ArcadeDB for a Cypher blast-radius view.
- **Auth:** session JWT in an httpOnly cookie (`jose`, 8-hour expiry). Agent tokens are opaque bearer strings, `vch_<id>_<secret>`, stored as SHA-256 hashes with prefix lookup.
- **Gemini** via the Google AI SDK with function calling; each tool call is a Hono-internal call that passes the same authorization middleware as the UI.
- **Context.dev** monitors post to `/webhooks/context` and are verified by a shared HMAC secret. Assumption: webhook signature scheme is HMAC-SHA256 over the raw body; verify on day one.
- **Valkey (Aiven):** optional, for token-rate limiting per agent. Skip if short on time.

## 3. Data model and key queries
- `tenants(id, name, kind in {buyer, supplier, hub, auditor}, registered bool)`. Unregistered companies exist as a `companies` row with `tenant_id NULL` and an invite token.
- `principals(id, tenant_id, type in {user, agent}, name, role, password_hash NULL)`. Roles: `buyer`, `manager`, `supplier`, `auditor`. Agents carry `role='agent'`.
- `api_tokens(id, principal_id, token_hash, scopes text[], expires_at, revoked_at, created_by)`.
- `companies(id, tenant_id, name, country, industry, sanctions_hit)`, `products(id, company_id, price_min, price_max, published, opted_in)`.
- `edges(id, from_id, to_id, trust enum(inferred, claimed, agreed, audited), confidence, sources jsonb, from_confirmed, to_confirmed, audited_by, created_by principal)`.
- `authz_log(id, ts, principal_id, scope, resource, decision, reason)`. Every allow and deny is written here.
- Scopes (fixed list): `graph:own`, `graph:visible`, `edge:write_inferred`, `edge:confirm`, `edge:audit`, `risk:write`, `risk:read`, `order:propose`, `order:approve`, `order:place`, `catalogue:read`.
- **Policy matrix (one TS table, unit tested):**
  - buyer user: `graph:own`, `graph:visible`, `risk:read`, `order:propose`.
  - manager user: buyer scopes plus `order:approve`.
  - supplier user: `graph:own`, `edge:confirm`, `catalogue:read`.
  - auditor user: `edge:audit`, `graph:visible`.
  - agent tokens: only the scopes minted for them. `order:approve` and `order:place` are on a forbidden list at mint time and at check time, so no agent token can hold them.
- **Visibility query:** `visibleGraph(principal)` returns the principal's own tenant edges; risk rows for suppliers and upstream nodes; aggregates with `HAVING count(DISTINCT tenant_id) >= 5`; products where `opted_in AND published`. Edges between two other tenants are never selected.
- **Upstream traversal:** `WITH RECURSIVE up AS (SELECT from_id, 1 AS d FROM edges WHERE to_id = $1 UNION ALL SELECT e.from_id, up.d+1 FROM edges e JOIN up ON e.to_id = up.from_id WHERE up.d < 4) SELECT DISTINCT from_id FROM up;` Each row is filtered by visibility afterwards for buyers.
- **Hidden concentration:** group the upstream rows by ancestor id, keep ancestors reached through at least two distinct direct suppliers.
- **Blast radius:** same CTE downstream from a failed node.
- **Alternatives:** products in the category joined to `opted_in`, ordered by `price_min`, with `published = true`.

## 4. Agents (discovery, monitoring, procurement)
Each agent is a service principal with its own token; its run is a Gemini function-calling loop capped at six steps.
- **Discovery** token: `edge:write_inferred`, `risk:read`. Tools: `search_news`, `enrich_company`, `write_inferred_edge`. Output requires at least two source URLs with the company name in the fetched text; confidence capped at 0.8 for single-source. Cannot write confirmed or audited edges, since the DB check refuses trust levels above `inferred` for this principal type.
- **Monitoring** token: `risk:write`, `risk:read`. Triggered by cron or a Context.dev monitor. Writes risk rows with URL and timestamp; cannot touch edges.
- **Procurement** token: `order:propose`, `catalogue:read`. Tools: `list_alternatives`, `propose_switch`. Writes an order with `status='proposed'`. There is no `place` tool and no `order:place` scope.
- **Human approval** is an HTTP route, `POST /orders/:id/approve`, requiring a user session with `order:approve`, approver not equal to proposer, and then calling the Valio mock with an idempotency key. The route, not the agent, owns the Valio credential.
- Revocation: `POST /tokens/:id/revoke` by a manager. The next tool call fails with a logged deny, which is our kill switch.

## 5. Risk engine
Deterministic TypeScript rules, each emitting `{rule, severity, sources, as_of}`:
- `sanctions`: seeded list name match, critical.
- `compliance`: expired certificates on products, EUDR and CSDDD flags from a seeded commodity and country table.
- `geopolitical`: country score table weighted by spend.
- `concentration`: upstream CTE, two or more direct suppliers sharing one ancestor.
- `live_events`: Context.dev news search with keyword rules, each with URL.
- `financial`: Context.dev enrichment fields (funding, headcount change).
- `price_premium`: only when published alternatives exist.
Gemini writes the one-sentence explanation; scores are not model output.

## 6. Screens and graph view
- **Login:** persona picker: hotel buyer, Valio manager, dairy supplier, auditor.
- **Map:** Cytoscape graph of the viewer's visible graph. Arrow direction, dashed for inferred, solid for agreed, double for audited, red outline for open risk. Other tenants' internal edges are absent, not greyed out.
- **Risk and alternatives:** cards with rule, source link and as-of time; alternatives list with opt-in badge.
- **Approvals:** proposed switch, price delta, approver check status.
- **Access console (manager):** agent tokens with scopes, last used, Revoke button, and the authz log filtered by denies.
- **Supplier:** confirm-edge button. **Auditor:** stamp-audited button.

## 7. Demo script (4 min)
- 0:00–0:25 Hotel buyer logs in; map shows only its own chain and aggregates.
- 0:25–0:55 Discovery token runs live; console shows Context.dev URLs; new inferred supplier appears.
- 0:55–1:30 Risk alert on upstream dairy; alternatives with published price ranges.
- 1:30–2:10 Procurement proposes switch. Show the procurement token's scope list; it has no order-placement scope.
- 2:10–2:40 Manager approves; Valio mock order placed; authz log shows the approve and the approver is not the proposer.
- 2:40–3:10 Manager revokes the procurement token; a second proposal attempt is denied in the log.
- 3:10–3:40 Supplier confirms edge (claimed to agreed); auditor stamps audited.
- 3:40–4:00 Close on the authz log.

## 9. Judging-criteria mapping
- Valio end-to-end (30%): request, approval, mock order, partial path.
- Guardrails and auditability (20%): scoped tokens, forbidden scopes, revocation, authz log, approver-is-not-proposer rule.
- Exceptions (15%): partial availability returns to proposal with its own approval.
- Open standards and production path (15%): OAuth-shaped scopes and bearer tokens, a credible move to an external IdP.
- Context.dev (15%): live discovery and monitor webhook with URLs and as-of times.
- Trust and privacy (10%): tenant-scoped visibility, aggregates with minimum group size of five, fixed edge-level trust rules.
- Side bounties: Gemini (agents), Aiven (Postgres, optional Valkey), CRACI (CI and SBOM), Codex if used meaningfully.

## 10. Risks and cuts
- Cut first: ArcadeDB, Cala, Modal, Oxylabs, Exa, Valkey.
- Auth bugs leaking another tenant's edges. Mitigation: all graph reads go through `visibleGraph`, with three fixture tests run in CI.
- Webhook verification details from Context.dev unknown. Mitigation: polling fallback every two minutes.
- Persona login could look like a toy. Mitigation: show real token hashes and scope lists on screen.

## 11. Biggest weakness of this proposal (be honest)
The identity layer is custom and minimal, so it is a convincing controls story rather than production IAM: no SSO, no key rotation, no row-level security enforced by the database. The graph is also plain Postgres, so the ArcadeDB features the brief highlights go unused.

# Entrant 26: Pactline, the procurement agent with a trust graph (lens: Contrarian)

## 0. Bold bet
The product is a procurement agent, not a graph app, so the main screen is a chat with the buyer's agent, and the graph is a panel it opens on request. The graph exists to make the agent's recommendations checkable (trust level, confidence, sources on every claim), which is what Valio's "guardrails and auditability" criterion rewards.

## 1. Summary and name
**Pactline.** A hotel buyer talks to its procurement agent: "Any dairy risk this week?", "Cheaper milk that is still EU-certified?", "Switch the dairy order if it is safe." The agent answers from a trust graph of companies and edges, cites every claim with trust level and source URLs, drafts a switch, and waits for a manager's approval before calling Valio's mock order API. Suppliers and auditors use the same network through short confirm and stamp actions.

## 2. Architecture and DB choice
**Postgres (Aiven managed) for everything; no ArcadeDB.** Reasons: the agent's answers are narrow lookups (one company's neighbourhood, one product's alternatives, one risk feed), not open-ended graph exploration. Recursive CTEs cover upstream traversal and blast radius at demo scale, pgvector covers alternatives, and one database keeps the audit log, approvals and graph transactional. ArcadeDB's ready-made traversal is a feature we don't need, and it adds Docker/Helm and a query language to learn.

Components:
- **Agent runtime:** Gemini (main LLM) with function calling. Tools are typed Python functions over the DB, each returning rows with `trust`, `confidence` and `source_url`. The model may only state facts that came back from a tool.
- **Tools:** `get_my_suppliers`, `get_risks(company)`, `find_alternatives(product)`, `discover_company(domain)`, `propose_switch(...)`, `request_approval(...)`, `place_order(proposal_id)`, which fails unless approval exists.
- **Background workers:** discovery and monitoring, scheduled every 5 minutes and triggered by Context.dev webhooks.
- **Web:** Context.dev for enrichment, news search and monitors. Exa optional.
- **Valio:** mock catalogue, availability and order APIs.
- **UI:** a single React page with chat on the left, a Cytoscape graph panel on the right, and an approvals tray.
- **Hosting:** Aiven Runtime for the API and Postgres. Fallback: laptop plus tunnel.

## 3. Data model and key queries
```sql
CREATE TABLE company (id uuid PRIMARY KEY, domain text UNIQUE, name text, country char(2),
  industry text, status text CHECK (status IN ('registered','unregistered')),
  alt_opt_in boolean DEFAULT false, embedding vector(768));
CREATE TABLE edge (id uuid PRIMARY KEY, buyer_id uuid, seller_id uuid,
  trust text CHECK (trust IN ('inferred','claimed','agreed','audited')),
  confidence real, sources jsonb, buyer_ok boolean DEFAULT false,
  seller_ok boolean DEFAULT false, audited_by text, UNIQUE (buyer_id, seller_id));
CREATE TABLE risk (id bigserial PRIMARY KEY, company_id uuid, kind text, severity smallint,
  confidence real, headline text, source_url text, public_name boolean, created_at timestamptz);
CREATE TABLE price (company_id uuid, product_id text, unit_price numeric, published boolean,
  PRIMARY KEY (company_id, product_id));
CREATE TABLE proposal (id uuid PRIMARY KEY, buyer_id uuid, from_supplier uuid, to_supplier uuid,
  product_id text, qty int, status text, approved_by text, valio_order_id text);
CREATE TABLE event (id bigserial PRIMARY KEY, actor text, tool text, args jsonb,
  result_hash bytea, prev_hash bytea, hash bytea, at timestamptz DEFAULT now());
```
- **Trust:** `claimed` on one-sided declaration. A trigger sets `agreed` when both `*_ok` flags are true. `audited` only via the simulated auditor stamp.
- **Privacy:** RLS on `edge` lets a session read only edges where it is an endpoint. The agent's `get_risks` tool returns only `risk` rows for the buyer's upstream chain, with headlines, never the upstream edges. Upstream entities are named only when `public_name` is true, otherwise shown as "Tier-2 supplier".
- **Upstream risk (depth ≤ 4):**
```sql
WITH RECURSIVE up(anc, depth, path) AS (
  SELECT seller_id, 1, ARRAY[buyer_id, seller_id] FROM edge WHERE buyer_id = $me
  UNION ALL
  SELECT e.seller_id, up.depth+1, up.path || e.seller_id FROM up
  JOIN edge e ON e.buyer_id = up.anc WHERE up.depth < 4 AND NOT e.seller_id = ANY(up.path))
SELECT r.* FROM up JOIN risk r ON r.company_id = up.anc WHERE r.severity >= 2;
```
- **Hidden concentration:** same recursion, grouped by ancestor, `HAVING count(DISTINCT direct supplier) >= 2`, excluding direct suppliers.
- **Blast radius:** recursion walking downward (`seller_id = X`), returning buyer counts with k-anonymity (`HAVING count(*) >= 5`).
- **Alternatives:** `SELECT c.name, min(p.unit_price), max(p.unit_price) FROM company c JOIN price p ON p.company_id = c.id AND p.published WHERE c.alt_opt_in AND p.product_id = $prod ORDER BY c.embedding <=> $q LIMIT 3`.

## 4. Agents
**Discovery.** Trigger: "Scan now" in chat, or a monitor tick. Tools: Context.dev enrichment and news search. Gemini extracts `{buyer, seller, relation, confidence, source_url, quote}`. Validation: `source_url` must be a page we fetched; `quote` must appear verbatim in it; both names must match. Stored confidence = min(model score, 0.5 + 0.15 × sources), capped at 0.9. Output: `inferred` edge plus an `unregistered` node and invitation. The chat reports each new edge with its URL.

**Monitoring.** Context.dev monitors on supplier domains and news queries, posting to `/hooks/ctx`. Gemini classifies changes into risk kinds with severity and confidence. Sanctions: a cached EU list (assumption: downloaded Friday) matched by `pg_trgm` similarity above 0.8. Each risk is deduplicated on `(company, kind, source_url)`.

**Procurement.** Triggers: a severity ≥ 3 risk on a current supplier, or a published premium above 15%. It gathers Valio availability and candidates, then writes a two-line rationale that cites only tool rows. It creates `proposal.status = pending_approval`. The approval tray shows the diff, the risk headline and its source. `place_order` POSTs to Valio with `Idempotency-Key = proposal.id` only after approval. Partial stock (e.g. 40 of 60) produces a split or substitute proposal, which the agent must ask about in chat.

## 5. Risk engine
- **Geopolitical:** seeded country table (assumption, labelled) plus Gemini news classification.
- **Regulatory:** sanctions match; EUDR and CSDDD fields from Valio sustainability data; missing or expired certificate = severity 3.
- **Concentration:** hidden-upstream query and single-source flag.
- **Financial:** Context.dev news and enrichment (layoffs, funding, insolvency terms).
- **Live events:** Context.dev news monitors (recall, strike, outage).
- **Price:** published price versus cheapest opted-in alternative.
- Score = severity × confidence × 0.7^(hops − 1). Chat only mentions risks scoring ≥ 2.

## 6. Screens and graph view
1. **Login:** company switcher; hotel persona is default.
2. **Chat (main):** streaming answers. Each claim shows a trust chip (inferred 0.72, claimed, agreed, audited) and clickable source URLs.
3. **Graph panel:** direct suppliers around Valio. Arrow direction; dashed grey = inferred, blue = claimed, green = agreed, gold = audited; red badge = risk. Upstream nodes are only shown as badges.
4. **Approvals tray:** proposal diff, risk source, Approve and Reject. Approval creates a signed event.
5. **Audit page:** the `event` table as a timeline, with "verify chain".
6. **Supplier and auditor views:** Confirm edge; Stamp audited.

## 7. Demo script (4 min)
- 0:00–0:30 Hotel asks: "Who do I depend on for dairy?" Agent answers with trust chips and privacy note.
- 0:30–1:10 "Scan for new dairy suppliers." Live Context.dev run; new `inferred` edge with confidence and URLs appears in chat and graph.
- 1:10–1:40 Monitor webhook fires (pre-armed): "Upstream dairy producer under sanctions review," with source link. Agent cites hidden concentration: three suppliers share one co-op.
- 1:40–2:10 Supplier confirms in a second browser: `claimed` to `agreed`, live in graph. Auditor stamps `audited`.
- 2:10–2:40 "Find cheaper EU-certified milk." Three opted-in alternatives with price ranges.
- 2:40–3:30 "Propose the switch." Approval tray; manager approves; Valio mock order with idempotency key. Partial stock: agent proposes substitute and asks.
- 3:30–4:00 Audit page: every tool call, actor and hash; "verify chain".

## 9. Judging-criteria mapping
- **Valio (30%):** end-to-end chat-to-order flow; idempotent mock order; approval enforced in code.
- **Buyer need (20%):** a single question answers risk, alternatives and price.
- **Controls (20%):** tool-only facts, RLS, approval gate, hash-chained log.
- **Exceptions (15%):** partial stock turned into a question, unregistered suppliers invited, Context.dev fallback to cache.
- **Open standards (15%):** OpenAPI for tools, SQL, pgvector, Aiven path.
- **Context.dev (15%):** live discovery and monitors in the core flow, with sourced quotes.
- **Bounties:** Gemini (agent LLM), Aiven (store and hosting), Codex (seed and tests), CRACI (Actions CI with SBOM). Cala not entered.

## 10. Risks and cuts
- **Cut order:** Cala, Oxylabs, Exa, embeddings (category match instead), real sanctions list (seeded 20 entities), Aiven Runtime (run locally), graph panel (chat-only if short on time).
- **Risks:** LLM hallucinated facts (mitigated by tool-only answers and a checker that rejects uncited claims); Context.dev latency (pre-cached scan labelled cached); Gemini rate limits (cache); webhook not arriving (pre-armed replay).

## 11. Biggest weakness of this proposal
Chat-first UI risks looking like a chatbot wrapper to judges, and the graph, which the brief centres on, becomes secondary. Agent answers are only as reliable as the tool outputs, and a single hallucinated risk in the live run would undermine the trust story.

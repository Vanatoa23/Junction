# Entrant 05: Rootwire on One Graph Engine (lens: ArcadeDB-native graph-first)

## 0. Bold bet
One ArcadeDB instance holds everything (graph, trust, vectors, documents, time-series, audit), and the demo's showpiece is Cypher traversals answering business questions live on screen. We win if judges watch hidden concentration and blast radius run against edges the discovery agent found minutes earlier, not on a prettier table.

## 1. Summary and name
- Name: **Rootwire**. A living supply-chain graph: buyers see their upstream chain, risk alerts and opt-in alternatives; agents grow the graph and procure with human approval.
- Stack: ArcadeDB (only store), Node/TypeScript API (Fastify) with SSE, Python agent workers (Gemini, Context.dev SDK), React + Cytoscape.js.
- Aiven: host the app on Runtime and cache Context.dev responses in Valkey (about 1h of work).
- Assumption: ArcadeDB runs in Docker. Cypher is primary; ArcadeDB SQL (MATCH/TRAVERSE) is the fallback.

## 2. Architecture and DB choice
- **ArcadeDB, not Postgres.** Upstream and concentration queries are natural Cypher; in Postgres they become recursive CTEs, and we would dual-write edges. A hybrid doubles the integration work we cannot afford in 48h.
- API: resolves the persona, runs only parameterised query templates (clients never send raw Cypher), and exposes `/ingest` as the only write path. `/ingest` validates trust, sources and confidence, then MERGEs.
- Agent workers: poll `Job` documents in ArcadeDB (no Kafka), write back via `/ingest`, and log every tool call as an `AuditEvent`.
- External: Context.dev (enrichment, news, scrape with JSON schema, monitors with webhooks to `/hooks/context`), Gemini (JSON-mode extraction and classification), Valio mock API (catalogue, availability, order).
- Live path: Context.dev → worker → Gemini extraction → `/ingest` → ArcadeDB → SSE to UI.
- Spike Friday morning (90 min): confirm `MERGE`, `*1..4` variable-length paths with relationship predicates, and an HNSW vector index in the Docker image. Assumption, unverified. Fallback is SQL traversal plus brute-force cosine over about 700 vectors, which is cheap at this scale.

## 3. Data model and key queries
Vertices:
- `Company` {id, name, country, industry[], registered, visible_alt (opt-in), embedding, certs JSON}
- `Product` {sku, name, unit, price_min, price_max, price_published}
- `Risk` {type: geo|reg|conc|fin|event|price, score, confidence, sources[] URLs, ts}
- `Order` {id, status: proposed|approved|placed|rejected, lines, approved_by}
- `AuditEvent` {id, ts, actor, action, payload, prev_hash, hash}
- `Signal` (time-series type; sparkline of lead times and news volume, cut first if tight)

Edges:
- `SUPPLIES` (supplier → buyer) {trust: inferred|claimed|agreed|audited, confidence, owner_id, visibility: private|public, declared_by, confirmed_by, auditor_id, sources[], valid_from}
- `HAS_RISK` (Company → Risk)

Rules:
- Trust is monotonic. `/ingest` rejects any downgrade.
- Agent-discovered public edges get `visibility=public`. Declared edges default to `private` with `owner_id` set.
- Buyers see private edges only when `owner_id` matches them. They see risk on any node in their upstream chain, aggregates only when the group size is at least 5, alternatives only when `visible_alt=true`, and prices only when `price_published=true`.

Key queries (pseudo-Cypher; syntax to verify):
- **Upstream chain:** `MATCH p=(s:Company)-[e:SUPPLIES*1..4]->(me:Company {id:$me}) WHERE all(r IN relationships(p) WHERE r.visibility='public' OR r.owner_id=$me) RETURN p`
- **Hidden concentration:** `MATCH (d:Company)-[:SUPPLIES]->(me:Company {id:$me}), (u:Company)-[:SUPPLIES*1..3]->(d) WITH u, collect(DISTINCT d.name) AS via, count(DISTINCT d) AS n WHERE n>=2 RETURN u.name, via, n`
- **Blast radius:** `MATCH p=(f:Company {id:$failed})-[:SUPPLIES*1..5]->(x:Company) RETURN x.name, min(length(p)) AS hops`
- **Alternatives:** vector kNN on `Company.embedding` (ArcadeDB SQL `vectorNeighbors`, syntax to verify), then Cypher filters `visible_alt=true`, same industry, and joins `price_published` prices. Premium = (supplier price − min alternative) / min alternative.

## 4. Agents
- **Discovery.** Input: Valio supplier list (a 40-supplier demo subset of the synthetic 700) plus hand-crafted dairy producers. Tools: Context.dev enrichment (name → domain, country, industry), news search, scrape of "about/sustainability" pages with a JSON schema. Output: `Company` (registered=false, invited) and `SUPPLIES` with `trust=inferred`, confidence and source URLs. Validation: at least two distinct source URLs, or confidence ≥0.7 with a domain match; otherwise the job is marked `needs_review`. Human approval is not needed for inferred edges, but procurement only uses `claimed` or better suppliers unless a manager overrides.
- **Monitoring.** Context.dev monitors on each company's domain and a news query, with webhooks to `/hooks/context`. Gemini classifies each change into `{type, severity, summary, source_url}` and writes `Risk` + `HAS_RISK`. Risk reaches buyers by traversal, not copying. Sanctions: a snapshot of the EU list loaded at seed time, with normalised name matching (assumption: the snapshot is recent enough for a demo).
- **Procurement.** Trigger: a risk ≥0.6 on a node in the buyer's chain, or a price premium above 15% against published prices. It runs the alternatives query, and Gemini writes a rationale citing graph facts and URLs. It creates `Order(status=proposed)`. After a manager approves, the agent calls the Valio mock: product lookup, availability, then order at the fixed price. Exceptions: a short stock line gets a substitute from the next alternative; a lead time outside the delivery window is rejected with a reason.

## 5. Risk engine
Score per type, stored with confidence. The company score is the max of its types. Upstream risk reaches the buyer with a decay of 0.8 per hop, shown as "via tier-2".
- **Geopolitical:** static country table (labelled snapshot) plus Context.dev news in the last 30 days, with Gemini conflict tagging, which adds 0.3.
- **Regulatory:** sanctions exact match gives 1.0 and fuzzy gives 0.6. Expired certs give 0.8. A missing required cert for CSDDD or EUDR scope gives 0.5.
- **Concentration:** graph query above; score = min(1, shared_suppliers/5).
- **Financial:** news tags for layoffs, insolvency and funding; insolvency gives 0.7.
- **Live events:** recall, strike or outage tags from the news monitor; 0.5–0.9 by severity.
- **Price premium:** min(1, premium/0.3), only when prices are published.

## 6. Screens and graph view
1. Persona switch (hotel, grocery, Valio admin, supplier, auditor). No real auth.
2. My supply map (Cytoscape). Arrows point supplier → buyer. Edge line style encodes trust: dotted inferred, solid claimed, double agreed, thick with an audit badge for audited. Node fill encodes risk (grey, amber, red). Dashed border marks invited, unregistered nodes. Private edges show only to their owner.
3. Risk card: type, score, confidence, source links, traversal path.
4. Alternatives: opted-in suppliers, published price range, lead time, certs.
5. Proposal: rationale, price delta, approve/reject.
6. Audit timeline with hash chain.
7. Supplier portal: confirm edge (claimed → agreed).
8. Auditor console: stamp audited.
9. Discovery console: "Run discovery" streams Context.dev hits with URLs, and shows the Cypher text that runs.

## 7. Demo script (4 min)

- 0:25–1:00: Log in as the hotel. Walk the map and the trust legend.
- 1:00–1:30: Run discovery live. Four companies stream in with URLs, appear as inferred, and the Cypher panel shows the query.
- 1:30–2:00: Supplier confirms in a second browser tab, claimed → agreed over SSE. Auditor stamps audited.
- 2:00–2:40: Monitor webhook fires on a dairy producer (recall or strike news). Risk card shows sources. Blast radius: three hotel products affected.

- 3:10–3:40: Alternatives with an opt-in supplier and published price range; premium shown.
- 3:40–4:10: Procurement proposal; manager approves; Valio mock order placed; audit timeline shows every step.

## 9. Judging-criteria mapping
- **Valio (30/20/20/15/15):** end-to-end order through the mock API; approval gate; audit chain; exceptions (substitution, lead-time reject); open formats (OpenAPI-described endpoints, Apache-2.0 engine with Docker/Helm for a production path).
- **Context.dev:** discovery, news and monitor webhooks sit in the core flow; webhooks give real-timeness; URLs visible on every inferred edge.
- **Trust and privacy:** enforced in query templates, k≥5 aggregates, monotonic trust, visible on screen.
- **Concreteness:** query text shown during the demo.
- **Bounties:** Gemini (extraction, classification, rationale); Aiven (Runtime plus Valkey); CRACI (Action); Codex (used in dev, noted in commits). Cala is cut.

## 10. Risks and cuts
- **Cut order:** Cala; Oxylabs; Modal; Exa; Signal time-series (plain documents instead); Valkey (in-memory cache); live monitor (fall back to a pre-recorded webhook with real logged calls).
- **Risks:** (1) ArcadeDB Cypher gaps on relationship predicates or MERGE; mitigate with the Friday spike, a query repository layer and SQL fallback. (2) HNSW in the Docker image unverified; mitigate with brute force. (3) Context.dev latency on stage; pre-warm and cache. (4) Gemini rate limits; cache extractions. (5) Webhooks need a public URL; use a tunnel and poll as backup.

## 11. Biggest weakness of this proposal
It bets the whole demo on an engine the team has not run. If the Friday spike fails, the showpiece collapses to SQL and we lose a day. Visibility also lives in API templates rather than the database, so one bug can leak a private edge, and a judge who pokes the API could find it.

# Entrant 44: Three-Layer Seed (lens: Data seeding strategy)

## 0. Bold bet
Every row in the demo carries an `origin` (valio_synth, story, scraped, live), and the live path reads the same JSON shape that a cached fixture holds, so the demo cannot fail on data and every visible "live" claim is genuinely sourced. We win because judges see real Context.dev URLs and a fully scripted story at once, and the golden path is tested in CI before Sunday.

## 1. Summary and name
Name: **Lattice Harbour** (short: **Harbour**). Seeded network of Valio's supply base, a fictional hotel's buying story, and a small set of real public companies, all in one graph. The hotel logs in, sees its map, gets a dairy risk alert with a live-sourced link, compares opted-in alternatives, approves a switch, and watches the Valio mock order and audit trail.

## 2. Architecture and DB choice
- **Postgres on Aiven** (with pgvector) as the only store. Seeding is plain SQL `COPY` and idempotent upserts; ArcadeDB would need its own import path and Docker setup, which is days we do not have.
- **Seed pipeline** (Python CLI `seed`): reads manifests, validates references, writes in one transaction, prints a row-count report.
- **Snapshot store:** `fixture_response(url, fetched_at, json)` holds raw Context.dev responses. Live and replayed data go through the same parser.
- **Services:** FastAPI API, Gemini for agent reasoning and extraction, Context.dev for live fetches, Valio mock APIs, React front end.
- **Hosting:** Aiven Runtime for the API, with a laptop fallback.

## 3. Data model and key queries
Three seed layers, one schema:
```sql
CREATE TABLE company (id uuid PRIMARY KEY, name text, domain text UNIQUE, country char(2),
  industry text, status text CHECK (status IN ('registered','unregistered')),
  origin text CHECK (origin IN ('valio_synth','story','scraped','live')),
  is_fictional boolean NOT NULL, alt_opt_in boolean DEFAULT false, fetched_at timestamptz);
CREATE TABLE edge (id uuid PRIMARY KEY, buyer_id uuid, seller_id uuid,
  trust text CHECK (trust IN ('inferred','claimed','agreed','audited')),
  confidence real, origin text, sources jsonb,  -- [{url, quote, fetched_at}]
  buyer_ok boolean DEFAULT false, seller_ok boolean DEFAULT false, audited_by text,
  UNIQUE (buyer_id, seller_id));
CREATE TABLE fixture_response (url text, fetched_at timestamptz, body jsonb, PRIMARY KEY (url, fetched_at));
```
- **Layer A, Valio synthetic (base):** about 700 supplier companies, ~300 dairy and food products with prices and certificates. The 20,000 customers are not nodes: they become industry counts (`industry_usage` with k ≥ 5 threshold). Edges: Valio ← supplier, `claimed` by Valio.
- **Layer B, story (hand-built, `is_fictional = true`):** the hotel (buyer), its manager user, Lakeside Dairy Co-op (the risky producer), its upstream packaging and feed firms, three opted-in alternative dairies with published prices, and one simulated auditor. Story edges are set to the trust state each beat needs.
- **Layer C, scraped (real):** 25 real public companies with real domains, chosen Friday for having pages that state supplier or product relationships. Stored with `fetch_at` and quotes from the fetched page. Edges are `inferred` with confidence from the validation rule (below).

Key query, upstream risk for the hotel (depth ≤ 4):
```sql
WITH RECURSIVE up(anc, depth, path) AS (
  SELECT seller_id, 1, ARRAY[buyer_id, seller_id] FROM edge WHERE buyer_id = $hotel
  UNION ALL
  SELECT e.seller_id, up.depth+1, up.path || e.seller_id FROM up
  JOIN edge e ON e.buyer_id = up.anc WHERE up.depth < 4 AND NOT e.seller_id = ANY(up.path))
SELECT c.name, c.origin, c.is_fictional, r.* FROM up JOIN company c ON c.id = up.anc
JOIN risk r ON r.company_id = up.anc WHERE r.severity >= 2;
```

Trust and privacy: `claimed` set by one-sided declaration; `agreed` by a trigger when both `*_ok` flags are true; `audited` only by the auditor stamp. RLS restricts edges to their endpoints; the hotel sees upstream risks only through the function above.

## 4. Agents (discovery, monitoring, procurement)
- **Discovery:** input is a domain or news query. Context.dev returns JSON and the page text. Gemini extracts `{buyer, seller, relation, quote, source_url}`. Validation: the URL must be in the fetched set, the quote must appear verbatim in page text, and both names must match. Confidence = min(model score, 0.5 + 0.15 × sources), cap 0.9. The output is an `inferred` edge with `origin = live` and a chat line with the URL.
- **Monitoring:** Context.dev monitors on the 25 scraped domains and the story dairy's news query, posting to `/hooks/ctx`. Gemini classifies changes into risk kinds. A pre-armed replay of a stored webhook body is the fallback.
- **Procurement:** triggers on a severity ≥ 3 risk on a current supplier or a published premium above 15%. It writes `proposal.status = pending_approval`. `place_order` calls the Valio mock with `Idempotency-Key = proposal.id`, only after manager approval.

## 5. Risk engine
- **Story risk (fictional):** Lakeside Dairy Co-op carries a seeded `kind = regulatory`, severity 3, headline "Certificate expiry flagged in supplier audit" with a placeholder source marked `fictional`. The UI labels it FICTIONAL in the story layer.
- **Scraped risk (real):** only facts found in fetched pages are stored, with quote and URL. No invented news about real companies.
- **Concentration:** hidden shared upstream query on the story chain (three direct suppliers share the co-op).
- **Price premium:** published price vs cheapest opted-in alternative.
- **Sanctions:** EU list cached Friday (assumption), name match at `pg_trgm` > 0.8.
- Score = severity × confidence × 0.7^(hops − 1).

## 6. Screens and graph view
- Map: nodes labelled with origin chip (VALIO / STORY / REAL / LIVE). Edge style by trust. Story nodes marked FICTIONAL in a legend.
- Risk inbox: each item shows source URL, origin, and `fetched_at`.
- Alternatives: three story dairies (fictional, labelled) and any opted-in real company.
- Proposal, approval tray, audit timeline.
- Data panel (for judges): row counts per origin and the golden-path test status.

## 7. Demo script (4 min)
- 0:00–0:30 Hotel map. Legend: Valio supply base, story, real. Say what is fictional and what is real.
- 0:30–1:10 "Scan now": Context.dev fetches 5 real domains; new `inferred` edge with quote and URL appears. If live fails, replay of the same fixture is shown and labelled "cached at Fri 18:40".
- 1:10–1:40 Risk alert on the dairy co-op (story layer). Concentration card.
- 1:40–2:10 Supplier confirms `claimed` → `agreed`. Auditor stamps `audited`.
- 2:10–2:40 Alternatives with published price ranges.
- 2:40–3:30 Proposal, manager approval, Valio mock order with idempotency key.
- 3:30–4:00 Audit log with origin per event; show the golden-path test passing.

## 9. Judging-criteria mapping
- **Valio (30%):** a story that uses the synthetic Valio data end to end, with order and approval.
- **Buyer need (20%):** risk, alternatives and price range from the same seeded data.
- **Controls (20%):** origin on every row, fixture provenance, audit log.
- **Exceptions (15%):** golden-path test covers partial stock and substitution from the Valio data.
- **Context.dev (15%):** real fetches with URLs, webhook replay, fixture = real response.
- **Trust/privacy (10%):** RLS, fictional labels, no invented facts about real companies.
- **Bounties:** Aiven (store), Gemini (agents), Codex (seed CLI and tests), CRACI (CI for golden path).

## 10. Risks and cuts
- Cut first: Layer C beyond 10 domains; Exa; Oxylabs; Cala.
- Biggest risk: a real domain changes or blocks the fetch. Mitigation: 25 candidates, 10 needed, fixtures captured Friday.
- Risk: a judge asks whether story companies are real. Mitigation: FICTIONAL legend and the data panel.
- Risk: Valio data format differs from our assumption. Mitigation: loader accepts CSV assumed from brief and maps columns in one file.

## 11. Biggest weakness of this proposal
Seeding is invisible to a judge who only sees the UI, so its value depends on a clear legend and the data panel; a judge may still feel that the story layer is too convenient. The scraped layer is small, so "genuinely live" applies to a handful of companies, not the network.

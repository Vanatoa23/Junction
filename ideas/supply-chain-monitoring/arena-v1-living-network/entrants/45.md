# Entrant 45: Steadyline (lens: deterministic demo reliability)

## 0. Bold bet
Every external call goes through one adapter that returns LIVE, RECORDED or SEEDED data, and the UI badges every fact with its mode, so the demo cannot silently fail and never pretends. The scoring path is pure database logic with no network or LLM, so the headline result is identical online, offline and in rehearsal.

## 1. Summary and name
- **Steadyline**: a living supply-chain network that shows buyers risk warnings and hidden shared upstream producers, built to run on venue wifi or none.
- Live parts are live when the network works, fall back to recorded real responses (with timestamp and URL) when it does not, and are never faked.
- The demo includes a deliberate wifi-cut beat that shows the fallback working.

## 2. Architecture and DB choice
- **Postgres only.** Demo runs on a laptop in Docker Postgres; the same schema and snapshot deploys to Aiven (side bounty). ArcadeDB is rejected: a second store adds a sync failure mode for under 500 nodes.
- **Source adapter** `fetch(source, request)` is the single gateway for Context.dev, Exa, Gemini and Valio.
  - Modes: `live` (3s timeout), `recorded` (last real response in `raw_fetch`, keyed by request hash), `seeded` (fixture).
  - Fallback chain: live, then recorded, then seeded. Each result carries `mode`, `fetched_at`, `source_url`.
  - Circuit breaker: 2 failures in 60s opens the circuit for 5 minutes; ops banner says so.
- **Record mode**: `RECORD=1` stores every live response during rehearsal days.
- Assumptions: all four APIs return storable JSON; Context.dev webhooks need a public URL, so monitors are polled every 60s and webhooks are optional.
- Components: FastAPI, React + Cytoscape.js, Gemini function calling (cached by prompt hash), Valio replay stub.

## 3. Data model and key queries
- `company(id, name, country, kind [registered|unregistered|inferred], domain, sanctions_status, cert_expiry)`
- `edge(id, src_id, dst_id, category, trust [inferred|claimed|agreed|audited], confidence, visibility [private|risk_only|public])`
- `evidence(id, edge_id|company_id, url, quote, mode, fetched_at, raw_fetch_id)`
- `raw_fetch(id, source, req_hash unique, request jsonb, response jsonb, url, fetched_at)`
- `risk_signal(id, company_id, type, score, confidence, path jsonb, mode, status)`
- `order_proposal(id, buyer_id, sku, qty, from_id, to_id, price, reason, status [proposed|approved|rejected|placed], approved_by, valio_order_id)`
- `audit_event(id, ts, actor, action, payload jsonb, mode, prev_hash, hash)`
- `demo_snapshot`: pg_dump of seed state plus recorded `raw_fetch` rows; `make reset` restores it in under 20s.

**Hidden concentration (offline, deterministic)**
```sql
WITH RECURSIVE up(src, node, depth, path) AS (
  SELECT e.src_id, e.src_id, 1, ARRAY[e.dst_id, e.src_id]
  FROM edge e WHERE e.dst_id = $buyer
  UNION ALL
  SELECT up.src, e.src_id, up.depth+1, up.path || e.src_id
  FROM up JOIN edge e ON e.dst_id = up.node
  WHERE up.depth < 4 AND NOT e.src_id = ANY(up.path)
)
SELECT node AS hub, count(DISTINCT src) AS n_direct FROM up
WHERE depth >= 2 GROUP BY node HAVING count(DISTINCT src) >= 2;
```
- Visibility enforced in the query layer: buyers never receive another company's edges; a hub name appears only if its edge is `public` or `agreed`.
- Path trust = weakest edge; path confidence = minimum edge confidence.

## 4. Agents (discovery, monitoring, procurement)
All three call tools only through the adapter, so each run records its own mode.
- **Discovery** (Gemini, Context.dev extract, Exa news). Page schema: `{upstream_sources: [{name, domain, product, quote, url}]}`. Writes `inferred` edges with evidence; rejects items without URL and quote. Confidence 0.5, +0.2 for category quote, +0.2 for two agreeing pages, capped at 0.9.
- **Monitoring** (polls Context.dev monitors every 60s). Re-extracts only changed pages, diffs against last `raw_fetch`, writes `risk_signal`.
- **Procurement** (Gemini tool-use over Valio catalogue, price, availability, `hub_check`). Writes `order_proposal`; order endpoint refuses unless `status=approved`. Partial availability falls through to the next upstream-disjoint alternative.
- Gemini reasons fall back to a template sentence on cache miss, so no screen is ever empty.

## 5. Risk engine
Scores are computed in SQL and Python; the LLM writes text only.
- **Concentration (hero)**: hub query; signal at score ≥ 0.4, where `score = (n_direct - 1) / (direct_in_category - 1) * trust_factor` (inferred 0.6, claimed 0.8, agreed or audited 1.0).
- **Regulatory**: seeded sanctions CSV (public list, normalized names); CSDDD and EUDR certificate expiry; Context.dev cert pages.
- **Geopolitical, financial, live events**: Exa news with date filter, shown with URL; static country table labelled as assumption.
- **Price premium**: only where both sides publish; flagged above 10% over cheapest upstream-disjoint alternative.

## 6. Screens and graph view
- **Buyer map**: arrows show supply flow; edge colour shows trust (inferred dashed grey, claimed amber, agreed blue, audited green). Each node and edge has a mode badge: LIVE, REC with timestamp, or SEED.
- **Risk detail**: hub, paths, evidence URLs with fetch times, score breakdown.
- **Alternatives**: opted-in suppliers, published price ranges, upstream-disjoint check.
- **Procurement inbox** (Approve/Reject) and **audit log** (hash check).
- **Ops panel** (judge-visible): source status, "Run live now". Live clicks show a request ID.

## 7. Demo script (about 4 min)
- 0:00 (20s): Ops panel pre-check: every source live or marked recorded, stated aloud.
- 0:20 (40s): Buyer map; banner "3 dairy suppliers, effectively 1 source"; hub detail with URLs and fetch times.
- 1:00 (50s): "Run live now" on a supplier sourcing page. Live: new dashed edge with URL and quote. Not live: the adapter replays the recorded run, badge reads REC with its original time. Either way, labelled truthfully.
- 1:50 (30s): Deliberate wifi cut. Circuit opens, banner changes, map keeps working on recorded data, a monitor alert still appears.
- 2:20 (40s): Two upstream-disjoint opted-in alternatives with price ranges; a third auto-rejected for sharing the hub.
- 3:00 (30s): Supplier confirms edge (claimed to agreed); auditor stamps one edge audited.
- 3:30 (40s): Procurement proposal, manager approves, Valio order placed (labelled), audit chain verified.

## 9. Judging-criteria mapping
- **Valio (30/20/20/15/15)**: end-to-end order through the mock; partial-availability and substitution responses exercised; approval gate and hash-chained audit; JSON and OpenAPI contracts.
- **Context.dev (15%)**: live extraction in the core flow; monitor polling for change over time; latency and fetch times on screen; URL on every inferred fact.
- **Feasibility (25%)**: one database, deterministic scoring, a fallback per external call, a rehearsed offline drill.
- **Trust and privacy (10%)**: visibility enforced in queries.
- **Concreteness (10%)**: schemas, SQL, score formula, timings.
- **Bounties**: Gemini (main LLM), Aiven (snapshot and read-mostly deploy), CRACI (replay tests in CI). Codex only if genuinely used. Cala skipped.

## 10. Risks and cuts
- **Cut order**: Exa, geopolitical table, Context.dev webhook, supplier mobile view, Cala, Oxylabs, Modal/Verda.
- **Risks**: recordings drift from schemas (freeze at M2); demo looks staged (timestamps, request IDs, judge-triggered live run); laptop failure (snapshot restores on a second machine in under 20s).
- **Data risk**: hubs below 0.5 confidence stay in the ops view.

## 11. Biggest weakness of this proposal (be honest)
Honest REC badges make the demo more trustworthy but less dramatic, and judges may read them as weakness. The reliability machinery (adapter, recordings, snapshots, CI replay) takes engineering time from agents and UI, so the flashiest live features are the first to be cut.

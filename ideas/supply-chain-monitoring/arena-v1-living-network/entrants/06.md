# Entrant 06: Two Stores, One Audit Trail (lens: Hybrid store)

## 0. Bold bet
Each datum lives where its query pattern and legal duty live. ArcadeDB answers "who depends on whom, how many tiers up, with what trust"; Aiven Postgres answers "who may see what, who approved what, what happened". Every graph edge projects from a Postgres event, so the graph can be rebuilt from the audit trail.

## 1. Summary and name
- **Tierline** (working name). A living supply network that grows as companies declare links and agents discover them. Buyers get risk alerts, opt-in alternatives and price ranges; a manager approves each switch; the order goes through the Valio mock API; every step is hash-chained.
- Assumptions: ArcadeDB runs in Docker on the demo laptop, with a backup VM. Aiven Postgres is reachable from all laptops.

## 2. Architecture and DB choice
- Components: React app; Fastify API; Postgres on Aiven (system of record); ArcadeDB (graph plus vectors); projector worker; agents as API jobs using Gemini function calling; Context.dev; Valio mock client.
- Placement:
  - Users, sessions, companies, edge events (actor, time, source URLs): Postgres. Edge events are append-only.
  - Current edge state (trust, confidence, owner, sources): ArcadeDB, derived from events. Traversal needs it.
  - Risk signals with URL and expiry: Postgres. `risk_score` is copied onto the graph vertex for propagation.
  - Opt-in flags, published prices, orders, approvals: Postgres. Commercial and legal records stay out of the graph.
  - Product embeddings and vector search: ArcadeDB, filtered against Postgres.
  - Audit log: Postgres `audit_event` with `prev_hash` and `hash`. A trigger blocks UPDATE and DELETE.
- Sync rule: Postgres first, graph second. Each Postgres write also inserts an `outbox` row in the same transaction. The projector polls every second (`FOR UPDATE SKIP LOCKED`) and applies idempotent `MERGE` statements to ArcadeDB. Target lag is under 2 seconds. `reproject --all` replays `edge_event` for recovery. The graph never writes back to Postgres.

## 3. Data model and key queries
- Graph (ArcadeDB, Cypher):
  - `Company {id, name, country, industry, status, risk_score}`
  - `Product {id, category, embedding VECTOR(768)}`
  - `SUPPLIES` (supplier to buyer) `{id, trust in [inferred, claimed, agreed, audited], confidence, sources[], owner_id}`
  - `OFFERS` (Company to Product)
- Postgres: `companies`, `users`, `edge_event`, `listing_consent(company, product, opted_in, price_min, price_max, published)`, `risk_signal`, `orders`, `order_approval`, `outbox`, `audit_event`.
- Visibility is enforced in the API. Buyer views contain only its own edges, risk alerts, opt-in alternatives, published prices and aggregates.
- Upstream traversal:
  ```
  MATCH p=(u:Company)-[:SUPPLIES*1..4]->(b:Company {id:$buyer})
  WHERE ALL(e IN relationships(p) WHERE e.confidence >= $minConf)
  RETURN u.id, u.name, length(p) AS tier, [e IN relationships(p) | e.trust]
  ```
- Hidden concentration (shared upstream of two or more direct suppliers):
  ```
  MATCH (d:Company)-[:SUPPLIES]->(b:Company {id:$buyer})
  MATCH (u:Company)-[:SUPPLIES*1..3]->(d)
  WITH u, collect(DISTINCT d.id) AS direct WHERE size(direct) >= 2
  RETURN u.id, u.name, direct
  ```
- Blast radius: `MATCH (f:Company {id:$failed})-[:SUPPLIES*1..3]->(c:Company) RETURN c.id, count(*)`.
- Alternatives: ArcadeDB vector neighbours of the product (assumed `vectorNeighbors` syntax, to verify), then Postgres `listing_consent WHERE product_id = ANY($ids) AND opted_in AND published`.
- Aggregates: count of distinct buyers in the same industry using a supplier. Returned only if at least 5 (k-anonymity).

## 4. Agents (discovery, monitoring, procurement)
- **Discovery.** Input: seed names, Valio supplier list. Tools: Context.dev `company.enrich`, `web.extract`, `news.search`. Output: `edge_event kind=discovered`, trust `inferred`, confidence, source URLs. Validation: claims without a returned URL are dropped; confidence below 0.6 is hidden. Unregistered companies get an invite row (no email sent).
- **Monitoring.** Input: watched URLs per company (news, recall pages, a dummy sanctions list). Tools: Context.dev monitors with webhook, plus a 15-minute poll fallback. Gemini classifies the change into a risk type. Output: `risk_signal` with URL, severity from a fixed rubric, and expiry. The demo triggers a real change on a dummy producer's page.
- **Procurement.** Tools: `get_alternatives`, `check_price_availability` (Valio), `draft_switch`, `place_order`. The agent emits a proposal with price delta, lead time and a reason chain. `place_order` is a hard gate in the API: it rejects any call without an `order_approval` row. The guardrail is code, not prompt.

## 5. Risk engine
- Deterministic scoring; the LLM classifies text and writes explanations only.
- Geopolitical: static country table (dummy values) plus news signals.
- Regulatory: sanctions name match, certification expiry from Valio sustainability data, CSDDD/EUDR attribute flags.
- Concentration: single-source is one incoming edge for a product. Hidden shared upstream uses the query in section 3.
- Financial: keyword and LLM classification of news (layoffs, insolvency).
- Live events: recalls, strikes, outages from monitors.
- Price premium: buyer price minus the cheapest opted-in published price, only when both are published.
- Propagation: `upstream_risk = max over paths of risk x 0.8^tier`. Each alert stores its path for explanation.

## 6. Screens and graph view
- Buyer dashboard: supply map plus alert list.
- Alert detail: signal, source links, upstream path, alternatives with price ranges.
- Procurement proposal with tool-call trace, then approval.
- Order confirmation and audit trail with a verify-chain button.
- Supplier: confirm edge (`claimed` to `agreed`), publish prices.
- Auditor: stamp `audited`.
- Live discovery panel: shows each Context.dev call and its URL.
- Graph view (Cytoscape.js): arrows point to the buyer. Line style encodes trust (dashed inferred, dotted claimed, solid agreed, bold audited); node colour encodes risk. Edges show confidence and sources on click. Other companies' internal edges are hidden.

## 7. Demo script (about 4 minutes)
- 0:00 Hook: "Who is upstream of your milk?"
- 0:20 Hotel login. Supply map, Valio at centre.
- 0:50 "Find upstream" runs Context.dev on a pre-chosen public page. Inferred dairy node appears at 0.7 confidence with URL.
- 1:20 Monitor fires on the dummy producer's page. Risk alert: shared upstream plus live event.
- 1:50 Alert detail: Cypher path, two opted-in alternatives with price ranges.
- 2:20 Supplier confirms edge: `claimed` to `agreed`, live.
- 2:50 Procurement proposes switch with tool trace. Manager approves.
- 3:15 Valio mock order. Partial availability triggers substitution.
- 3:45 Audit chain verified. Competitor map hidden; "used by 7 hotels in region" aggregate.
- 4:10 Auditor stamps `audited`.

## 9. Judging-criteria mapping
- Valio (30%): end-to-end mock order, code-enforced approval gate, hash-chained audit.
- Buyer need (20%): alerts, alternatives with price ranges, substitution.
- Exceptions (15%): partial availability, substitution, lead times.
- Open standards (15%): openCypher, Postgres, OpenAPI.
- Context.dev (15%): live extraction, monitor webhook, URLs on screen.
- Trust and privacy (10%): trust on every edge, API-enforced visibility, k of at least 5.
- Bounties: Gemini, Aiven, Codex, CRACI. Cala excluded.

## 10. Risks and cuts
- Cut first: ArcadeDB vector search, moved to pgvector on Aiven (assumed available). Then webhooks, moved to polling. Then Oxylabs, Modal, Cala.
- Biggest technical risk: ArcadeDB Cypher dialect and deployment. Mitigation: day-one query spike. Fallback: Postgres recursive CTE over a mirrored `edge_current` table.
- Projection lag: force a synchronous flush before the demo beat. Context.dev latency: cache the live response and show its timestamp.

## 11. Biggest weakness of this proposal
Two stores mean two operational surfaces and custom sync code for a 48-hour team. An outbox ordering bug would show a wrong trust level on screen. The graph beats a recursive CTE mainly at this demo's four-tier depth, so the hybrid is justified by the story, not by scale.

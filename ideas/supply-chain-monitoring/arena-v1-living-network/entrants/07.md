# Entrant 07: Gemini Tool-Contract Agents (lens: Gemini function-calling agent design)
## 0. Bold bet
Every agent is a Gemini function-calling loop whose only write path is a typed proposal tool, so the LLM never touches the graph, prices or orders directly. Every final model output is schema-constrained JSON, stored verbatim, which makes the proposal log the Valio audit trail.

## 1. Summary and name
Name: **Tessera**. A hotel chain logs in, sees its supply map centred on Valio Aimo, receives a risk alert on an upstream dairy producer, compares visible alternatives, approves a switch proposed by the procurement agent, and the order goes to the Valio mock API. Everything is logged.
Assumptions: Gemini model `gemini-2.5-flash` (verify model ID on day 1); the `google-genai` Python SDK.

## 2. Architecture and DB choice
- Frontend: React + Cytoscape.js, three role views (buyer, supplier, auditor).
- Backend: FastAPI. One `agent_runner` module wraps Gemini; each agent is a config (system prompt, function declarations, output schema).
- Tool adapters (thin, deterministic): `ctx_*` (Context.dev SDK), `exa_*` (search fallback), `valio_*` (mock REST), `db_*` (Postgres).
- **DB: Postgres on Aiven** as system of record (companies, edges, trust, visibility, proposals, approvals, audit log). Aiven also earns the hosting bounty.
- **ArcadeDB: stretch only.** Upstream traversal runs as `WITH RECURSIVE` in Postgres (3-4 hops is trivial at demo size). ArcadeDB Cypher is a flagged swap if M2 is ahead of schedule. Reason: one database for four engineers to debug.
- Valkey, Kafka, ClickHouse: not used.

## 3. Data model and key queries
Tables:
- `company(id, name, country, industry, registered bool, visible_opt_in bool, source_urls jsonb)`
- `edge(id, from_id, to_id, product_category, trust enum[inferred,claimed,agreed,audited], confidence numeric null, sources jsonb, published_price jsonb null)`
- `edge_confirmation(edge_id, party_id, role enum[supplier,buyer,auditor], at)`. `agreed` is set when both parties confirm. `audited` is set by an auditor row. Agents can never write `agreed` or `audited`, enforced by a state-machine check in `db_*`.
- `risk_signal(id, company_id, type, severity, confidence, evidence jsonb, status, detected_at)`
- `proposal(id, kind enum[edge_inferred,risk_alert,switch_order], payload jsonb, status enum[pending,approved,rejected,executed], decided_by, decided_at)`
- `agent_run(id, agent, model, input jsonb, tool_calls jsonb, output jsonb, tokens, ts)`
- `audit_log(id, actor, actor_type enum[human,agent,system], action, args jsonb, result jsonb, ts)`, append-only (revoke UPDATE/DELETE).

Visibility is enforced in SQL views, not in the UI. `v_buyer_risk` returns risk signals only for companies upstream of the buyer. `v_alternatives` returns only `visible_opt_in` suppliers with a published price. `v_industry_usage` returns counts with a k>=5 threshold.

Queries:
- Upstream (depth 4): `WITH RECURSIVE up AS (SELECT from_id, to_id, 1 d FROM edge WHERE to_id=$1 UNION ALL SELECT e.from_id, e.to_id, up.d+1 FROM edge e JOIN up ON e.to_id=up.from_id WHERE up.d<4) SELECT DISTINCT from_id FROM up;`
- Hidden concentration: the same recursion seeded from each direct supplier, then `GROUP BY upstream_id HAVING COUNT(DISTINCT via_supplier) >= 2`.
- Blast radius: recursion downstream from a failed supplier; count buyers and their weekly volume.
- Alternatives: `SELECT ... FROM v_alternatives WHERE product_category=$cat AND company_id NOT IN (risky) ORDER BY published_price->>'min'`.

## 4. Agents (discovery, monitoring, procurement)
Shared rules:
- Function calling with `toolConfig.functionCallingConfig` mode `ANY` and `allowedFunctionNames` per agent. Gemini only sees its allowlist.
- Tool calling and JSON output are not mixed in one request (assumption: verify on day 1). The loop runs with tools until the model stops calling, then a second call with `responseMimeType: application/json` plus `responseSchema` turns the transcript into the typed result.
- Every run is written to `agent_run`.
- System prompt rules: cite only URLs returned by tools; if a tool returns nothing, emit `no_data`; never invent companies.

Discovery (inputs: region, sector seeds; tools below).
```json
{"name":"propose_edge","description":"Record a candidate supplier link as an INFERRED proposal. Creates no graph edge until a human confirms.",
 "parameters":{"type":"OBJECT","properties":{
   "supplier_name":{"type":"STRING"},"buyer_name":{"type":"STRING"},
   "product_category":{"type":"STRING","enum":["dairy","meat","produce","dry_goods","beverages","packaging"]},
   "confidence":{"type":"NUMBER","description":"0-1"},
   "source_urls":{"type":"ARRAY","items":{"type":"STRING"},"minItems":1}},
 "required":["supplier_name","buyer_name","product_category","confidence","source_urls"]}}
```
- Other tools: `ctx_news_search(query, since_iso, limit<=10)`, `ctx_company_enrich(url)`, `ctx_extract(url, schema_name)`, `ctx_company_lookup(name)` (dedupe before insert).
- Output schema: `{candidates:[{supplier,buyer,product_category,confidence,sources:[{url,quote}]}]}`.
- Validation: at least 2 independent source URLs for confidence >0.7, otherwise the proposal is capped at 0.6. Below 0.4 is dropped.

Monitoring (scheduled plus Context.dev monitor webhooks).
- Tools: `ctx_monitor_create(url, css_selector)`, `ctx_news_search`, `sanctions_check(name, country)` against a seeded EU consolidated list download (assumption), `valio_get_certificates(supplier_id)`.
- Output: `{signals:[{company_id,type enum[geo,reg,conc,fin,event,price],severity_hint 0-1,summary,evidence_urls}]}`.
- Gemini classifies. The score is computed in code (section 5).

Procurement (inputs: risk alert; tools below).
- Tools: `valio_search_products(category, filters)`, `valio_check_availability(sku, qty, delivery_date)`, `get_published_prices(supplier_id)`, `propose_switch(current_sku, alt_sku, qty, reason, evidence_refs)`.
- There is no order tool in the agent's allowlist. `place_order` exists only behind the approval endpoint.
- Output: `{recommendation:{current_sku,alt_sku,price_delta_pct,delivery_days,reason,evidence_refs[]}|null, requires_approval:true}`.

Human approval: the proposal shows the diff, price delta and evidence. Approve calls `valio_place_order` with the stored payload (no LLM in the path) and writes `audit_log`.

## 5. Risk engine
Gemini classifies. Code scores.
- Geopolitical: seeded country-risk table plus news classification. Severity = table value.
- Regulatory: sanctions hit (severity 1.0). Certificate expired or missing for forest-risk categories (EUDR list: cocoa, soy, palm, beef) and CSDDD-relevant suppliers flagged.
- Concentration: single-source = one direct supplier in a category. Hidden shared upstream = recursive query from section 3.
- Financial: news classified as layoffs, insolvency or funding stress.
- Live events: Context.dev monitor on recall or strike pages, classified by Gemini.
- Price premium: `(buyer_price - min_published_alt) / min_published_alt`, only when published.
- Score = type_weight x confidence x recency_decay(14 days). Alert at >=0.6. Every alert needs at least one evidence URL, otherwise it is not created.

## 6. Screens and graph view
1. Buyer home: Valio at centre, own suppliers, alert count.
2. Supply map: direction arrows, edge style by trust (dashed = inferred, grey = claimed, solid = agreed, gold double = audited), red halo = risk, grey = visible alternatives.
3. Risk alert: severity, evidence URLs with timestamps, hidden-concentration panel.
4. Alternatives: price ranges (published only), delivery days, sustainability badge, anonymised industry usage.
5. Proposal inbox: diff, Gemini tool-call trace, Approve or Reject.
6. Order result and audit timeline.
7. Supplier view: confirm edge (claimed to agreed). Auditor view: stamp audited.

## 7. Demo script (4 min)
- 0:00-0:20 Hook: "Who is behind your supplier?"
- 0:20-0:45 Log in as hotel chain; supply map.
- 0:45-1:20 Click Scan. Discovery agent runs live Context.dev news search; source URLs stream into the panel; a new dashed edge appears at confidence 0.78.
- 1:20-1:50 Risk alert on upstream dairy co-op (seeded monitor event). Evidence links.
- 1:50-2:20 Hidden concentration: three suppliers share one upstream. Alternatives with price ranges.
- 2:20-2:50 Procurement proposal; Gemini tool-call trace on screen.
- 2:50-3:15 Manager approves; order ID from Valio mock API.
- 3:15-3:35 Supplier tab confirms edge: claimed to agreed.
- 3:35-3:50 Auditor stamps: audited.
- 3:50-4:10 Audit timeline: every tool call, args, model and output.
Fallback: pre-recorded video; cached Context.dev response if the live call fails.

## 9. Judging-criteria mapping
- Valio (30%): order via mock API only after approval; agent allowlist; audit timeline; partial-availability handling in procurement tool.
- Feasibility (25%): one DB, Gemini only classifies and proposes, cached fallback.
- Context.dev (15%): discovery, monitors and extraction in the core flow; live run on stage.
- Trust and privacy (10%): SQL views; state-machine trust.
- Concreteness (10%): schemas above.
- Gemini bounty (main LLM). Aiven (Postgres hosting). CRACI optional, about an hour of CI setup. Cala and Codex skipped.

## 10. Risks and cuts
- Cut first: ArcadeDB, Cala, Oxylabs, Modal, Codex.
- Risk: Gemini tool-call and JSON schema interaction (mitigated by the two-call pattern). Latency: pre-warm and record one full run.
- Risk: hallucinated suppliers (mitigated by the two-source rule and the URL allowlist).
- Risk: sanctions data availability; use a seeded list and label it.

## 11. Biggest weakness of this proposal
It depends on Gemini behaving correctly under a tight schedule. The two-call pattern adds latency and a failure point. The graph view is simpler than a bespoke design, and real discovery depth is limited by Context.dev rate limits during the demo.

# Entrant 01: SupplyMandate, an agent that buys inside a mandate and always asks a human to sign (lens: Valio prize maximalist)

## 0. Bold bet
Valio's "Trusted Trade Agents" is won by proving a buyer can hand an agent a bounded mandate and get autonomy, exception handling and a tamper-evident log, while a human still approves the order. The graph exists only to give the procurement agent better facts (upstream risk, visible alternatives, published prices), so every graph feature is judged by whether it improves an agent proposal.

## 1. Summary and name
- **SupplyMandate**: a hotel chain sets a mandate (categories, max order value, origin rules, max supplier risk, max price premium, expiry). Agents watch its supply network and propose compliant orders through Valio's API. A manager approves each order in one tap. Every step is logged.
- The graph is the substrate, not the headline.
- Assumptions: **A1** Valio mock exposes catalogue, price, availability, delivery-slot and order endpoints. If the shape differs, we fix the adapter; if the mock is unusable, we write a 150-line local mock by Friday 22:00.

## 2. Architecture and DB choice
- **Postgres on Aiven** as the single store (also earns the Aiven bounty). The graph is an edge table queried with recursive CTEs. At demo scale (about 2,000 nodes) this is fast enough. **A2**: pgvector is available on Aiven Postgres; fallback is category tags for alternatives.
- **ArcadeDB: rejected.** A second engine and query language costs setup time we do not have. Revisit only if a one-hour spike shows it runs in Docker without fuss.
- Components: web app (React, Cytoscape.js for the graph); API (Node/Express or FastAPI); agent runtime (Gemini function calling, one loop per agent, typed tools); Valio adapter; Context.dev client (SDK, monitors and webhooks); event log.
- Flow: Context.dev monitor or discovery → ingestion → risk engine → `risk_signal` → procurement agent → `proposal` (status `pending`) → manager approves → order service → Valio order API → audit.
- **Hard rule:** the LLM never has the order tool. Only the order service can call Valio's order endpoint, and only with an approval row whose payload hash matches the proposal. The Valio idempotency key is the proposal ID.

## 3. Data model and key queries
- `company(id, name, country, domain, industry, status: unregistered|registered, opted_in_alt bool)`
- `edge(id, from_id, to_id, scope_sku_cat, trust: inferred|claimed|agreed|audited, confidence, sources jsonb, confirmed_from, confirmed_to, audited_by, updated_at)`
- `edge_event(id, edge_id, type, actor, payload, prev_hash, hash, at)`: append-only, hash-chained. Used for trust transitions and all agent actions.
- `risk_signal(id, company_id, type, severity 0-100, confidence, sources jsonb, observed_at, expires_at)`
- `price_publication(company_id, sku, price_min, price_max, currency, published bool)`
- `mandate(id, buyer_id, categories, max_order_eur, allowed_origins, max_risk, max_premium_pct, valid_until, active)`
- `proposal(id, buyer_id, trigger_signal_id, lines jsonb, total_range, quote_expires_at, status: pending|approved|rejected|placed|failed, checks jsonb, rationale, payload_hash)`
- `approval(id, proposal_id, approver, decision, payload_hash, at)`
- `agent_run(id, agent, model, tool_calls jsonb, sources jsonb, started_at, ended_at)`
- **Visibility** is enforced in the API layer by one function `visible(viewer, object)`, backed by SQL views. A buyer sees: its own mandate and proposals; risk signals on its upstream set; alternatives only where `opted_in_alt`; industry usage as aggregates with k≥5 (otherwise hidden); prices only where `price_publication.published`.
- **Queries**
  - Upstream (depth ≤4): `WITH RECURSIVE up AS (SELECT from_id AS id, 1 AS d FROM edge WHERE to_id=$1 UNION ALL SELECT e.from_id, up.d+1 FROM edge e JOIN up ON e.to_id=up.id WHERE up.d<4) SELECT DISTINCT id, min(d) FROM up GROUP BY id;`
  - Hidden concentration: the same traversal, grouped by ancestor, `HAVING count(DISTINCT direct_supplier) ≥ 2`.
  - Blast radius: the same traversal run downward from a failing supplier, returning buyers and SKUs.
  - Alternatives: `company` joined to `price_publication` where `category=$cat AND opted_in_alt AND published AND id NOT IN (risky set)`, ordered by `price_min`.

## 4. Agents
- **Discovery.** Inputs: Valio supplier list, supplier domains. Tools: `ctx.company_enrich(domain)`, `ctx.news_search(q)`, `ctx.extract(url, schema)`. Output: candidate companies and `inferred` edges with confidence and source URLs. Validation: no source, no edge. Unregistered nodes get an invite queued.
- **Monitoring.** Context.dev monitors on supplier domains and news queries push webhooks (**A3**: reachable via tunnel; fallback is 60-second polling). Gemini classifies the change into a risk type with structured output. Rule: a signal needs at least one source URL, and a confidence below 0.5 is shown but does not trigger procurement.
- **Procurement.** Triggered by a signal at severity ≥70 or a premium alert. Tools: `valio.search(q)`, `valio.availability(sku, date)`, `valio.quote(lines)` (fixed price, TTL 30 min), `graph.alternatives`, `graph.upstream`, `mandate.check`, `propose(lines)`. Max 8 tool calls. No order tool.
  - Exceptions: partial availability → split the proposal or substitute a same-certification SKU; delivery slot unavailable → next slot; price moved → re-quote, and re-approval if the premium rises; nothing viable → escalate to a human with three options.
- **Guardrails:** per-agent tool allowlist, mandate checked on every proposal, every call written to `agent_run` with args and result hash.

## 5. Risk engine
Score = base × confidence × recency decay (half-life 30 days). Upstream risk propagates with a 0.8 factor per hop.
- **Geopolitical:** curated country table with cited index, plus `ctx.news_search` for conflict or trade-restriction terms.
- **Regulatory:** sanctions name match against OpenSanctions (**A4**: an offline CSV, fuzzy ≥0.9). EUDR: deforestation-relevant categories (cocoa, soy, palm, beef, wood) without a declared statement. CSDDD: `ctx.extract` on the supplier's policy page. Expired certificates from Valio sustainability fields.
- **Concentration:** single-source count per category, plus the hidden shared-upstream query.
- **Financial:** `ctx.news_search` for layoffs, insolvency, funding-round keywords.
- **Live events:** recall, strike and outage monitors via webhook.
- **Price premium:** (price − min published alternative) / min, only where prices are published.

## 6. Screens and graph view
1. **Buyer home:** mandate status, active alerts, pending approvals.
2. **Supply map:** graph view (below).
3. **Risk detail:** signal, confidence, clickable source URLs with timestamps, affected SKUs, upstream path.
4. **Proposal review:** old vs new lines, price range, delivery slot, mandate checks table (pass/fail per rule), rationale, Approve / Reject / Edit.
5. **Agent timeline:** tool calls, sources, approvals, and "hash chain verified" badge.
6. **Supplier portal:** confirm edge (claimed → agreed), publish prices, opt into alternatives.
7. **Auditor page:** stamp edge as audited (simulated auditor account).
- **Graph view:** buyer at the right, arrows point toward it (upstream on the left). Node colour = max risk (green/amber/red). Dashed border = unregistered. Edge style = trust: dotted `inferred`, solid thin `claimed`, solid thick `agreed`, double `audited`. Edge label shows confidence. Clicking a red node shows the blast radius.

## 7. Demo script (4 min)
- **0:00–0:20** Hotel sets mandate: "≤€X per order, EU origin, supplier risk <70, premium ≤5%."
- **0:20–0:50** Supply map: Valio Aimo centre, upstream dairy co-op via a `claimed` edge. Trust styles explained.
- **0:50–1:20 LIVE.** "Run monitors now": Context.dev pulls fresh news for the co-op. A new signal appears with three clickable source URLs and timestamps. If live results are thin, a seeded item is shown and labelled as seeded, not passed off as live.
- **1:20–1:40** Signal triggers procurement. The tool-call timeline streams.
- **1:40–2:20** Proposal: one alternative is an opted-in supplier with a published price range. Exception: one SKU partially available, so the agent substitutes a same-certification SKU. Delivery slot moved. Checks table passes; premium 4%, within mandate.
- **2:20–2:50** Manager approves. Order placed via Valio mock with a reference. Hash chain verified.
- **2:50–3:20** Supplier confirms edge on their phone (claimed → agreed). Auditor stamps audited.
- **3:20–3:45** Privacy panel: "used by 7 of 40 industry peers"; no peer names.
- **3:45–4:00** Close: Context.dev, Gemini, Aiven, MCP.

## 9. Judging-criteria mapping
- **Valio end-to-end (30%):** scripted mandate → signal → proposal → approval → order.
- **Buyer need (20%):** a manager sees risk, alternatives and a checks table, and approves in one tap.
- **Autonomy and controls (20%):** mandate, tool allowlist, approval bound to payload hash, idempotency key, hash-chained audit.
- **Exceptions (15%):** partial availability, substitution, slot change, re-quote, escalation.
- **Open standards and path (15%):** tools exposed as an MCP server, JSON Schema for mandates, OpenAPI-style adapter. Production path is named, not built.
- **Context.dev:** monitors, enrichment, news search and extraction in the core loop, with visible URLs and latency shown.
- **Gemini:** all three agents. **Aiven:** hosted Postgres. **CRACI:** GitHub Actions with SBOM (about 30 min). **Codex:** claimed only if used in development and logged. **Cala:** skipped.

## 10. Risks and cuts
- A1 wrong: adapter plus local mock by Friday 22:00.
- A3 webhooks unreachable: polling fallback. Cached results are shown with their real timestamps.
- Gemini latency or quota: pre-warm, cache the last run, log token use.
- Demo "live" drifts into staged: keep one real run and say so.

## 11. Biggest weakness of this proposal
Maximalism on Valio takes effort from the graph and discovery. The "living network" may look like a seeded map with one live feed, and judges weighting the trust and privacy model may find it thin. The approval UI can also read as a standard CRUD app unless the proposal review is polished.

**Assumptions:** A1 Valio endpoints as described. A2 pgvector on Aiven. A3 Context.dev webhooks reachable via tunnel. A4 OpenSanctions CSV available offline.

# Entrant 37: Pinline (lens: Geography)

## 0. Bold bet
Pinline makes the map the primary surface: a supply network is first a set of places, lanes and chokepoints, and geopolitical and logistics risk only become legible when overlaid on where goods physically move. The graph stays as a linked side panel for trust levels and concentration, so the buyer gets both views without a second screen. It wins on demo clarity (a judge sees a risk move across Europe in seconds) and on the 20% buyer-need criterion, since a Helsinki wholesaler's buyer reasons about origin, lanes and lead time first.

## 1. Summary and name
- Name: **Pinline**.
- The hotel chain logs in and sees a map of Valio's supply: pins for sites, lanes for shipments, and country and chokepoint risk shaded on the basemap. A news event in a dairy-exporting region lights up the lane and the affected pin. The monitoring agent turns it into a risk alert with source URLs. The procurement agent proposes an opted-in alternative within a lead-time ring, with a published price range. A manager approves, the Valio mock API places the order, and every step is logged.
- Assumptions: the Valio mock API returns site or warehouse coordinates and lead times (label: assumption; if not, we seed them). Sea lanes are drawn as straight or waypoint polylines, not real routes. Country risk scores are hand-set for demo countries.

## 2. Architecture and DB choice
- **Postgres on Aiven** as the single store (Aiven bounty). Use PostGIS if Aiven offers it (assumption); otherwise store lat/lon and use haversine in SQL. Demo scale is small, so either works.
- **ArcadeDB not used.** Its geo support is not a feature the brief lists, and Docker setup is a risk we do not need.
- **Map basemap is local**: Natural Earth GeoJSON shipped with the repo, rendered with Leaflet. No tile server or API key, so venue Wi-Fi cannot break the demo. This is the single most important reliability decision here.
- Components: React + Leaflet (map) + Cytoscape.js (graph panel, linked); FastAPI; Python agents on Gemini function calling; Context.dev SDK for extraction, news search and monitors with webhook; Valio mock client; one worker for scheduled scans.
- Flow: Context.dev news monitor (filtered by country or region) → webhook → `source_event` → monitoring agent geo-tags and classifies it → `evidence` + `geo_risk` / `risk_signal` → risk engine → map layer refresh and alert.

## 3. Data model and key queries
- `company(id, name, country_iso, lei, registered, sanctions_hit)`.
- `site(id, company_id, name, lat, lon, country_iso, region_code, commodity[])`. Sites carry the geography; companies are the legal owners.
- `supply_edge(src_site, dst_site, src_company, dst_company, category, trust enum{inferred,claimed,agreed,audited}, confidence, visibility enum{private,aggregate,opted_in}, lane enum{road,sea,rail,air}, lead_time_days, price_min, price_max null unless published)`.
- `route_point(id, name, kind{chokepoint,port}, lat, lon, polygon jsonb)`, for Suez, Hormuz, Bosporus, Baltic and North Sea ports.
- `geo_risk(region_code, kind{geopolitical,trade,strike,outage}, score, valid_from, valid_to, evidence_ids[])`.
- `evidence(id, subject_type, subject_id, source_url, snapshot_sha256, retrieved_at, extractor, confidence)`.
- `audit_event(id, ts, actor, action, payload jsonb, prev_hash, hash)`.
- **Trust enforcement**: claimed→agreed needs a counterparty confirm event; agreed→audited needs a simulated auditor event. A DB trigger rejects other transitions.
- **Visibility enforcement**: buyer reads go through views only. `v_buyer_map` (sites and lanes of the buyer's own chain plus open risks), `v_alternatives` (opted_in, price visible only if published), `v_industry_agg` (suppressed under 5 companies). A company's private site list never joins into buyer views.

Queries:
```sql
-- Sites upstream of the buyer that sit inside a flagged region
WITH RECURSIVE up(root, node, depth) AS (
  SELECT src_site, src_site, 0 FROM supply_edge WHERE dst_company = $buyer
  UNION ALL
  SELECT up.root, e.src_site, up.depth+1 FROM up JOIN supply_edge e ON e.dst_site = up.node WHERE up.depth < 4)
SELECT s.* FROM site s JOIN up ON up.node = s.id WHERE s.region_code = $region;

-- Geographic concentration: several direct suppliers share one upstream site
WITH RECURSIVE up(root, node, depth) AS (...same closure...)
SELECT node, COUNT(DISTINCT root) FROM up WHERE depth > 0 GROUP BY node HAVING COUNT(DISTINCT root) >= 2;

-- Lanes crossing a chokepoint under an active event (route exposure)
SELECT e.* FROM supply_edge e JOIN route_point r ON r.id = ANY(e.route_ids)
JOIN geo_risk g ON g.region_code = r.region_code AND g.valid_to > now() AND g.score > 0.5;

-- Alternatives within a lead-time ring of the delivery site
SELECT s.* FROM v_alternatives a JOIN site s ON s.id = a.site_id
WHERE a.category = $cat AND a.lead_time_days <= $max_lead
  AND haversine(s.lat, s.lon, $dlat, $dlon) <= $radius_km
ORDER BY a.price_min NULLS LAST;

-- Blast radius of a failed site (downstream closure)
WITH RECURSIVE down(node, depth) AS (
  SELECT dst_site, 1 FROM supply_edge WHERE src_site = $failed
  UNION SELECT e.dst_site, down.depth+1 FROM down JOIN supply_edge e ON e.src_site = down.node WHERE down.depth < 5)
SELECT DISTINCT node FROM down;
```

## 4. Agents (discovery, monitoring, procurement)
Shared rule: every output is `{claim, source_url, snapshot_sha256, confidence, geo}`. No write without an evidence row. Gemini uses schema-constrained JSON with one retry.
- **Discovery**: Context.dev structured extraction on news and company pages (schema: company, HQ and site addresses, supplier mentions, commodity). Addresses are geocoded from a curated gazetteer file (assumption, shipped with the repo), not a live geocoder. Output: `inferred` sites and edges. Validation: two distinct domains, or one registry source; country on the page must match the site's country; confidence under 0.6 goes to review. No human gate, since inferred is badged.
- **Monitoring**: Context.dev monitors on news filtered by demo country and region, plus each supplier's news page. Webhook to `/hooks/change`, with a scheduled scan as backup. Gemini classifies the event (geopolitical, trade, strike, outage) and assigns a region or chokepoint. Output: `geo_risk` and `risk_signal`, with the URL shown.
- **Procurement**: triggered by a high-severity signal touching a supplier's route or region, or a published premium. It queries alternatives in the lead-time ring, keeps only complete packs, and Gemini writes a rationale citing evidence IDs. A manager approves; the approval row stores the proposal hash. The Valio mock order is posted with `Idempotency-Key = proposal_id` (endpoint shape assumed). If the Valio response is partial, the agent falls back to the second-closest alternative and logs it.

## 5. Risk engine
- Score = severity × confidence × recency decay (half-life 60 days). Map colour uses the maximum score in a region.
- **Geopolitical**: country base score from a hand-set table for demo countries, plus event score from monitors. Labelled as opinion, not an index.
- **Trade and chokepoint**: lane exposure = share of Valio volume on lanes crossing a chokepoint with an active event.
- **Logistics**: lead-time increase on a lane compared with the seeded baseline.
- **Concentration (geographic)**: more than 50% of a category's supplier volume in one region, or the shared-upstream query above.
- **Regulatory**: sanctions match on the company or country; EUDR-relevant origin countries flagged for extra statements (assumption: a country benchmark list we hand-set and label as such).
- **Financial and live events**: news monitors for insolvency, layoffs, recall, strike. Confidence rises with independent sources.
- **Price premium**: only where published; flagged above 15% over the cheapest opted-in alternative.

## 6. Screens and graph view
Verdict: **both, map as the default**. The map answers "where and what is between us and the truck"; the graph answers "who depends on whom and how sure are we". A graph-only view hides geography; a map-only view hides shared upstream concentration and trust levels. We link them with one selection state.
1. **Map**: Leaflet with local basemap. Pins are sites (solid if registered, dashed if unregistered). Lanes show direction with arrows and colour by trust (inferred dotted grey, claimed amber, agreed blue, audited green). Chokepoint pulses red when an event is open. Country shading shows geo risk. Layer toggles on the side.
2. **Graph panel**: same nodes, Cytoscape, selection syncs both ways.
3. **Risk alert**: map zooms to the incident; evidence cards show source URL, snapshot hash, retrieved time.
4. **Alternatives**: opted-in pins within the lead-time ring, with price range badges (published only) and a route preview.
5. **Approval and order**: rationale, compliance pack, approve or reject, Valio order result.
6. **Audit trail** with a "verify chain" button; **supplier portal** for edge confirm and simulated auditor stamp.

## 9. Judging-criteria mapping
- **Valio (30% demo, 20% need, 20% guardrails, 15% exceptions, 15% standards)**: an order only after approval; geographic need (origin, lane, lead time) answered on one screen; approval row, hash chain, idempotency and views; partial availability falls back to the next alternative; GeoJSON and LEI as open identifiers.
- **Context.dev (15%)**: news monitors and extraction drive the map change; URLs visible.
- **Trust and privacy (10%)**: buyer map uses views; aggregates suppressed under 5.
- **Concreteness (10%)**: schema and five queries above.
- **Side bounties**: Gemini main LLM; Aiven Postgres; CRACI; Codex only if used meaningfully. Skip Cala and Oxylabs.

## 10. Risks and cuts
- Cut order: Oxylabs and Cala (never in); sea-route waypoints (straight lines first); Exa; real auditor flow (button); price premium; webhooks (scheduled scan only, one live call kept); graph animation.
- Lane geometry is approximate; say so on screen.
- Context.dev latency or quota: cache last good results and show "cached, 2h ago".
- Gemini JSON drift: schema-constrained output and retry.
- Country scores are opinion; label them.

## 11. Biggest weakness of this proposal
A map can look like a pin demo and lose the "living network" idea, and our lanes are approximations. Multi-tier upstream traversal and concentration sit in the graph panel, which gets less polish. Country risk scores are hand-set, so judges may challenge their basis. Geography helps the buyer, but the supplier-side value (discovery) is thinner than in a graph-first design.

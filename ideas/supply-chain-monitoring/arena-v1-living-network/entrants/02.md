# Entrant 02: Live Wire (lens: real-timeness first)

## 0. Bold bet
A change on a monitored web page becomes a visible network event within about 10 seconds: a Context.dev monitor fires a webhook, the hotel's supply map alerts over SSE, and a procurement proposal appears with source URLs and measured latency on screen. Judges watch the network react to the real web, not a snapshot.

## 1. Summary and name
- Name: **Live Wire**.
- A hotel chain (buys via Valio Aimo) sees its supply map, gets a live alert when a monitored upstream dairy page changes, compares visible alternatives with price ranges, approves a switch proposed by the procurement agent, and the order goes through Valio's mock API with a full log.
- Assumptions to verify in hours 1-2:
  - A1: Context.dev monitors can be created by API with URL, interval and webhook URL; the payload includes the changed content or a diff.
  - A2: An interval of 60 s or less is available.

## 2. Architecture and DB choice
- **Aiven managed Postgres as the only store.** Graph as adjacency tables with recursive CTEs (depth 4 suffices). LISTEN/NOTIFY gives the live push. Aiven bounty counts.
- **ArcadeDB rejected for the core:** a second store costs a day we lack. Stretch only.
- Live path: Context.dev monitor → webhook receiver (Aiven Runtime, fixed public URL) → `change_event` → NOTIFY → SSE → browser.
- Fallback: 60 s scrape of watched URLs with content-hash diffs, same downstream path.
- Agents are worker jobs (Gemini Flash, JSON-schema output) writing `agent_log`. Frontend: React + Cytoscape.js.
- Latency budget: webhook to DB and NOTIFY to UI each under 1 s; classification 3-5 s. UI shows "detected N s after page change".

## 3. Data model and key queries
- `company(id, name, country, industry, registered, opted_in, source_urls)`; `product(id, supplier_id, category, certs, cert_expiry, price_range null)`
- `edge(id, supplier_id, buyer_id, category, trust_level enum[inferred,claimed,agreed,audited], confidence, sources jsonb)`. Direction is supplier to buyer.
- `edge_confirmation(edge_id, party_id, kind enum[declared,confirmed,audited], ts)`. Trust is derived: one declaration = `claimed`; both sides = `agreed`; auditor row = `audited`.
- `risk_signal`, `change_event` (url, received_at, latency_ms, diff), `agent_log` (agent, tool, input_hash, output, ts), `proposal` (from/to product, price range, status, approved_by, idempotency_key)

**Visibility lives in the query layer, not the UI:**
- `own_map(buyer)`: edges where the buyer is a party.
- `supplier_risks(buyer)`: risk signals for upstream companies only, no edge details.
- `alternatives(buyer, category)`: `opted_in` AND `price_public`.
- Aggregates (buyers per supplier in the same industry) returned only when n >= 5.
- Production path: Postgres row-level security by role. The demo has a hotel / public role switch.

- **Upstream traversal:** `WITH RECURSIVE` walk over `edge` from the buyer, depth <= 4, cycle-guarded by a path array.
- **Hidden concentration:** upstream set grouped; flag `count(DISTINCT direct supplier) >= 2`.
- **Blast radius:** same walk forward from the failing company.
- **Alternatives:** category, `opted_in`, `price_public`, cheapest first, limit 5.

## 4. Agents
Shared rules: every tool call writes `agent_log`; every output carries `sources[]` and `confidence`; nothing reaches the graph unvalidated.
- **Discovery.** Input: seed company or Valio supplier list. Tools: Context.dev enrichment, news search, structured extraction. Output: `inferred` edges. Validation: evidence page fetched and contains both names; confidence >= 0.6 writes, else queued. Live run on one real public Finnish page.
- **Monitoring.** Input: `change_event`. Tools: Context.dev scrape, Gemini classification. Output: `risk_signal`, score, SSE event. Validation: `high` needs two sources or one official source; otherwise "watch".
- **Procurement.** Trigger: `high` risk, or price premium above 10% over the cheapest opted-in published alternative. Steps: query alternatives, check Valio availability and lead time, build proposal (substitution if partial), post to approval queue. On approve: order to Valio mock with idempotency key. The server refuses any order call without an approval row.

## 5. Risk engine
- Company score = max(severity weight x confidence) over signals, plus upstream propagation at 0.7 per tier.
- **Live events:** Context.dev monitors on recall and news pages; keyword prefilter, then classifier.
- **Geopolitical:** hand-entered country index (assumption) plus news search.
- **Regulatory:** EU sanctions list (assumption: CSV at build time); certificate expiry; CSDDD flag where no `audited` edge exists. EUDR skipped as not relevant to dairy.
- **Concentration, financial, price premium:** single-source categories and shared upstream from the graph; Context.dev enrichment plus news keywords; premium only where prices are published.

## 6. Screens and graph view
1. **Hotel home:** live alert feed with "detected N s ago"; supply map summary.
2. **Graph:** arrows supplier → buyer, Valio at centre. Solid = agreed, dashed = claimed, dotted = inferred (confidence badge), double = audited. Node colour = risk; the changed node pulses.
3. **Alert detail:** diff, source URL, timestamps (page change, webhook received, UI shown).
4. **Alternatives:** opted-in suppliers, price range, lead time, certificates.
5. **Proposal:** current vs proposed, savings, substitutions, approve or reject.
6. **Supplier inbox:** confirm claimed → agreed. **Auditor console:** stamp audited (simulated).
7. **Audit log:** agent steps, sources, Valio responses.

## 7. Demo script (about 3:40)
- **0:00-0:20** Hook: "A supplier's page changed minutes ago. Watch." Hotel login, graph.
- **0:20-0:50** Live web: monitor list (URL, interval, last check); discovery run result with real URLs.
- **0:50-1:20** We publish a recall notice on the watched dairy page (DEMO company, hosted by us, labelled). Timer runs; alert appears live with source URL and latency (target under 10 s); node pulses.
- **1:20-1:50** Privacy: alternatives with price ranges (published, opted-in only). Role switch to public shows anonymised aggregate and no other buyer's map.
- **1:50-2:30** Procurement proposes a switch; Valio mock returns partial availability; substitution proposed.
- **2:30-2:50** Manager approves; order placed via Valio mock; audit log shows steps, sources, idempotency key.
- **2:50-3:20** Supplier confirms claimed → agreed; auditor stamps audited; edge styles update live on the second screen.
- **3:20-3:40** Replay the saved webhook payload to show repeatability.
- Fallback: replay button with original timestamp, plus backup video.

## 8. 48h build plan (4 engineers)
- **Roles:** A = schema, visibility, SSE, Valio client. B = monitors, webhooks, fallback, discovery. C = agents, risk engine, procurement. D = graph and screens.
- **M1 Friday night:** schema and seed (Valio synthetic subset plus dummy companies); webhook receiver on public URL; one monitor fires into `change_event`; SSE line on a bare page. Gate: end-to-end ping works.
- **M2 Saturday:** discovery writes `inferred` edges from a real page; risk engine v1; graph with trust styles; role switch; Valio catalogue and availability client.
- **M3 Saturday night:** monitoring agent to alert feed; procurement, approval and Valio order; confirm and audit flows; audit log.
- **M4 Sunday morning:** freeze about 09:00; polish; rehearse three times; record backup video. No features after Saturday midnight.
- Side items: CRACI GitHub Action with SBOM (under an hour); Codex only if actually used, and logged.

## 9. Judging-criteria mapping
- **Valio (30%):** proposal → approval → mock order; substitution on partial stock; approval gate, idempotency, audit log; price and lead-time alternatives; JSON Schema events.
- **Context.dev:** monitors and webhooks in the core flow; on-screen latency; source URLs on every alert.
- **Trust and privacy:** visibility in the query layer, shown by the role switch.
- **Bounties:** Gemini, Aiven, CRACI. Cala not in the core: not claimed.

## 10. Risks and cuts
- **Monitor timing or webhooks unsupported (A1/A2):** 60 s scrape polling; replay button.
- **Webhook unreachable at venue:** fixed Aiven Runtime URL; test Saturday morning.
- **Valio mock quirks:** verify in hour 1.
- **Demo company page:** labelled DEMO, hosted by us; no real company imitated.
- **Cut order:** Cala; Exa; Oxylabs; Modal/Verda; ArcadeDB; graph animation.

## 11. Biggest weakness of this proposal
The live moment depends on a third-party monitor's timing and our webhook path working on stage; if either stalls, the story becomes a replay. Postgres instead of ArcadeDB also shows less native graph depth, and real-web discovery covers only a few pages.

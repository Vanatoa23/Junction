# Entrant 04: Postgres Spine (lens: Postgres-only pragmatist)

## 0. Bold bet
One managed Aiven Postgres holds the graph, trust levels, risk signals, approvals, audit log and vectors, with recursive CTEs for every traversal and pgvector for alternatives. A second graph engine buys nothing at demo scale (a few thousand nodes) and adds a second failure mode on a 48-hour clock, while the Aiven bounty comes for free.

## 1. Summary and name
Name: **Tessera** (each company is a tile; edges show how tiles fit). Companies declare buyers and suppliers, unregistered counterparties are auto-added and invited, trust rises as parties confirm, and agents keep the map current. The hotel persona sees its own map, a live-discovered and monitored risk on an upstream dairy producer, opted-in alternatives with published price ranges, and a procurement proposal that a manager approves before Valio's mock order API is called.

## 2. Architecture and DB choice
**Choice: Postgres only (Aiven managed, pgvector enabled). ArcadeDB rejected.**
- Scale: Valio's 700 suppliers, 20k customers (aggregated, not stored as nodes), plus seeded and scraped companies is roughly 2k nodes and 10k edges. A depth-4 recursive CTE over that returns in milliseconds.
- Operations: ArcadeDB needs Docker/Helm, a driver, backups and a query language the team does not know. None of that is scored by any judge. Our queries are 15-line SQL that we can show on screen.
- Privacy: Postgres row-level security enforces "a company's own map is private" in the database. ArcadeDB's multi-model permissions would push the same rule into app code.
- Hybrid rejected: two stores to keep consistent for no demo benefit.
- Concession: ArcadeDB's native traversal and its supply-chain demo code would be faster to showcase, and it would scale past our demo. We do not need either in 48 hours.

Components:
- API: FastAPI + psycopg (OpenAPI spec for open-standards points).
- Agents: Python workers in the same repo, triggered by a 5-minute tick, a "Scan now" button, and a Context.dev webhook endpoint.
- LLM: Gemini 2.5 Flash with JSON-schema output; Gemini embeddings (768-dim) into pgvector.
- Web data: Context.dev (company enrichment, news search, monitors with webhooks). Exa optional.
- Valio: mock catalogue, availability and order APIs.
- Frontend: React + Cytoscape.js. No Kafka: events are rows in `event`.
- Hosting: Aiven Runtime for the API if it works; fallback is a laptop with a tunnel. The demo DB is always on Aiven.

## 3. Data model and key queries
```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE company (id uuid PRIMARY KEY, domain text UNIQUE, name text, country char(2),
  industry text, status text CHECK (status IN ('registered','unregistered')),
  alt_opt_in boolean DEFAULT false, description text, embedding vector(768));
CREATE TABLE edge (id uuid PRIMARY KEY, buyer_id uuid REFERENCES company, seller_id uuid REFERENCES company,
  trust text CHECK (trust IN ('inferred','claimed','agreed','audited')), confidence real,
  sources jsonb,  -- [{url, title, quote, fetched_at}]
  buyer_confirmed boolean DEFAULT false, seller_confirmed boolean DEFAULT false, audited_by text,
  UNIQUE (buyer_id, seller_id));
CREATE TABLE risk_signal (id bigserial PRIMARY KEY, company_id uuid, type text, severity smallint,
  confidence real, summary text, source_url text, shown_to_buyers boolean, created_at timestamptz,
  UNIQUE (company_id, type, source_url));
CREATE TABLE price_point (company_id uuid, product_id text, unit_price numeric, currency char(3),
  published boolean, valid_from date, PRIMARY KEY (company_id, product_id, valid_from));
CREATE TABLE proposal (id uuid PRIMARY KEY, buyer_id uuid, from_supplier uuid, to_supplier uuid,
  product_id text, qty int, reason jsonb, status text, approved_by text, valio_order_id text);
CREATE TABLE event (id bigserial PRIMARY KEY, actor text, action text, payload jsonb,
  prev_hash bytea, hash bytea);  -- trigger blocks UPDATE/DELETE; hash = sha256(prev_hash || row)
```
Trust rules: `claimed` on one-sided declaration; a trigger sets `agreed` when both confirm flags are true; `audited` only via the simulated auditor stamp. `inferred` always displays confidence and sources.

Visibility: RLS on `edge` lets a session see only edges where it is an endpoint. The buyer's risk view is a `SECURITY DEFINER` function returning only `risk_signal` rows with `shown_to_buyers = true`, never the upstream edges.

Upstream traversal (depth ≤ 4, cycle-safe):
```sql
WITH RECURSIVE up AS (
  SELECT seller_id AS anc, seller_id AS direct_s, 1 AS depth, ARRAY[buyer_id, seller_id] AS path
  FROM edge WHERE buyer_id = $me AND trust <> 'inferred' OR confidence >= 0.6
  UNION ALL
  SELECT e.seller_id, up.direct_s, up.depth + 1, up.path || e.seller_id
  FROM up JOIN edge e ON e.buyer_id = up.anc
  WHERE up.depth < 4 AND NOT e.seller_id = ANY(up.path))
SELECT anc, count(DISTINCT direct_s) AS n_direct, min(depth) AS hops
FROM up WHERE anc NOT IN (SELECT seller_id FROM edge WHERE buyer_id = $me)
GROUP BY anc HAVING count(DISTINCT direct_s) >= 2;  -- hidden shared upstream
```
Blast radius: the same recursion walking `seller_id = X` downward to `buyer_id`, returning downstream buyer counts with k-anonymity (`HAVING count(*) >= 5`) for anyone but the owner.

Alternatives: `SELECT c.name, min(p.unit_price), max(p.unit_price) FROM company c JOIN price_point p ON p.company_id = c.id AND p.published WHERE c.alt_opt_in AND p.product_id = $prod ORDER BY c.embedding <=> $q LIMIT 5`.

Industry usage aggregate: `count(*) FILTER (WHERE buyer.industry = $ind)` with a k≥5 threshold.

## 4. Agents
**Discovery.** Input: a domain, a news query, or a tick. Tools: Context.dev enrichment and news search. Gemini returns `[{buyer, seller, relation, confidence, source_url, quote}]`. Validation: `source_url` must be one we actually fetched; `quote` must appear verbatim in the fetched text; both names must match; stored confidence = min(LLM score, 0.5 + 0.15 × distinct sources), capped at 0.9. Writes `inferred` edges and `unregistered` nodes with an invitation. No human gate, because inferred data is labelled as such.

**Monitoring.** Context.dev monitors on supplier domains and per-company news queries, delivered to `POST /hooks/ctx`, with a 5-minute poll fallback. Gemini classifies each change into a risk type, severity and confidence. Sanctions: a cached EU consolidated list (assumption: downloaded Friday), name match with `pg_trgm` similarity > 0.8. Dedup on `(company, type, source_url)`.

**Procurement.** Triggers on a severity ≥ 3 signal on a current supplier, or a published price premium > 15%. Calls Valio catalogue and availability, pulls candidates from pgvector and opted-in price points, and asks Gemini for a two-line rationale that cites only the rows it was given. It writes `proposal.status = pending_approval` and never orders. On manager approval, it POSTs the Valio order with `Idempotency-Key = proposal.id`. Partial availability (e.g. 40 of 60) produces a split or substitute proposal, not a silent change.

## 5. Risk engine
- Geopolitical: seeded country table (assumption, labelled) × Gemini news classifier.
- Regulatory: sanctions match; CSDDD/EUDR fields in Valio sustainability data; missing or expired certificate = severity 3.
- Concentration: the hidden-upstream query above. Single-source = one direct supplier for a product.
- Financial: Context.dev news and enrichment (layoffs, funding, insolvency terms), classified by Gemini.
- Live events: Context.dev news monitors (recall, strike, outage).
- Price premium: published price versus cheapest opted-in alternative.
- Score = severity (1–5) × confidence × 0.7^(hops − 1). Buyers see signals with score ≥ 2 as warnings. Upstream entities appear by name only when the source is public news; otherwise as "Tier-2 supplier #n".

## 7. Demo script (4 min)
- 0:00–0:30 Hotel login. Map: Valio central, six direct suppliers, trust styles. Say what stays private.
- 0:30–1:15 Live: "Scan now" pulls real pages through Context.dev; a new `inferred` edge appears with confidence and URLs.
- 1:15–1:50 Monitor webhook (real, pre-armed) raises a dairy-producer alert. Concentration card: three direct suppliers share one upstream co-op.
- 1:50–2:20 Supplier confirms in second browser: `claimed` → `agreed`, live. Auditor stamps `audited`.
- 2:20–2:50 Alternatives: three opted-in suppliers, one 4% cheaper with a published range and an EU certificate.
- 2:50–3:30 Proposal cites the risk and the price. Manager approves; Valio mock order placed; idempotency key shown. Partial availability branch proposes a substitute.
- 3:30–4:00 Audit log: actor, source, hash chain, "verify chain".

## 9. Judging-criteria mapping
- Valio (30%): full request → approval → order through mock API; idempotent order; partial-availability branch.
- Buyer need (20%): risk warnings, alternatives, price range in one flow.
- Controls (20%): approval gate, RLS, validation rules, append-only hash-chained log.
- Exceptions (15%): partial stock, unregistered suppliers, Context.dev fallback to cache.
- Open standards (15%): OpenAPI, SQL, pgvector, Aiven managed path.
- Context.dev (15%): live discovery, monitor webhooks, sourced quotes.
- Bounties: Aiven (store and hosting), Gemini (all LLM calls), Codex (seed/tests), CRACI (Actions CI with SBOM). Cala not entered.

## 10. Risks and cuts
- Cut order: Cala (not entered), Oxylabs, Exa, embeddings (fall back to category match), real sanctions list (use a seeded 20-entity list), Aiven Runtime (run locally), recursion depth 4 → 3.
- Risks: Context.dev latency (pre-cached scan labelled as cached); Gemini rate limits (cache responses); RLS leaking a map (write a test per role); live webhook not arriving (pre-armed replay).

## 11. Biggest weakness of this proposal
Postgres-only reads as "not graph-native" to judges who were pitched a graph database. Blast radius as recursive SQL is less visually impressive than a Cypher traversal, and recursive CTEs slow down past depth 6 at scale. We are claiming a network we do not demo at full size.

# Entrant 32: Agent Mesh over A2A (lens: Google ADK + Agent2Agent)

## 0. Bold bet
The buyer's procurement agent negotiates with Valio's seller agent over the open Agent2Agent (A2A) protocol, so the human approval gate is a protocol state (`input-required`) and every message is a standard, inspectable task artifact. Any supplier that publishes an A2A agent card can join the network, which turns "open standards and a credible path to production" into a working demo rather than a slide.

## 1. Summary and name
**Lattice Agents.** A Gemini-powered buyer agent (Google ADK) runs in a hotel's workspace. It discovers suppliers, monitors risk, and asks Valio's seller agent for prices, availability and orders over A2A. The supply map is a projection of agent findings and human confirmations stored in Postgres. Nothing is ordered without a manager's approval inside an A2A task.

## 2. Architecture and DB choice
- **Services (Python, one repo, four processes):**
  - `buyer-agent` (ADK root `LlmAgent` with sub-agents `discovery`, `monitor`, `procurement`). Exposed as an A2A server; the UI talks to it through the A2A client.
  - `valio-seller` (A2A server): thin adapter over Valio's mock catalogue, availability and order APIs. Assumption: Valio's mock exposes REST, not A2A, so we wrap it. If Valio ships an A2A endpoint, we point the client at it instead.
  - `supplier-agents` (A2A servers, two for the demo: the dairy producer and an alternative): answer price and certification queries from published data only.
  - `api` (FastAPI): graph and risk views from Postgres, SSE stream of A2A task events, webhook receiver for Context.dev monitors.
- **Discovery and monitoring tools:** Context.dev news search, company enrichment and monitors (assumed endpoints per brief), Exa as backup search.
- **LLM:** Gemini via ADK (model choice pinned at build time; assumption).
- **DB: Aiven Postgres as the only store**, including ADK session state. ArcadeDB is cut: it is not sponsor-hosted, adds Docker and a new query language, and recursive CTEs cover the four queries needed (upstream, concentration, blast radius, alternatives).
- **Trust and provenance on the wire:** every A2A artifact carries a `DataPart` with `{trust, confidence, source_urls[], visibility}`. The buyer agent refuses artifacts without sources when trust is `inferred`.

## 3. Data model and key queries
- **Tables:** `company(id, name, country, registered, opted_in)`, `edge(id, src, dst, trust, confidence, sources jsonb, owner, status)`, `price_publish(company, sku, min, max, currency)`, `risk_signal(company, type, severity, confidence, sources, ts)`, `task(id, agent, state, payload jsonb)`, `approval(task_id, approver, decision, ts)`, `order(id, valio_order_id, idem_key)`.
- **Trust rule:** rank only increases (`inferred` < `claimed` < `agreed` < `audited`). `agreed` requires confirmations from both `src` and `dst` agents or users. `audited` requires an auditor stub event. Regressions are rejected in one SQL `CHECK` in the write path.
- **Visibility rule:** the buyer agent's tools query only views: `v_my_map` (own edges), `v_risk` (risk plus propagation path), `v_peer_usage` (count by industry, minimum group 5), `v_alternatives` (where `opted_in`), and `price_publish`. Agent cards for non-opted-in suppliers are never served.
- **Upstream traversal (depth 3):**
```sql
WITH RECURSIVE up AS (
  SELECT src, dst, 1 AS d, ARRAY[dst] AS p FROM edge WHERE dst = $1
  UNION ALL
  SELECT e.src, e.dst, up.d+1, up.p||e.dst FROM edge e
  JOIN up ON e.dst = up.src
  WHERE up.d < 3 AND NOT e.dst = ANY(up.p))
SELECT * FROM up;
```
- **Hidden concentration:**
```sql
SELECT s2.src AS shared_upstream, array_agg(DISTINCT s1.src) AS via
FROM edge s1 JOIN edge s2 ON s2.dst = s1.src
WHERE s1.dst = $1 GROUP BY s2.src HAVING count(DISTINCT s1.src) >= 2;
```
- **Blast radius:** the same recursion walking `src -> dst` from the failed node.
- **Alternatives:** same category, `opted_in`, with a `price_publish` row, excluding current suppliers.

## 4. Agents (discovery, monitoring, procurement)
- **Discovery (ADK LlmAgent):** tools `context_news_search(query)`, `context_company_enrich(name)`, `exa_search(query)`. Output schema per candidate: `{company, relation, country, confidence, quote, url}`. Each candidate becomes an `inferred` edge if it has at least two URLs; otherwise it is dropped and logged. Runs on a 10-minute schedule and on a "Run discovery now" button.
- **Monitoring:** Context.dev monitors register per watched company or news query. Webhooks POST to `api`, which starts an ADK run that classifies the change into a risk type and severity (Gemini structured output) and writes `risk_signal`.
- **Procurement (ADK agent acting as A2A client):** on a risk score above threshold, it sends an A2A `message/send` to `valio-seller` asking for product, price and availability for the affected SKUs. Valio's answer is a task artifact. For partial availability, the agent asks `supplier-agents` for substitutes over A2A and proposes a split. The task then moves to `input-required` with a proposal artifact.
- **Human approval:** the manager's "Approve" sends a follow-up A2A message with `approval_id` and proposal hash. Only then does the procurement agent call `valio-seller` `place_order` with an idempotency key equal to the task id. Denied proposals end in `canceled`.
- **Validation:** every agent output is a Pydantic model; confidence in [0,1] and at least one source URL are required. Failures set the task to `failed` with the reason and appear in the timeline.

## 5. Risk engine
- **Score:** per signal `c = severity x confidence x 0.5^(age_days/14)`; company risk per type `= 1 - prod(1 - c)`.
- **Propagation:** buyer exposure `= max(own, 0.5 x upstream)` per hop, path stored.
- **Types and sources:**
  - Geopolitical: static country index (assumption) plus news keywords.
  - Regulatory: sanctions name match (fuzzy >0.9 on a public list, assumed format); certificate expiry from supplier JSON; CSDDD flag stub. EUDR not applied to dairy.
  - Concentration: shared-upstream query, severity = shared count / direct suppliers.
  - Financial: Gemini classification of enrichment and news for layoffs, funding, insolvency.
  - Live events: recall, strike and outage keywords on Context.dev news (the live beat).
  - Price premium: `(unit price - min opted-in alternative) / min`, only where prices are published.

## 6. Screens and graph view
1. **Login:** hotel persona.
2. **Supply map:** Cytoscape graph, upstream left. Trust styles: dashed amber `inferred` (confidence label), grey solid `claimed`, dark solid `agreed`, double gold `audited`. Risk border red/amber. Unregistered nodes grey with "invite".
3. **Agent trace (signature panel):** live list of A2A messages and task states (`submitted`, `working`, `input-required`, `completed`), each with the agent name, artifact and source URLs.
4. **Risk alert:** highlighted path to Valio and the hotel; sources; "Find alternatives".
5. **Alternatives:** opted-in suppliers, published price range, lead time, certificate badges.
6. **Proposal and approval:** lines, split lines, Approve/Reject.
7. **Supplier and auditor stubs:** confirm edge (`claimed` to `agreed`); stamp `audited`.

## 7. Demo script (about 4 min)
- 0:00 "Companies see one step. Our agents talk to each other over A2A."
- 0:20 Hotel logs in; supply map shows Valio centre, two `claimed` edges, one dashed `inferred` dairy producer with 0.78 confidence and two URLs. Agent card of Valio shown.
- 0:55 Supplier tab confirms the edge; `claimed` becomes `agreed` live.
- 1:20 **Live beat:** "Run discovery now". Context.dev news returns a fresh article; the discovery agent emits an edge or signal with its URL in about 15 s. Fallback: Friday-recorded A2A trace replayed.
- 1:50 Risk alert on the dairy producer propagates to Valio and the hotel.
- 2:20 Agent trace: procurement sends A2A query to Valio seller; artifact shows prices; alternatives shown with published ranges; concentration card "3 suppliers share upstream X".
- 2:50 Proposal goes `input-required`: two substitutes, one partial-availability split.
- 3:15 Manager approves; trace shows `place_order`; Valio order id returned.
- 3:35 Auditor stamps an edge `audited`. Privacy beat: the hotel sees Valio's peer-usage aggregate only; a non-opted-in supplier does not appear in alternatives.

## 9. Judging-criteria mapping
- **Valio (30%):** orders only after an A2A approval state; exceptions (partial, substitution) are artifacts; the trace is the audit log.
- **Feasibility (25%):** ADK and A2A are new to the team; mitigated by a plain-JSON fallback with the same message shapes.
- **Context.dev (15%):** monitors plus live news beat, URLs visible in trace.
- **Trust and privacy (10%):** trust and visibility enforced in SQL views and in agent-card publication.
- **Concreteness (10%):** schemas, SQL, task states above.
- **Side bounties (10%):** Gemini (ADK agents, classification), Aiven Postgres, CRACI in CI, Codex only if used in development and stated. Skip Cala, Modal, Oxylabs.

## 10. Risks and cuts
- **Cut order:** Exa, Oxylabs, Modal, Cala, ArcadeDB, price premium. Last resort: replace A2A transport with plain JSON-RPC using the same task states and message shapes.
- **Technical risks:** ADK and A2A SDK version churn (pin versions Friday); Gemini rate limits during demo (cache discovery outputs; fallback to pre-generated classification); webhook needs a public URL (tunnel or polling); Context.dev news empty on stage (pre-capture a real article).

## 11. Biggest weakness of this proposal
It stacks two young frameworks (ADK and A2A) on a 48-hour clock, and the wrapper we build around Valio's mock API is our own assumption, not theirs. If the SDKs fight us on Saturday, we lose the protocol story and fall back to plain JSON-RPC, which weakens the open-standards score. The trace panel also adds UI work that judges see only briefly.

# Entrant 07: Fleetline (lens: Monitor fleet engineering)

## 0. Bold bet
Every watch is a row in a reconciled fleet, generated from templates and diffed against live state, not clicked together by hand. The demo runs about 180 real Context.dev and Exa monitors and shows one live change with its source URL and a measured latency badge.

## 1. Summary and name
**Fleetline**: a client pastes its supplier list; Fleetline compiles a per-company monitor spec, reconciles it into Context.dev and Exa monitors, and turns raw change events into deduplicated, corroborated alerts. Each alert carries an incident footprint and an incident-disjoint alternative, with human approval before any order.

## 2. Architecture and DB
- Flow: client list → Context.dev enrichment → spec compiler → reconciler → monitors (Context.dev page and news monitors, Exa monitors) → webhook receiver or poll worker → normaliser → fingerprint dedupe → Gemini classifier → corroboration gate → incident and footprint → alternatives agent → approval.
- Stack: TypeScript API and worker on Aiven Runtime; Aiven Postgres (JSONB for configs, FTS for dedupe). Postgres-backed job queue (`SELECT ... FOR UPDATE SKIP LOCKED`), so no Valkey dependency. Public webhook URL via Runtime (A).
- Cala is seed-only, loaded once into `companies` and `edges`. No graph DB; the edge table is enough for one- and two-hop queries.
- Gemini for structured classification only (JSON schema output).

## 3. Data model and incident footprint
- `clients(id)`; every other table carries `client_id`. Queries are scoped by a mandatory tenant filter, so one client's supply map never joins another's.
- `companies(id, domain, name, country, geo jsonb, source)`: global public cache keyed by domain. Only public facts are shared across clients.
- `client_companies(client_id, company_id, tier, role)` and `edges(client_id, from_id, to_id, kind: supplies|parent|customer)`.
- `monitors(id, client_id, company_id, kind, provider, query_key, config jsonb, desired bool, external_id, next_due, cost_units, status)`, unique on `sha(company_id|kind|config)`.
- `raw_items(canonical_url, content_hash, published_at, fetched_at, provider)`; `events(fingerprint unique, company_id, risk_type, severity, sources[], first_seen)`.
- `incidents(id, client_id, event_id)`; `footprint(incident_id, dimension, value)` with dimensions: region, port, plant_geo, parent, sanction_program, carrier.
- `alerts(id, client_id, incident_id, status)`; `alternatives(incident_id, candidate_id, disjoint_check jsonb, approved_by, approved_at)`.

## 4. Onboarding and bootstrap
- Input: paste or CSV with name, country, tier, optional domain. Normalise names and dedupe against the global `companies` cache.
- Context.dev company enrichment in batch: domain, HQ, sites, newsroom and investor URLs. Output drives page monitors.
- Exa: Websets only to fill missing tier-2 names for the client's category (A). Cala: parent and owner lookup and seed edges (A on field names).
- Timing (assumed): 60-company demo list enriched in about 2 minutes; 200 companies in about 8 minutes, with batch limits as the constraint. Demo uses a pre-enriched client so the live part is about onboarding, not waiting.

## 5. Monitoring design
Spec compiler maps each company to monitors by tier:

| Tier | Context.dev page monitor | Context.dev news monitor | Exa monitor | Filings |
|---|---|---|---|---|
| 1 direct | newsroom, investors, operations or status page (found by one crawl, filtered on "plant, facility, notice, force majeure") | `{name} strike OR fire OR sanction OR recall OR insolvency` | daily news query with `{name}` plus site city terms | listed firms only, PDF parse (A) |
| 2 upstream | none | same query, weekly | weekly plant and port query per site | none |
| downstream (credit) | none | payment and delay query, weekly | none | off in demo |

- Risk templates: 8 types (strike, sanction, fire or shutdown, port closure, recall, insolvency, cyber, force majeure), each with region terms from enrichment.
- Reconciler: runs every 15 min, diffs desired monitors against provider state, creates or deletes by key. Idempotent, so reruns are safe.
- Cadence and quota: priority by tier and recent event count. Token bucket per provider, 429 backs off exponentially. Per-run cost ledger feeds a budget bar. Hard cap of 600 monitors per client.
- Webhooks: Context.dev monitor events hit `/hooks/ctx`, which only enqueues. Exa polled on schedule (A: no webhook assumed).
- Dedupe: raw by canonical URL plus boilerplate-stripped hash; events by fingerprint = `company|risk_type|normalised entities|72h window`. The same story from Exa and Context.dev merges into one event with multiple sources.
- Noise filter, in order: (1) deterministic: ignore changes under 3% or date and nav only; (2) Gemini classifier returns `is_supply_risk`, `risk_type`, `severity 1-5`, geo, and a verbatim evidence quote; (3) corroboration: severity 3 or above needs two distinct domains, or one primary source (company's own status page or government domain).
- Latency: stamp `published_at`, `received_at`, `alerted_at`. Target webhook-to-alert under 30 s excluding LLM, under 20 s with it. Dashboard shows p50 and p95.
- Accuracy: a labelled set of 25 items (synthetic, labelled as such) plus live items; report precision and recall on the dashboard.

## 6. Incident-disjoint alternatives agent
- Candidates: same category from Exa Websets and Cala, excluding the affected supplier and its parent.
- Check, per footprint dimension: region, port, plant_geo (distance threshold), parent, sanction_program (A: external list lookup), carrier. Candidate passes only if no dimension overlaps.
- Also reject any candidate with an open event matching the incident fingerprint in its own monitors.
- Explainable output: a per-dimension table ("shared: none") with the evidence URL for each value.
- Ranking: passes first, then lead time and tier. Gate: human approval. Ordering through Valio's mock API is a stacked stretch only.

## 7. Upstream and downstream
- Upstream: in as tier 2, weekly and cheap, because it reuses news and plant queries. Its value shows up in the footprint.
- Downstream: out of the core demo. One credit-signal monitor per customer is a labelled stretch.

## 8. Screens and demo script (timed)
- 0:00–0:30: problem. Client list pasted (60 companies).
- 0:30–1:10: enrichment progress, then fleet view: 180 monitors with IDs, tier mix, budget bar.
- 1:10–2:00: live change. A real newsroom or status page changes, or a pre-armed monitor fires (fallback: labelled synthetic source). Alert appears with source URL and latency badge.
- 2:00–2:40: incident. Strike event, corroboration gate passes, footprint lights up.
- 2:40–3:20: alternative card with disjoint table per dimension, then approve button.
- 3:20–3:50: fleet dashboard, p50 and p95 latency, precision on the labelled set.
- Covers all five criteria: impact (live supply exposure), creative web use (templated monitors), completeness (close loop to approval), latency and accuracy (dashboard numbers), real-timeness (live change).

## 9. Build plan, risks, cuts
- Hours 0–8: schema, Context.dev enrichment, one page monitor end to end through the webhook.
- Hours 8–20: reconciler, news and Exa monitors, dedupe, classifier, corroboration.
- Hours 20–30: incidents, footprint, alternatives table, approval UI.
- Hours 30–36: labelled eval set, latency dashboard, fallback source.
- Hours 36–40: freeze, backup video.
- Team: E1 onboarding and enrichment; E2 reconciler and webhooks; E3 event pipeline; E4 UI and alternatives.
- Risks: webhook reachability, provider rate limits on monitor creation, LLM latency, venue network. Mitigation: pre-created monitors, cached enrichment, recorded backup.
- Cut order: downstream, Valio mock order, Websets, filings, Cala beyond seeds, Exa monitors (fall back to Context.dev news only).

## 10. Biggest weakness (honest)
The fleet is the product, but judges see only a few alerts in three minutes, so the plumbing can look invisible. Real change events are rare, so the live moment relies on a controlled source. Quotas for 180 monitors are unknown (A), and the cost story is a model until we measure it.

# Entrant 01: Quaysight, the Context.dev-native supply watch (lens: Context.dev maximalist)

## 0. Bold bet (2 sentences)
Every supply fact in Quaysight comes from a live web page, news item or PDF that Context.dev fetched, structured and watched, and the source URL is shown next to it. Context.dev monitors and webhooks drive the whole incident loop, so the demo shows a real change on a real page reaching an alternative-supplier offer in under a minute.

## 1. Summary and name
- **Quaysight**: client uploads a supplier list (CSV, or a PDF of a supplier list), and we watch every company on it.
- Context.dev capability in the core flow, and the criterion each one earns:
  - **Company enrichment** (batch): domain to legal name, HQ, parent and subsidiary links. Earns real-world impact (dedupes entities) and accuracy.
  - **Crawl + structured JSON extraction**: crawl each supplier's ops, news and investor pages, then extract plants, ports, regions, certifications and notices into a fixed schema. Earns creative live use and accuracy.
  - **Monitors + webhooks**: page, news and PDF monitors per company. Earns real-timeness and latency.
  - **News search**: per-company queries (strike, fire, sanction, shutdown, recall) with publish dates and URLs. Earns demo completeness.
  - **PDF parsing**: force-majeure notices and certificates linked from supplier pages. Earns creative use.
  - **People enrichment**: named operations and procurement contacts for the alert card (A: useful to the client, not scored heavily).
  - **Batch**: onboarding enrichment for all companies, and a nightly full re-extraction to correct drift.
- Gemini is the LLM for classifying changes and extracting footprint tags. It never validates an alternative alone.

## 2. Architecture and DB
- **Aiven Postgres** is the system of record. **Aiven Valkey** holds webhook dedupe keys and the job queue (A). **Aiven Runtime** hosts the web app and worker (A).
- Stack: TypeScript, one API service, one worker, one Next.js UI. Context.dev JS SDK and MCP for the agent (A).
- Flow: upload, then Exa and Cala bootstrap, then Context.dev batch enrichment, crawl and extraction, then monitor creation. A webhook hits the API, then a change diff, then Gemini classification, then an incident, then footprint match, then the alternatives agent, then a human approves.
- Postgres row-level security keys every tenant-owned table on `tenant_id`.

## 3. Data model and incident footprint
- Shared (public web facts): `companies` (domain, legal name, HQ, parent), `monitors` (company, kind page|news|pdf, Context.dev monitor id), `observations` (monitor, source_url, extracted jsonb, content_hash, observed_at), `incidents`, `incident_sources`.
- Tenant-private: `supplier_edges` (tenant, buyer, supplier, tier), `alerts`, `alternatives`, `approvals`.
- Privacy rule: a monitor watches public content only, so it may be shared across tenants. Which companies a tenant watches, and any alert, is visible only through a tenant-scoped join. Alerts are generated only from that tenant's edges.
- **Footprint** of an incident: a set of tags over five dimensions: region ID, plant ID, port (UN/LOCODE), sanction-list ID, upstream company ID. A company's footprint is its extracted attributes plus the closure of its upstream companies.

## 4. Onboarding and bootstrap (about 8 minutes for 200 suppliers, A)
1. **0 to 2 min:** upload. Exa Websets or search resolves names to domains and finds same-category candidates. Cala gives funding and investor context on each company (data source only).
2. **2 to 4 min:** Context.dev batch company enrichment on all domains. Merges duplicates and adds parent links.
3. **4 to 8 min:** crawl depth 2 per domain for news, ops and investor pages. Structured extraction into the footprint schema.
4. **8 min:** create monitors per company, and register webhook endpoint.
- Demo: a seeded 40-supplier list. Anything not fetched live is labelled **SEEDED**. Real companies are fetched live.

## 5. Monitoring design
- **Page monitors** on ops and status pages, extracting `{status, closures, notices}`. Webhook on change.
- **News monitors**: `"<company>" strike OR fire OR sanction OR shutdown`, 24-hour window, deduped by URL.
- **PDF monitors**: force-majeure and recall PDFs linked from the company's notices page, parsed on discovery.
- **Noise filter**: diff on extracted fields, not raw HTML. Gemini labels each change incident-relevant with a confidence score. An incident opens only with two independent sources (for example page and news, or two URLs on different domains).
- **Latency**: `alert_visible_at minus source_published_at` (from Last-Modified or the news date), with p50 and p95 shown on the dashboard. **Accuracy**: a labelled set of 20 seeded changes, precision and recall shown on the same panel.

## 6. Incident-disjoint alternatives agent
- For incident I with footprint F, candidate C passes only if F and footprint(C) are disjoint on all five dimensions, including C's upstream closure.
- Each dimension is printed as a row: `region: disjoint, evidence <URL>`. If C's footprint is unknown on any dimension, the default is **deny**, not pass.
- Extra gates: C is not a parent or subsidiary of the affected supplier (from enrichment), and C is not on the sanction list the incident cites.
- **Candidate pool**: Cala graph companies in the same category, Exa Websets results, and the tenant's own approved suppliers.
- **Ranking**: capacity match from extracted fields, then footprint distance, then price band from client input (A).
- **Human approval**: the alert card shows the candidate, the check table and the source URLs. Approve triggers the Valio mock order (secondary, stacked only after approval).

## 7. Upstream and downstream
- **Upstream: IN**, two levels, reusing page and news monitors. It is the input to the footprint closure check, so it is core, not optional.
- **Downstream: OUT of the core demo.** One stretch screen: news and enrichment signals on the client's customers as a credit-risk flag (A). Cut first if time runs short.

## 8. Screens and demo script (timed, 3:30)
- **Screens**: Onboard (batch progress), Graph (tiers), Supplier card (extracted fields with source URLs, monitors), Live feed (webhooks with latency), Incident (footprint and sources), Alternatives (check table), Approval.
- **0:00 to 0:30**: the pivot. "The web is your real-time database."
- **0:30 to 1:00**: upload 40 suppliers. Batch enrichment ticks up. Each row shows the source domain.
- **1:00 to 1:30**: open a supplier card. Plant and port fields, each with its source URL.
- **1:30 to 2:30**: the live change. We edit a status page on a staging domain we control (labelled test), and a real news query also runs. The webhook arrives, the feed shows the diff and latency, Gemini classifies it, and an incident opens.
- **2:30 to 3:15**: alternatives. Show the disjoint table with evidence for each dimension. Approve. Valio mock order confirms.
- **3:15 to 3:30**: p95 latency, precision and recall, and the five criteria recap.

- **Hours 0 to 4**: Aiven Postgres and Valkey, Context.dev SDK, first monitor on one domain.
- **Hours 4 to 12**: onboarding, batch enrichment, extraction schemas.
- **Hours 12 to 22**: monitor and webhook pipeline, Gemini classifier, incident model.
- **Hours 22 to 30**: footprint check, alternatives agent, UI screens.
- **Hours 30 to 34**: feature freeze. Approval, Valio stack, staging page for the live change.
- **Hours 34 to 40**: rehearse twice, record backup video, fix only blockers.
- **Risks**: webhook reachability from the demo laptop (deploy to Runtime by hour 6); extraction accuracy on messy pages; Context.dev rate limits (A); Exa and Cala access (A).
- **Cut order**: downstream stretch, then PDF monitors, then Valio, then Cala, then Exa Websets (fall back to Exa search).

## 10. Biggest weakness (honest)
Breadth is the risk: seven Context.dev capabilities in one flow means each is thin, and four engineers can polish only part of it. Extraction accuracy on arbitrary supplier pages is unproven, and the footprint depends on tags pulled from unstructured pages, so a missed plant can fool the disjoint check. The mitigation is default-deny on unknown footprint, but that makes the alternatives list sparse, which a judge may see as a weak result.
